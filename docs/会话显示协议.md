# 会话显示协议 v1

App 和 `kite` HTTP 客户端只接收 Kite 显示语义；`sdk`、`harness` 和原生 journal 事件不出现在 HTTP SSE 中。原生存储保留模型恢复所需的完整内容，显示协议不反过来承担模型恢复。

## 历史与连接

先通过 `GET /machine` 取得工作机身份。以下所有请求与 SSE 都必须带 `X-Kite-Machine: <id>`。App 保存该身份，地址对应机器发生变化时请求返回 409；重新连接由用户在连接面板发起。

`GET /threads/:id/history` 返回：

```typescript
{
  version: 1,
  threadId: string,
  cursor: string,
  records: DisplayRecord[],
  pending: PendingInput[],
  state: DisplayState
}
```

`threadId` 表示线程身份；工作区管理使用 `/workspaces/:id`。类型定义在 [显示协议](../kited/src/transcript/protocol.ts)。记录有稳定的 `id`、毫秒时间 `at`、可选的子调用 `parent` 和一个 `block`。块包含 human、kite、text、thinking、tool_use、tool_result、interrupted、error、compacted；人消息 id 和工具调用 id 独立保留，工具结果用 `call` 关联调用。错误、停止和等待继续如实显示，不补造成功结果。

`compacted` 块表示一次上下文压缩：`{id, text, from?, through?, automatic?, reverted?}`。`text` 是摘要正文，`from`、`through` 是被压缩范围首尾记录的 id，客户端把这段记录收在摘要下面，原文可展开查看；`reverted` 为 true 表示已撤销，范围按原样显示。压缩记录追加在发生时的位置，不改写范围内的记录。

`tool_use.batch` 是可选的调用批次标识。同一次模型回复发起的调用共享标识，下一次回复使用另一标识；历史与实时事件保持一致。它表示模型回复的边界，不表示工具必定并发执行。客户端没有批次信息时不按工具名、完成顺序或相邻位置猜测分组。

## 事件归属与订阅

| 请求 | 首帧 | 后续范围 |
| --- | --- | --- |
| `GET /events` | `catalog.snapshot`：`workspaces` 为完整工作区聚合列表 | `checkout.changed`、`workspace.changed`、`thread.changed`，提示重新读取目录；`context-templates.changed`、`roles.changed` 分别提示重新读取模板与角色列表 |
| `GET /events?workspace=:id` | `workspace.model`：`workspaceId` 和 `model` 工作区聚合 | 该工作区的管理事件和所属 `thread.changed`，不含对话正文 |
| `GET /events?thread=:id` | `thread.history`：上述历史快照 | 该线程的显示事件和 `thread.changed` |

所有首帧包含 `version: 1`、`cursor`、`at`，线程历史还带 `threadId`。空 ID、同时选两种范围、重复或未知参数返回 400；不存在的工作区或线程返回 404。客户端从连接时的快照开始接收后续变化，不需要提前打开其他范围的流。

业务事件由 `kited/src/events.ts` 定义，按实际归属携带标识：

| 事件 | 归属及内容 |
| --- | --- |
| `checkout.changed` | `projectId`、`checkoutId`，检出已登记 |
| `workspace.changed` | `workspaceId`、`status`，工作区创建、状态或文件恢复发生变化 |
| `thread.changed` | `workspaceId`、`threadId`、`status`，线程创建或归档 |
| `workspace.setup` | `workspaceId`、`exit`、`log`，初始化结果 |
| `workspace.snapshot` | `workspaceId`、`commit`、`label`、`changedFiles`，新快照，包括回退和归档前保存 |
| `workspace.adopt` | `workspaceId`、`result`，一次采纳只发一次 |
| `workspace.error` | `workspaceId`、`message`，工作区准备或自动采纳失败 |

工作区操作可带 `originThreadId` 标明触发线程，但事件仍属于工作区。没有线程的工作区照常通知初始化和快照。工作区变更不会让已归档线程重新可用。

线程显示事件由 [显示协议](../kited/src/transcript/protocol.ts) 定义，均带 `threadId`：

| 事件 | 客户端操作 |
| --- | --- |
| `thread.record` | 按 `record.id` 替换原记录；首次出现才追加，开始、阶段变化和定稿均使用此事件 |
| `thread.record.delta` | 按 `delta.id` 将内容追加或校正到已有记录的字段 |
| `thread.pending` | 替换全部待处理输入 |
| `thread.state` | 替换运行阶段、忙闲、结果、上下文测量、有效状态及能力声明 |
| `thread.check`、`thread.idle`、`thread.error` | 显示检查结果、回合结束或线程错误 |

`state.status` 是线程的有效状态：线程归档时为 `archived`，否则采用工作区状态。工作区生命周期变化通过 `thread.state` 通知线程订阅者；初始化、采纳、快照等操作只通过工作区订阅提供。

实时事件也带 `at` 和 `cursor`，SSE `id` 与 cursor 相同。首帧与后续事件连续覆盖连接建立期间的变化，不能在快照与订阅之间丢失事件。目录订阅不传递线程正文、原生运行事件或工作区操作日志。

cursor 由服务实例 UUID 和事件序号组成，用于识别显示版本，不是原生记录序号或分页位置。当前不提供事件日志重放或分页；无论客户端带哪个 Last-Event-ID，每次连接都用对应范围的完整快照替换本地副本。服务重启后仍按这个规则恢复。工作区首帧只含领域聚合；快照清单从 `/workspaces/:id/snapshots` 读取，客户端可在工作区订阅建立后读取并在快照事件到来时刷新。

### 工作区列表版本

`GET /workspaces` 响应体为聚合数组，`X-Kite-Cursor` 响应头标识这份列表的版本。客户端可忽略同一服务实例中不晚于已读取版本的目录通知，不能让旧响应覆盖新列表。

重连或切换工作机后，以新连接的完整快照建立基线，丢弃旧连接的迟到结果；不同服务实例的序号不可比较。带 `?project=` 的列表游标仅覆盖该查询范围。

### 生成与执行的流式更新

记录带可选 `generation: streaming | complete | interrupted`；不带该字段的历史内容为完整记录。记录 ID 作为不透明标识使用，生成中与完成后保持身份不变。

`thread.record.delta` 携带 `{id, field, text, part?, replace?, limit?, input?}`。field 为 `text`、`arguments` 或 `output`。text 字段用于正文和思考，part 默认为 0，多分段以两个换行拼接，replace=true 只校正该分段。arguments 为工具参数原文，可追加或完整校正；可选 input 是供概要使用的草稿字段，缺省时客户端保留上一版，不自行解析参数，不用于工具执行。output 为工具执行器输出，按 limit 个 Unicode 码点保留尾部，发生裁剪时 outputTruncated=true。

工具概要只反映确实收到的参数字段；缺字段时不补默认值，不能用于执行。最终完整参数校正概要，原始 arguments 保留供查看。参数完整且通过执行校验后才能启动工具。

正文/思考块在生成期间保存 parts；完整条目定稿以 text 校正。tool_use 额外携带 arguments、stage、output、outputLimit、outputTruncated、startedAt、finishedAt。阶段为 generating（参数生成）、queued（等待执行）、running（执行中）、finished（执行器已经给出结果）、not_executed（生成阶段停止）、unfinished（历史恢复时没有结果）。最终成功/失败/未执行/未知仍来自关联的 tool_result.status，不从生成状态或会话 busy 推测。

增量对应的记录必须先出现；客户端收到没有对应记录的 delta 时重新同步。请求中断时仍未定稿的正文/思考记为 interrupted，生成中的工具记为 not_executed；已启动的工具等待执行器返回结果。模型条目完成不代表整个请求或回合完成。

服务仍在运行时的重连快照包括生成草稿、工具阶段和已累计的受限输出。daemon 重启只恢复已经落盘的完整条目；未完成草稿可能消失，没有结果的工具为 unfinished，仍由 recovery 核查残留进程。客户端每次连接以历史快照替换副本，旧连接的更新不覆盖新快照。

内容完整性与生成、执行的区分见 [流式展示](会话流式展示.md)。

## 输入与控制

`POST /threads/:id/messages` 的 `{id, text}` 使用客户端生成的稳定 id。harness 可靠保存输入后再确认 HTTP；同 id、同内容重试不会执行两次，同 id 不同内容会报错。

输入落盘后进入 pending，真正纳入模型请求才产生 human/kite 记录并移出 pending。客户端按同一输入 ID 合并待处理与历史状态，不能重复呈现。`midTurn` 表示是否并入同一回合；它以服务纳入请求的时刻为准。

`POST /threads/:id/messages/:message/cancel` 只撤回尚未纳入请求的输入。停止的参数、退回结果、跨端草稿与重试语义统一见 [会话状态机](会话状态机.md#手动停止与消息交接)。`POST /threads/:id/compactions` 的 `{id, from, through}` 以两条输入的 id 指定范围，`DELETE /threads/:id/compactions/:compaction` 撤销，范围与生效规则见 [上下文压缩](harness-主循环.md#上下文压缩)。`resume` 表示显式继续，`recover` 表示恢复确认；App 按 `state.capabilities` 开关操作，不按模型供应商判断。

## 当前边界

历史读取不启动模型、工具或自动恢复。服务端发现未收尾回合时返回恢复阻塞，不能把 `busy=false` 当作旧进程已经停止。损坏记录应明确报错，不伪造完整历史。

Claude 提供文字、思考、工具调用与结果，并保留稳定输入身份、原始正文和队列状态；宿主附加上下文不重复显示为用户消息。重开后，命令输出和耗时以原生记录中的最终结果为准；缺失时间不冒充近期消息。原生子 agent 完整历史、插话附件和图片尚未接入。

当前控制支持发送、排队撤回、停止、继续、恢复、切换后端与上下文压缩。后端切换的条件及错误语义见 [会话后端](kited.md#会话后端与宿主边界)。对话回退、分叉和附件尚未提供，客户端只开放后端声明支持的操作。设备连接与验收边界见 [远程连接](kited.md#远程连接)。

`state` 包含执行阶段、上一回合结果、等待继续、恢复阻塞和是否正在压缩（`compacting`），语义统一见 [会话状态机](会话状态机.md#状态的归属)。

`state.context` 可选，结构为 `{requestId, inputTokens, windowTokens?, measuredAt}`；`measuredAt` 是请求完成时的毫秒时间戳。`windowTokens` 是对应请求实际采用的运行窗口，与自动压缩共用来源：harness 使用请求配置快照；Claude 使用回合结束时查询并保存的 CLI 窗口。查询完成后会推送更新，重连与服务重启后仍可恢复。窗口未知时省略，客户端只显示已用 token，不能拿[共享模型目录](../shared/agent-models.json)中的最大能力替代。新请求进行中保留上一次完成请求的测量，新完成请求缺少有效用量、压缩或撤销压缩时清除；历史和实时使用相同语义。客户端不得把上次测量当作当前请求的实时值。

## 文件与差异引用

`tool_result` 可选携带 `diff: {id, paths}`，仅反映实际完成并保存了历史内容的修改。部分写入失败仍可携带已完成文件的引用；unknown 与 not_executed 不得投影为成功。普通读取内容和上游错误文本不能被当成差异元数据。

App 据此生成 `path:diffId` 引用，前后全文由获准的 `files.diff` 按需读取；不从模型输入补丁或助手文字推断已完成修改。历史和实时遵守相同规则，格式、归属与定位见 [资源引用](资源引用.md)。
