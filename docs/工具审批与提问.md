# 工具审批与提问

本文适用于 kited、harness、Claude 线程与 App，规定回合中途停下等人回应的三种情形：工具调用越出事先授权时的审批，代理用提问工具向用户提问，以及代理向用户要密钥。沙箱与执行授权见 [实例操作](实例操作.md#实例执行授权) 与 [Agent 与插件契约](Agent与插件契约.md#71-插件与-harness-共用操作系统沙箱)，会话状态见 [会话状态机](会话状态机.md)，Line 的收件箱与代处理见 [Line 与工作区流转](Line与工作区流转.md#line-的收件箱代处理与托管)。

**状态：方向已确认，部分实现。** 第一版做「仅白名单」「越界询问」「全放行」三种审批模式、「必问」标记与提问工具；auto 模式由 Line 托管承担，见下文。已实现：提问工具、等你回应的状态与回应接口，Line 的停止、归档、创建、流转这几项必问动作的执行前审批，审批模式与 `approval-mode` 接口，命令连接网络许可之外主机时的询问与「允许并记住」，申请在沙箱外运行命令，代处理与托管，[密钥请求](#密钥请求)，App 的回应界面（线程里回应卡片摆在输入区上方，提问的「其他」就写在输入框里，不回应直接发消息即跳过；收件箱里同一个对象也能回应）。尚未实现：参数越界（例如 patch 写到工作区外）的执行前拦截、命令读写工作区外文件的越界记录与扩权重跑。

## 等你回应

审批、提问与密钥请求是同一类状态：回合仍在执行，卡在一个工具调用上，等人回应后，回应作为这次调用的结果交回模型，回合接着往下走，不开新回合。

会话状态带上 `waiting?: {id, kind: "approval" | "question" | "secret", ..., since}`，执行阶段仍为 `running`。等待的对象只有一份，原线程窗口与 Line 的收件箱展示的是同一个对象，在哪里回应都写回它。

等你回应不占工作区：同一工作区的其他线程照常运行，见 [工作区并行](工作区并行.md)。

## 审批

执行边界分两半：

- **沙箱与静态授权**划定不用问就能做的范围：项目、角色、实例三层合成的工具、协作授权与执行授权（工作区读写、额外路径、网络许可、沙箱外命令），见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。
- **审批层**处理越出这个范围的请求：放行、拒绝，或停下来问人。项目禁止的不进入审批，直接拒绝。

这与 Claude Code、Codex 的权限确认是同一种做法。命令默认在沙箱里运行；出沙箱只有两条路：命令整条匹配生效的沙箱外命令，或者代理申请、经审批放行。沙箱不可用时照旧拒绝执行，不会因此回退到无沙箱。Claude 线程继续以 `bypassPermissions` 运行，只拿到 Kite 提供的工具，审批全部在 Kite 这一层。

请求按「工具 + 它要碰的目标」对照授权判断，不只看工具名：

| 情形 | 拦截时机 |
|---|---|
| 参数里就能看出越界，例如 patch 写到工作区外 | 执行前 |
| 标了「必问」的动作，例如 Line 停止、归档、创建或流转其他工作区 | 执行前，与模式无关 |
| 命令连接白名单外的域名 | 执行中：沙箱的网络代理挂住这次连接来问，命令仍在运行 |
| 代理申请在沙箱外运行一条命令（shell 的 `outside_sandbox`） | 执行前：卡片给出命令原文与代理写的用途，并提示命令会执行工作区里代理能改的脚本 |
| 命令读写工作区外的文件 | 事后：操作系统沙箱只能拒绝不能暂停，工具结果带上越界记录；模型以「扩权重跑」重新发起，走执行前那条路 |

宿主的认证、数据库、会话记录与 Git 元数据保护不进入审批，任何模式下都不能放开。回环、未指定、链路本地与本机自己的地址同样不进入审批：本机控制接口尚未鉴权，任何模式下都拒绝连接。

| 决定 | 结果 |
|---|---|
| 这次允许 | 只放行这一次调用或连接 |
| 允许并记住 | 放行，并把对应许可写进这个实例的执行授权，之后同类请求不再问 |
| 拒绝 | 不执行，工具结果为「被拒绝」交回模型，回合继续 |

「允许并记住」是「运行中不能改执行授权」的例外：只追加许可，在后续调用生效，不重放已失败的命令；授权变化照常生成通知，见 [线程通知投递](线程通知投递.md)。申请出沙箱的命令记住时原样记下整条命令，之后一字不差的同一条不再问；要放宽成 `docker compose *` 这样的模式，在执行授权里改。

| 审批模式 | 越界请求 |
|---|---|
| 仅白名单 | 直接拒绝 |
| 越界询问 | 问人 |
| 全放行 | 自动允许，包括申请出沙箱 |

模式按实例设置，可由角色给默认值，实际按项目给的上限收紧，默认越界询问，接口取值依次为 `allowlist`、`ask`、`allow_all`；「必问」的动作在任何模式下都问人，也不能「允许并记住」。命令连接网络许可之外的主机时，同一条命令里同一主机只问一次，几台主机依次问，决定对这条命令后续的连接都有效；等人回应的时间不计入命令的超时，命令结束时还没回应的询问作废。是否问人看问的那一刻的模式，运行中改模式对正在跑的命令也生效。由辅助判断代批的 auto 模式不单独做，由 Line 的托管承担：Line 带着用户的记忆替用户决定，拿不准的留给用户。

## 提问

代理需要用户回答或拍板时调用 `question` 工具。参数沿用 Claude Code 提问工具的结构，harness 与 Claude 共用这一个 Kite 工具：

- 一次 1 到 4 个问题，每个问题有问题正文、2 到 4 个选项（标签与说明），分单选与多选。
- 每个问题都自动带「其他」，用户可以写自己的回答。
- 结果是每个问题选中的选项标签，或用户写的「其他」原文。

提问是可选的交互方式：代理也可以把问题写在回复里结束回合，回合结束本来就是轮到用户。

## 密钥请求

代理需要一个密钥时，用 `credentials` 工具的请求动作当场向用户要，用户在卡片里填好就保存，不用自己去设置里找。真正的密钥值只有用户知道，这也是它唯一的来源。

- 两种目标：一条独立的密钥，存好后代理在 shell 的 `secrets` 里按引用使用；或者设了路径的环境变量文件里的一项，例如 `.env` 的 `STRIPE_KEY`，存好后宿主把整个文件重写进项目的所有工作区。项目还没有这个文件的密钥时一并新建。
- 代理没给值时等同提问，只能由用户填写。代理给了值时（例如 `PORT=3001`，或它生成的随机串），卡片预先填好这个值，用户确认或修改后保存；审批模式为全放行时直接保存，不问人。
- 默认存为项目专用，用户回应时可以改成账号共享；文件里的一项只能是项目专用。同名的已经存在时是替换，卡片上写明。
- 用户填写后宿主存进凭据，工具结果只说明存到了哪里（引用，或文件与变量名），不带用户填的值；用户拒绝时，结果是拒绝和可选的理由。用户填的值只进凭据，不进会话记录、收件箱或通知。

写进工作区的环境变量文件，代理不能直接改（见 [凭据](kited.md#凭据)），要改其中一项也用这个请求。这样文件只有凭据这一个来源，各工作区里的副本随时整体重写也不会丢改动。

## 谁来回应

回应由用户做出，账号下任一设备都可以，原线程窗口和 Line 的收件箱都能回应。用户可以把某一项交给 Line 代处理，或开启 Line 的托管，这时 Line 替用户批准、拒绝或回答，记录上写明由 Line 代为处理及理由：提问的结果交回模型时写明，审批的处理记录留在 Line 的收件箱；Line 不能处理它自己发起的请求，拿不准的留给用户。密钥请求只能由用户填写，不能交给 Line，托管也不覆盖它。等待没有时限，不自动拒绝。

## 停止、跳过与重启

- 等待时停止会话：视为拒绝或未回答，再按常规停止。
- 等待时不回应、直接发一条新消息：新消息先排进输入，再把这一项按跳过交回（提问记为未回答、跳过，审批记为拒绝，密钥请求记为未提供），回合接着走，模型在下一次请求里看到这个结果和新消息。
- 等待时服务重启：与普通工具调用中途断开相同，沿用 [恢复约定](harness-主循环.md#恢复约定)：调用已开始而没有结果，标记 unknown，线程进入恢复阻塞；等待的对象作废，之后的回应被拒绝。执行中挂住的网络连接随命令一起结束。

两个后端行为一致：harness 的工具执行等待回应；Claude 线程的 Kite 工具由 Kite 宿主执行，同样在宿主里等待。

## 接口草案

| 入口 | 约定 |
|---|---|
| 会话状态 | `thread.state` 增加 `waiting?: {id, kind, since, ...}`：审批带工具、目标与原因，提问带问题与选项，密钥请求带名称或文件与变量名、用途、类型、代理给的值与同名是否已存在 |
| `POST /threads/:id/waiting/:waiting` | 审批 `{decision: "once" \| "remember" \| "deny"}`；提问 `{answers: [{selected?: string[], other?: string}]}`；密钥请求 `{secret: {value, scope?}}` 或 `{decision: "deny", reason?}`，`scope` 为 `project`（默认）或 `account`；已回应或已作废返回 409 与当前状态 |
| `POST /threads/:id/messages` 带 `skipWaiting` | 值是线程在等的那一项的 ID，只用于用户在 App 里发送：消息排进输入后按跳过交回那一项；那一项已回应或已作废时只发消息 |
| `GET / PUT /instances/:id/approval-mode` | 读取或设置实例的审批模式 |
| 工具 `question` | `{questions: [{question, options: [{label, description}], multiSelect}]}` |
| 工具 `credentials` 的请求 | 见 [credentials](harness-主循环.md#credentials) |
