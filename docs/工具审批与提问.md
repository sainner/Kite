# 工具审批与提问

本文适用于 kited、harness、Claude 线程与 App，规定等人回应的三种情形：工具调用越出事先授权时的审批，代理用提问工具向用户提问，以及代理向用户要密钥。沙箱与执行授权见 [实例操作](实例操作.md#实例执行授权) 与 [Agent 与插件契约](Agent与插件契约.md#71-插件与-harness-共用操作系统沙箱)，会话状态见 [会话状态机](会话状态机.md)，Line 的收件箱与代处理见 [Line 与工作区流转](Line与工作区流转.md#line-的收件箱代处理与托管)。

**状态：方向已确认，部分实现。** 第一版做「仅白名单」「越界询问」「全放行」三种审批模式、「必问」标记与提问工具；auto 模式由 Line 托管承担，见下文。已实现：提问工具、等你回应的状态与回应接口（提问与密钥请求不阻塞回合），Line 的停止、归档、创建、流转这几项必问动作的执行前审批，审批模式与 `approval-mode` 接口，命令连接网络许可之外主机时的询问与「允许并记住」，申请在沙箱外运行命令，代处理与托管，[密钥请求](#密钥请求)，App 的回应界面（线程里回应卡片摆在输入区上方，连着的同类请求合成一张，提问的「其他」就写在输入框里；收件箱里同一个对象也能回应）。尚未实现：参数越界（例如 patch 写到工作区外）的执行前拦截、命令读写工作区外文件的越界记录与扩权重跑。

## 等你回应

等人回应分两种做法：

- **审批阻塞回合。** 被审批的调用本身停在那里：回合仍在执行，卡在这次工具调用上，决定作为调用的结果交回模型，回合接着往下走。会话状态带上 `waiting?: {id, kind: "approval", ..., since}`，执行阶段仍为 `running`。
- **提问与密钥请求不阻塞。** 工具发出请求后立即返回请求 ID，代理接着做不依赖答案的事，没有就结束回合。请求挂在线程上等用户回应，会话状态带上 `asks?: [{id, kind: "question" | "secret", ..., since}]`，按发出的先后排，可以同时有几项。用户回应后，宿主处理（存密钥），撤下请求，把结果作为一条输入交给代理：代理在跑就在下一次请求时纳入，已经停下就此开始新的回合。代理不再需要时（例如用户在对话里直接答了）可以收回自己的请求。

每一项只有一份，原线程窗口与 Line 的收件箱展示的是同一个对象，在哪里回应都写回它。界面上连着的几项同类请求合成一张卡片，回应时按项拆开提交。线程的状态摘要只在回合卡着审批、或线程空闲而有没回应的请求时显示在等。

等你回应不占工作区：同一工作区的其他线程照常运行，见 [工作区并行](工作区并行.md)。

## 审批

执行边界分两半：

- **沙箱与静态授权**划定不用问就能做的范围：项目、角色、实例三层合成的工具、协作授权与执行授权（工作区读写、额外路径、网络许可、沙箱外命令），见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。
- **审批层**处理越出这个范围的请求：放行、拒绝，或停下来问人。项目禁止的不进入审批，直接拒绝。

这与 Claude Code、Codex 的权限确认是同一种做法。命令默认在沙箱里运行；出沙箱只有两条路：命令整条匹配生效的沙箱外命令，或者代理申请、经审批放行。沙箱不可用时照旧拒绝执行，不会因此回退到无沙箱。Claude 线程继续以 `bypassPermissions` 运行，只拿到 Kite 提供的工具，审批全部在 Kite 这一层。

请求按「工具 + 它要碰的目标」对照授权判断，不只看工具名：

| 情形 | 拦截时机 |
|---|---|
| 参数里就能看出越界，例如 patch 写到工作区外 | 执行前 |
| 标了「必问」的动作，例如 Line 停止、归档、创建或流转其他工作区 | 执行前，与模式无关 |
| 命令连接白名单外的域名 | 执行中：沙箱的网络代理挂住这次连接来问，命令仍在运行 |
| 代理申请在沙箱外运行一条命令（shell 的 `outside_sandbox`） | 执行前：卡片给出代理写的用途与命令原文，带密钥时写明绑定了哪几个 |
| 命令读写工作区外的文件 | 事后：操作系统沙箱只能拒绝不能暂停，工具结果带上越界记录；模型以「扩权重跑」重新发起，走执行前那条路 |

宿主的认证、数据库、会话记录与 Git 元数据保护不进入审批，任何模式下都不能放开。回环、未指定、链路本地与本机自己的地址同样不进入审批：本机控制接口尚未鉴权，任何模式下都拒绝连接。

| 决定 | 结果 |
|---|---|
| 这次允许 | 只放行这一次调用或连接 |
| 允许并记住 | 放行，并把对应许可写进这个实例的执行授权，之后同类请求不再问 |
| 拒绝 | 不执行，工具结果为「被拒绝」交回模型，回合继续 |

「允许并记住」是「运行中不能改执行授权」的例外：只追加许可，在后续调用生效，不重放已失败的命令；授权变化照常生成通知，见 [线程通知投递](线程通知投递.md)。申请出沙箱的命令记住时原样记下整条命令，之后一字不差的同一条不再问；要放宽成 `docker compose *` 这样的模式，在执行授权里改。

| 审批模式 | 越界请求 |
|---|---|
| 仅白名单 | 直接拒绝 |
| 越界询问 | 问人 |
| 全放行 | 自动允许，包括申请出沙箱 |

模式按实例设置，可由角色给默认值，实际按项目给的上限收紧，默认越界询问，接口取值依次为 `allowlist`、`ask`、`allow_all`；「必问」的动作在任何模式下都问人，也不能「允许并记住」。命令连接网络许可之外的主机时，同一条命令里同一主机只问一次，几台主机依次问，决定对这条命令后续的连接都有效；等人回应的时间不计入命令的超时，命令结束时还没回应的询问作废。是否问人看问的那一刻的模式，运行中改模式对正在跑的命令也生效。由辅助判断代批的 auto 模式不单独做，由 Line 的托管承担：Line 带着用户的记忆替用户决定，拿不准的留给用户。

## 提问

代理需要用户回答或拍板时调用 `question` 工具。参数沿用 Claude Code 提问工具的结构，harness 与 Claude 共用这一个 Kite 工具：

- 一次 1 到 4 个问题，每个问题有问题正文、2 到 4 个选项（标签与说明），分单选与多选。
- 每个问题都自动带「其他」，用户可以写自己的回答；用户也可以不回答，关掉这个提问。
- 交给代理的结果是每个问题选中的选项标签，或用户写的「其他」原文；不回答时写明没有回答。
- 下一步取决于答案时，代理不按猜测往下做，只做不相干的事，没有就结束回合。

提问是可选的交互方式：代理也可以把问题写在回复里结束回合，回合结束本来就是轮到用户。

## 密钥请求

代理需要密钥时，用 `credentials` 工具的请求动作当场向用户要，用户在卡片里填好就保存，不用自己去设置里找。

- 一次请求可以要几项（最多 10 项），同时缺几个就一起要，用户在同一张卡片里逐项填写。用户填了几项就存几项，没填的算未提供；结果逐项写明哪些存好了、哪些没填。

- 两种目标：一条独立的密钥，存好后代理在 shell 的 `secrets` 里按引用使用；或者设了路径的环境变量文件里的一项，例如 `.env` 的 `STRIPE_KEY`，存好后宿主把整个文件重写进项目的所有工作区。项目还没有这个文件的密钥时一并新建。
- 代理没给值的项等同提问，只能由用户填写。代理已知的值自己给，不论是否私密，不知道的不编。代理给了值时：环境变量文件里还没有这一项，或这一项的值本来就是代理给的，直接保存，不问人；其余的（文件里值是用户给的项、独立的密钥）卡片预先填好这个值，用户确认或修改后保存。审批模式为全放行时，代理给了值的项都直接保存。一次请求里两种都有时，能直接存的先存好，其余的再问用户。
- 环境变量文件里每一项记着值是谁给的：直接保存的代理给的值算代理的；用户在卡片上填写或确认的、添加项目时导入的、在设置里替换内容后的，都算用户的。这样用户给的值不会被代理悄悄换掉。
- 默认存为项目专用，用户回应时可以改成账号共享，对这次请求里的独立密钥一起生效；文件里的项只能是项目专用。同名的已经存在时是替换，卡片上逐项写明。
- 用户填写后宿主存进凭据，交给代理的结果只说明每项存到了哪里（引用，或文件与变量名）或没有填，不带用户填的值；用户拒绝时，结果是拒绝和可选的理由，整次请求都不存。用户填的值只进凭据，不进会话记录、收件箱或通知。
- 用到这些密钥的步骤，代理先放着去做别的，用户什么时候填都行。

写进工作区的环境变量文件，代理不能直接改（见 [凭据](kited.md#凭据)），要改其中一项也用这个请求。这样文件只有凭据这一个来源，各工作区里的副本随时整体重写也不会丢改动。

## 谁来回应

回应由用户做出，账号下任一设备都可以，原线程窗口和 Line 的收件箱都能回应。用户可以把某一项交给 Line 代处理，或开启 Line 的托管，这时 Line 替用户批准、拒绝或回答，记录上写明由 Line 代为处理及理由：提问的结果交给代理时写明，审批的处理记录留在 Line 的收件箱；Line 不能处理它自己发起的请求，拿不准的留给用户。密钥请求只能由用户填写，不能交给 Line，托管也不覆盖它。等待没有时限，不自动拒绝。

## 停止、跳过与重启

- 审批等待时停止会话：视为拒绝，再按常规停止。提问与密钥请求不跟着回合，停止会话不撤下它们。
- 审批等待时不回应、直接发一条新消息：新消息先排进输入，再把审批按拒绝交回，回合接着走，模型在下一次请求里看到这个结果和新消息。有没回应的提问或密钥请求时发消息只是发消息，请求留着。
- 审批等待时服务重启：与普通工具调用中途断开相同，沿用 [恢复约定](harness-主循环.md#恢复约定)：调用已开始而没有结果，标记 unknown，线程进入恢复阻塞；等待的对象作废，之后的回应被拒绝。执行中挂住的网络连接随命令一起结束。
- 没回应的提问与密钥请求存在工作机的库里，服务重启后照旧在等，随工作区流转到别的工作机；线程归档时撤下。

两个后端行为一致：审批在宿主里等待；提问与密钥请求由 Kite 宿主执行，结果经宿主的输入交给代理。

## 接口草案

| 入口 | 约定 |
|---|---|
| 会话状态 | `thread.state` 增加 `waiting?: {id, kind: "approval", since, ...}`，带工具、目标与原因，出沙箱的命令带 `outside` 与绑定的密钥引用 `secretReferences?`；`asks?: [{id, kind, since, ...}]`，提问带问题与选项，密钥请求带 `secrets`，每项是名称或文件与变量名、用途、类型、代理给的值与同名是否已存在 |
| `POST /threads/:id/waiting/:waiting` | 回应审批或一项请求。审批 `{decision: "once" \| "remember" \| "deny"}`；提问 `{answers: [{selected?: string[], other?: string}]}` 或不回答 `{decision: "deny"}`；密钥请求 `{secret: {values, scope?}}` 或 `{decision: "deny", reason?}`，`values` 按请求的顺序逐项给值、没填的为 `null`，`scope` 为 `project`（默认）或 `account`；已回应、作废或收回返回 409 与当前的审批 |
| `POST /threads/:id/messages` 带 `skipWaiting` | 值是线程在等的审批的 ID，只用于用户在 App 里发送：消息排进输入后按拒绝交回；审批已回应或已作废时只发消息 |
| `GET / PUT /instances/:id/approval-mode` | 读取或设置实例的审批模式 |
| 工具 `question` | 提问 `{questions: [{question, options: [{label, description}], multiSelect}]}`，立即返回请求 ID；收回 `{withdraw: 请求 ID}` |
| 工具 `credentials` 的请求 | 见 [credentials](harness-主循环.md#credentials) |
