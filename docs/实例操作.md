# 实例操作与授权

当前实现提供 agent、文件与 Bun 插件操作。HTTP、harness 模型工具与插件调用共用 `operation-contract.ts` 的输入、输出和错误声明，由 `InstanceOperations` 校验身份和授权，再调用对应业务服务。

## 操作与入口

| 操作 | 模型工具 | 主要输入 | 返回值 |
| --- | --- | --- | --- |
| `agent.start` | `agent_start` | definitionId、可选 title / prompt / presentation | instanceId、可选 windowId |
| `agent.list` | `agent_list` | 无 | 当前工作区的 agent 摘要与获准操作 |
| `agent.send` | `agent_send` | instanceId、text | 已接收输入的 id |
| `agent.resume` | `agent_resume` | instanceId | `{ok: true}` |
| `agent.stop` | `agent_stop` | instanceId；UI 可带未确认 inputs | `{returned: Input[]}` |
| `plugin.call` | 从获准 MCP 声明生成实例专属工具 | instanceId、tool、arguments | 原 MCP 工具结果 |

`GET /operations` 返回完整 JSON Schema、调用方类型、修改语义、重试和取消规则。`PluginDefinition.operations` 声明该定义的实例可接受哪些操作；agent 实例声明 send / resume / stop，创建和查询作用于工作区。

HTTP 调用使用 `POST /workspaces/:id/operations/:operation`。除 list 外，请求必须带稳定 `operationId`。例如：

```json
{
  "operationId": "create-review-1",
  "definitionId": "kite.agent.review",
  "title": "检查当前改动",
  "presentation": "background"
}
```

省略 prompt 只创建空会话，不调用模型。`presentation` 默认 window：实例、Thread 与首窗口同事务创建；inline 和 background 只创建实例与 Thread，后续可通过窗口接口打开其视图。当前尚无专门的 inline 界面。关闭窗口保留实例和执行。

带 prompt 的创建，以及 send / resume，都遵守现有工作区执行互斥：同一 cwd 有其他线程运行或等待恢复确认时拒绝启动。模型可以在自己的回合中创建空 agent，后续调度与跨线程并发仍待实现。

list 读取已保存的线程投影，不打开 Runner、不创建 journal、不唤醒模型。返回持久状态、执行阶段、busy、waitingForResume、恢复原因和调用方获准操作；获准不表示当前执行状态允许该动作，最终仍由 Thread 服务判断。

原有 messages / interrupt / resume HTTP 入口也转交给这套操作。stop 直接使用 Thread 停止收据，保留 App 未确认输入的核定与退回语义。恢复确认仍是 UI 的 recover 入口，模型没有自动确认未知执行结果的工具。

## 调用身份与授权

HTTP 宿主绑定 UI 身份；模型工具闭包绑定调用实例和工作区，ToolBatch 提供 turnId 与 callId。模型参数不能指定调用身份、工作区、operationId 或未确认用户输入。模型操作 ID 使用 `turnId:callId`，send / stop 的底层收据 ID 再加调用方命名空间。

Bun 插件的 MCP 连接绑定调用实例与工作区，`kite/operation` 回调通过同一授权入口执行；不能由插件参数更换身份。插件包、状态与调用收据见 [Bun 插件宿主](Bun插件.md)。

授权保存于 `PluginInstance.config.grants`，支持：

- list：查询所属工作区的 agent 摘要；
- start：仅创建列出的 definitionIds；
- send / resume / stop：目标为调用方创建的实例，或显式列出的 instanceIds。
- files.list / read / diff / state / select：目标为显式列出的文件 instanceIds，可包含文件插件自身。
- plugin.call：指定同工作区的 Bun 插件 instanceId 和 tools 名称列表，宿主发现并登记真实 MCP 声明；默认不授予。

宿主登记的 coding 定义默认可以查询、创建 coding / review，并控制自己创建的 agent。review 默认没有协作授权，工具仍只有 read。实例的 origin 由宿主写入，记录创建者和调用来源；它用于授权核验，不代表级联归档或删除关系。

读取与更新授权使用：

```text
GET /instances/:id/operation-grants
→ {grants, revision}

PUT /instances/:id/operation-grants
← {expectedRevision, grants}
```

更新与工作区控制串行执行。revision 不匹配时拒绝覆盖；显式目标必须是同一工作区内声明了相应操作的实例。每次调用都核对来源、工作区、目标生命周期和定义声明，并在等待锁或打开运行时之后、业务提交之前重新核对。agent 不能借协作操作控制自己。

harness 的工具声明保持固定；内置工具取定义声明、实例工具配置和授权的交集，插件工具取宿主登记声明与显式授权的交集。插件声明在首次请求前登记，之后只能撤回或恢复已登记的工具，新增声明需要新会话。授权撤回后，旧请求返回的工具调用也会被执行入口拒绝。插件工具授权变化在下次自然请求追加通知，不唤醒模型，也不改写历史上下文；已提交的动作不会因此撤销。具体工具别名、快照和可见性规则见 [Bun 插件宿主](Bun插件.md#模型工具与插件间调用)。

这层授权限定经过操作入口的调用。harness 的文件与命令访问另由下面的执行授权控制。当前本机 HTTP 仍信任本机客户端，`X-Kite-Machine` 只防止连错机器；远程认证仍待实现；自定义插件通过受限进程的 MCP 管道接入，不能直接访问本机管理 HTTP。

## 实例执行授权

执行授权保存于 `PluginInstance.config.execution`，独立于 agent 的工具选择和协作操作授权。当前接通 harness，Claude、占位插件和 Bun 插件不提供这个管理接口；首期 Bun 插件固定只能读自身代码与必要系统文件，使用临时空间，工作区访问经过能力桥。编程实例默认工作区可写，只读审查实例默认只读；额外路径和网络默认均为空。

```text
GET /instances/:id/execution-grants
→ {grants, revision}

PUT /instances/:id/execution-grants
← {expectedRevision, grants}
```

`grants` 的格式：

```json
{
  "workspace": "read",
  "read": ["/已有的参考目录"],
  "write": ["/已有的构建缓存目录"],
  "network": ["registry.npmjs.org:443"]
}
```

- `workspace` 为 `read` 或 `write`。`read` / `write` 是额外的绝对文件或目录许可，写许可也包含读取。路径须存在，保存时解析真实位置、去重并排序；此后路径消失或被替换成指向别处的链接会拒绝执行，须重新授权。
- 网络采用上游域名、IP 和可选端口规则，允许 `*.example.com`，不允许全网 `*`。目前拒绝 localhost 及回环 IP 的授权，避免沙箱内进程访问尚未鉴权的本机控制接口；普通域名解析到回环或本机地址也由上游代理拦截。
- 系统工具链与 Git 配置的基础读取权限由宿主提供；宿主认证、数据库、会话记录和 Git 元数据保护不能用额外路径许可解除。额外路径通过 shell 使用，`read` / `patch` 仍限当前工作区。
- PUT 与工作区控制共用锁，版本不匹配返回 409。相同配置不重复通知。运行中、停止中或执行结果未知时拒绝修改；先通过现有 stop / recover 流程确认停止，再更新。不会自动停止、重放命令或恢复模型请求。
- 配置和 `execution.permissions.changed` 通知同事务保存。已有运行时的后续工具调用读取新策略，下一次自然模型请求追加通知，已发送上下文前缀保持原样；请求快照的 `settings.execution` 保存版本与授权内容。
- 模型和插件没有修改执行授权的操作。它们创建的新 agent 使用目标定义的默认权限；父实例仅有工作区读取权限时，新 agent 也不会自动获得工作区写权限。额外目录和网络许可不自动继承。已经创建的实例仍按各自授权工作；跨实例控制受协作操作授权限制。

管理入口目前为 HTTP，App 的授权编辑界面尚未接入。执行机制及平台边界见 [Agent 与插件契约 §7](Agent与插件契约.md#71-插件与-harness-共用操作系统沙箱)。

## 重试、取消与结果

| 操作 | 重试依据 |
| --- | --- |
| list | 重新只读查询 |
| send | 沿用 Thread 输入 ID 与内容去重 |
| stop | 沿用 Thread 停止 ID 和停止收据 |
| start / resume | SQLite 保存调用方、operationId、请求及结果；同时到达的相同请求共用执行 |
| files.select | 复用 SQLite 操作收据；expectedRevision 防止覆盖另一端的新选择 |
| plugin.call | 插件宿主保存调用方、目标实例及 operationId 收据；丢失结果不重放 |

start / resume 的同一 operationId 不能换参数。已完成请求跨重启返回保存的结果，不再次创建或继续。若崩溃只留下开始记录、没有结果，则返回 unknown；调用方先查询实例状态，再决定是否以新 operationId 发起动作。实例创建事务与操作结果收据不是一个跨服务事务，因此不能承诺任意崩溃下恰好执行一次。

取消信号在提交前检查；提交后等待服务确定结果，不撤销已发生的动作。关闭 kited 时先拒绝新操作，并等待已进入的调用收口。

操作错误包含 `{error, outcome}`：

- denied：参数、身份、目标或授权不允许；
- failed：服务明确报告业务失败，例如工作区忙或需要恢复确认；
- cancelled：提交前已取消；
- unknown：无法确认结果，包括崩溃后缺失结果或执行后的收据写入异常。

模型侧分别映射为 error、not_executed 或 unknown 工具结果；失败正文保留 outcome。停止与恢复状态仍以 [会话状态机](会话状态机.md) 为准。

## 文件插件

`kite.files` 实例提供一个 files 视图，合并目录、原文、渲染预览与历史 diff，通过同一 HTTP 操作入口读取所属工作区。

| 操作 | 输入（均带 instanceId） | 输出 |
| --- | --- | --- |
| files.list | path 默认 `.`，offset 从 0 开始，limit 默认 200、最多 1000 | path、entries（name / path / kind）、total、nextOffset |
| files.read | path，offset 从 1 开始，limit 默认 200、最多 2000 | path、text、offset、totalLines、nextOffset、version |
| files.diff | diffId | id、files（path / before / after） |
| files.state | 无额外参数 | path（可为 null）、可选 diffId、revision |
| files.select | operationId、expectedRevision、path（null 表示清除）、可选 diffId | 保存后的 path、可选 diffId、revision |

list 按目录优先、名称排序，分页是本次查询的结果，不承诺目录变动中的稳定快照。read 返回最多 2 MiB 文本文件的指定行，version 是完整内容摘要。服务拒绝工作目录外的路径和越界符号链接；agent 的 read 与 patch 共用同一边界。文件读取不启动 Thread、不保存对话，也不修改文件或创建 Git 快照。

select 先检查文件可作为文本读取；携带 diffId 时改为核验文件属于该历史差异，不要求当前文件仍存在。随后将规范化的相对路径与新 revision 保存在实例 state，再广播工作区变化。App 从工作区聚合读取最新选择，同一实例的目录和内容区域共用它；关闭窗口和重启服务仍保留选择。文件被删除时保留所选路径，预览报告读取错误。文件的实际内容由文件系统持有，目录页码与文本页码由客户端管理，刷新读取最新内容；当前没有后台文件监听。

这些文件操作声明给 UI 与获准插件调用，不额外生成模型工具。模型继续使用现有 read / patch / shell，文件插件与模型在核心文件服务汇合。App 当前不编辑文件；符号链接会列出，但没有点击跳转入口。独立 `kite.preview` 占位已移除，引用与历史差异见 [资源引用](资源引用.md)。
