# 实例操作与授权

本文适用于 agent、文件与 Bun 插件的操作调用。HTTP、harness、Claude 模型工具与插件调用共用输入、输出和错误契约；宿主绑定身份并核验授权。

## 操作与入口

| 操作 | 模型工具 | 主要输入 | 返回值 |
| --- | --- | --- | --- |
| `agent.start` | `agent_start` | 可选 role / title / prompt / show / isolation；role 为角色 ID，省略时用默认角色；isolation 见 [子工作区](#子工作区) | instanceId，开子工作区时另带 workspaceId |
| `agent.merge` | `agent_merge` | instanceId，须是开出子工作区的代理 | `merged`、`unchanged`（都已归档）或 `conflict` 与冲突文件 |
| `agent.list` | `agent_list` | 无 | 协作范围内的 agent 摘要（含所用角色），字段见 [列出实例](#列出实例) |
| `agent.send` | `agent_send` | instanceId、text | 已接收输入的 id |
| `agent.resume` | 无，只给界面的「继续」 | instanceId | `{ok: true}` |
| `agent.stop` | `agent_stop` | instanceId；UI 可带未确认 inputs | `{returned: Input[]}` |
| `plugin.call` | 从获准 MCP 声明生成实例专属工具 | instanceId、tool、arguments | 原 MCP 工具结果 |
| `monitor.start` | `monitor_start` | title，command 或 at / minutes（可带 repeat） | instanceId |
| `monitor.list` | `monitor_list` | 无 | 协作范围内开着的 monitor 与来源状态 |
| `monitor.stop` | `monitor_stop` | instanceId | `{ok: true}` |

`GET /operations` 返回完整 JSON Schema、调用方类型、修改语义、重试和取消规则。能授予代理与插件的操作另带 `grant`：授权里 operation 以外要写的字段（`params`）与目标能取的种类（`targets`，不分目标的没有），由授权的 schema 推出，界面按它生成授权；没有 `grant` 的只给界面调用，调用方里不列插件。定义声明可接受的操作；agent 实例接受 send / resume / stop / merge，创建和查询作用于工作区。

HTTP 调用使用 `POST /workspaces/:id/operations/:operation`。除 list 外，请求必须带稳定 `operationId`。例如：

```json
{
  "operationId": "create-review-1",
  "role": "kite.review",
  "title": "检查当前改动"
}
```

按角色创建的代理与界面新建的一样：提示词、工具、默认模型与预算取自角色。省略 prompt 只创建空代理，不调用模型。新代理在各端的停靠栏里占一格，用户从创建它的 agent 处或停靠栏查看；带 `show: true` 时工作机推 `instance.show`，用户正在用的设备把它放上台面，见 [台面与停靠栏](台面与停靠栏.md#跨设备)，只在用户要求看着它时传。实例与 Thread 一起创建，失败不得留下半成品。缩小不改变实例和执行。

带 prompt 的创建，以及 send / resume，不要求同一工作区的其他线程空闲：线程之间默认并行，只有回退、采纳与交接这类工作区级操作要求全员空闲，归档工作区先停下全部线程，见 [工作区并行](工作区并行.md)。

list 只读状态，不启动执行或创建会话记录；列出的获准操作仍受当前执行状态限制。

messages / interrupt / resume HTTP 入口采用相同的授权与重试语义。stop 的未确认输入与队列退回规则见 [会话状态机](会话状态机.md#手动停止与消息交接)。代理之间发消息即继续，不另给继续工具。

### 列出实例

`agent_list`、`monitor_list`、`terminal_list`、`preview_list` 只返回调用方这项 list 授权的目标范围内的实例，代理即它的[协作范围](#调用身份与授权)；界面调用看全部。每项带 ID、标题、创建来源（`createdBy`，用户在界面上开的为空）、创建时间、一行状态，以及调用方对它获准的操作；预览实例另带目标与设备，见 [预览](#预览)。状态由宿主给出：代理为空闲、运行中、等用户批准或上一回合失败；终端与预览为运行中或已退出（带退出码或原因）；monitor 为在盯或来源都已结束。list 不返回实例的私有状态，内容经各插件自己的工具读取。自定义插件的工具按实例授予，可用的实例列在基础上下文里，不另设 list。

### 子代理回报

一回合里发过消息的代理都是这一回合的交代方；交代之后用户又发了消息，这一回合就归用户，不再回报。交代的回合结束时（完成、失败或被别人停下），宿主用 `agent.report` 模板给每个交代方投一条 Kite 来源的输入，写明子代理的标题与实例 ID、结果和最后回复的末尾（约 3000 字），交代方空闲时因此开始新回合。交代方自己用 agent_stop 停下的不回报，换机、关机等宿主自己打断的也不回报；卡在等用户回应不算结束。

每个代理每天被回报唤醒最多 40 次，超了或交代方此刻收不下输入（正在停止）时改为不唤醒的通知，在下一次自然请求时纳入。交代方已归档时不投。交代关系与当天的次数只在内存里，kited 重启时进行中的回合（包括重启后接着做完的）不再回报。Line 交代的工作照旧经 Line 的 monitor 汇报，不重复走这条路。

### 子工作区

**状态：已实现。** 子工作区的起点、合回、放弃、兜底与换机以 [项目与远程仓库](项目与远程仓库.md#子工作区) 为准，这里只写操作契约。

- `agent_start` 带 `isolation: "workspace"` 时，宿主在本机从调用方工作区最近的快照开出子工作区，新代理是其中第一个线程，prompt 是它的首条消息，来源与回报同普通创建。子工作区里的代理仍是调用方的后代。
- 子工作区没准备好（`.kite/setup` 失败等）时，宿主用 `agent.workspace` 模板给开出它的代理投一条 Kite 来源的输入，说明里面的代理没有开始。
- `agent_merge` 的目标须是用 `isolation` 开出子工作区的那个代理；同工作区的代理和子工作区里后来开的代理都拒绝并说明原因。它合回的是整个子工作区，合完归档子工作区及其中的实例。有冲突时立即返回 `conflict`，冲突交给子工作区里的线程解决，之后由宿主接着合；接着合完或失败时，以及处理冲突的代理被停下、回合失败时，宿主同样用 `agent.workspace` 模板给发起方投一条输入。子工作区里的代理不能合回自己所在的子工作区。这类输入与子代理回报共用每天的唤醒上限，超了改成不唤醒的通知。
- 代理没有归档工具。同工作区的代理停下即可，随工作区归档；子工作区的放弃只由用户执行。
- list 列出子工作区里的后代时，每项另带所在工作区（`workspace` 的 ID 与名称）。

## 调用身份与授权

HTTP 宿主绑定 UI 身份，模型和插件调用绑定来源实例与工作区。模型参数不能指定调用身份、工作区、操作 ID 或未确认用户输入；它们由宿主确定，避免冒用身份及跨调用混用收据。

Bun 插件的 MCP 连接绑定调用实例与工作区，`kite/operation` 回调通过同一授权入口执行；不能由插件参数更换身份。插件包、状态与调用收据见 [Bun 插件宿主](Bun插件.md)。

协作授权（接口里叫 operation grants）管代理与插件能对工作区里的哪些实例调用哪些操作。对其他代理、monitor 与终端的授权带目标 `targets`：

- `created`：调用方直接创建的实例；
- `instances`：显式列出的 instanceIds；
- `descendants`（仅后代）：调用方创建的实例，以及它们再创建的，按创建来源逐层往下算，包括代理、monitor 和转到后台的终端；在子工作区里的后代也算，见 [子工作区](#子工作区)；
- `workspace`（同工作区）：所属工作区里的全部。

各项授权：

- agent.list、monitor.list、terminal.list：目标只取 `descendants` 或 `workspace`，决定列出哪些；
- agent.send / stop / merge、monitor.stop、terminal.read / terminal.stop：四种目标都可以；
- agent.resume 不授予：只给界面的「继续」，代理之间发消息即继续；
- start：仅按列出的 roleIds 创建代理；内置代理默认可按「工作」与「只读审查」创建；
- monitor.start：不带目标，开 monitor，唤醒的是开启它的代理；
- preview.open / list / action / inspect / read / stop：不带目标，本工作区的预览都能起、看、操作和停，不限创建来源；
- files.list / search / read / write / diff / state / select：目标为显式列出的浏览 instanceIds，可包含浏览实例自身；插件调用 write 时路径还要在工作区内可写、不碰宿主内部数据。
- plugin.call：指定同工作区的 Bun 插件 instanceId 和 tools 名称列表，宿主发现并登记真实 MCP 声明；默认不授予。
- line：`{operation: "line", actions}`，Line 的管理动作白名单，目标范围是账号目录里的全部工作区，是「目标限同工作区」的唯一例外；只在启用 Line 时授予 Line 实例，其他代理须用户另行授予且角色放开了对应工具。动作与确认核验见 [Line](Line与工作区流转.md#line)。

代理共用 `kite.agent` 定义，默认授权随角色可用的工具收窄。「工作」（`kite.work`）可以按「工作」或「只读审查」（`kite.review`）创建代理，并开 monitor；「只读审查」只有 read，不保留协作授权。改选角色时，新角色用不了的授权去掉，新能用的补上默认授权。创建者关系由宿主确认，用于目标范围；归档代理时，同一工作区里它开出、还开着的各层子代理一起归档，子工作区里的不算，也不代表删除关系。

**代理的协作范围。** 代理对其他代理、monitor 与终端的那几项授权（上面的 list、send / stop、monitor.stop、terminal.read / terminal.stop）共用一个目标：`workspace`（默认）或 `descendants`，界面上作为一个「协作范围」选择，改选角色时补上的沿用原来的范围。范围同时决定 `agent_*`、`monitor_*`、`terminal_*` 工具能对准哪些实例，以及 list 返回哪些实例；项目约束禁用的工具照旧不声明给模型。超出后代范围时，对方的执行授权有调用方没有的项（工作区写入、额外读写路径、网络主机或沙箱外命令）的，send 先在调用方线程上等用户批准；agent.stop、monitor.stop、terminal.stop 一律先等用户批准，审批沿用 [工具审批](工具审批与提问.md)。agent.merge 也在这几项里，共用同一个范围；它的目标在子工作区里，只能经后代够到，所以不会超出后代范围。跨工作区只属于 Line 的授权；普通代理只能经后代够到自己开出的子工作区。插件作为调用方按各项授权逐项授予，插件工具按实例与工具逐项授予。

读取与更新授权使用：

```text
GET /instances/:id/operation-grants
→ {grants, revision}

PUT /instances/:id/operation-grants
← {expectedRevision, grants}
```

revision 不匹配时拒绝覆盖；显式目标必须是同一工作区内声明了相应操作的实例。目标须处于可用状态，且操作符合来源、工作区和定义声明的限制。权限变化后，已经在途但尚未提交的操作也不能绕过撤权。agent 不能借协作操作控制自己。

harness 与 Claude 的工具新增和撤回时机见 [线程通知投递](线程通知投递.md)，插件工具的声明与可见性见 [Bun 插件](Bun插件.md#模型工具与插件间调用)。工具选择与授权共同限制可调用范围，已提交的动作不会因撤权而撤销。

这层授权限定经过操作入口的调用。Kite 工具的文件与命令访问另由下面的执行授权控制。本机 HTTP 信任本机客户端，远程监听只接受已验证同账号身份的组网代理（见 [远程连接](kited.md#远程连接)），两者的调用都按 `ui` 身份进入操作入口；`X-Kite-Machine` 只防止连错机器；自定义插件通过受限进程的 MCP 管道接入，不能直接访问本机管理 HTTP。

### Bun 插件的定义级授权

每个 Bun 插件定义有一份协作授权，默认为空。新建这个插件的实例时拷进实例的协作授权，之后修改定义级不改变已有实例，实例上照旧用 `operation-grants` 增减；分层见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。它是账号级数据，在工作机之间同步，任一台工作机都能读写，账号资源库里尚未装到本机的包也一样。

```text
GET /plugins/:definitionId/grants
→ {grants, revision}

PUT /plugins/:definitionId/grants
← {expectedRevision, grants}
→ {grants, revision}
```

- 只收不对准具体实例、插件调得了的项：`agent.start`（roleIds 须是已有的角色）、目标为 `created`、`descendants` 或 `workspace` 的协作项，以及不带目标的 `monitor.start` 与预览操作。目标为 `instances` 的、`plugin.call`、`files.*` 和 `line` 只能在实例上授予。
- PUT 替换整个列表，revision 按 grants 计算，同实例授权。revision 不匹配 409；有不收的项 400，错误说明第几项、为什么；定义不存在或不是 Bun 插件 404。
- 修改后（本机改的或其他工作机同步来的）目录流推 `kind` 为 `plugin` 的 `library.changed`。
- 这一版认不出的项（新版本才有的操作）读取时不列出，保存时原样保留。

## 实例执行授权

执行授权独立于 agent 的工具选择和协作授权，按项目、角色、实例三层合成，见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。harness 与 Claude 提供此管理接口，占位插件和 Bun 插件不提供；Bun 插件只能读自身代码与必要系统文件、使用临时空间，工作区访问经过能力桥。没有项目许可和角色增减时，代理的执行授权是工作区可写，额外路径、网络和沙箱外命令均为空。

```text
GET /instances/:id/execution-grants
→ {grants, revision, effective, project}

PUT /instances/:id/execution-grants
← {expectedRevision, grants}
```

`grants` 是实例在项目基础上的增减（新建时拷自角色），`effective` 是三层合成后实际生效的，`project` 是所属项目的基础与禁止：

```json
{
  "workspace": "read",
  "add": { "read": ["/已有的参考目录"], "write": [], "network": ["registry.npmjs.org:443"], "unsandboxed": ["docker compose *"] },
  "remove": { "read": [], "write": [], "network": ["cdn.example.com"], "unsandboxed": [] }
}
```

- `workspace` 为 `read` 或 `write`，省略时用可写；项目定为只读时一律只读。`add` 加许可，`remove` 去掉项目给的基础许可。
- `read` / `write` 是额外的文件或目录许可，写许可也包含读取。实例里加的路径须为存在的绝对路径，授权针对其真实位置，新建时拷来的角色路径在本机存在的也同样绑定；此后被替换成指向别处的链接会拒绝执行，须重新授权。项目的路径按各工作机自己解析（跟随链接）。项目和角色的路径可写 `~/` 开头。各层路径在本机不存在的略过。`remove` 按项目里写的原样比对。
- `unsandboxed` 是沙箱外命令，写法同 Claude Code：`docker compose *` 以 ` *` 结尾表示带任意参数，否则须一字不差。一条调用里用 `&&`、`||`、`;`、`|`、`&` 连起来的每一段都要匹配；含 `$(`、反引号、重定向或换行的调用只认整条原样登记过的。匹配的命令不进沙箱，以用户身份运行，带 secrets 的也一样。项目禁止按词比对：去掉引号，不分大小写，程序路径只看名字，调用里任何位置出现都算命中（`FOO=1 sudo …`、`env sudo …`、`sh -c "sudo …"` 都算），这条调用就不能出沙箱；运行时才拼出来的命令（变量、脚本里的）认不出，要硬边界时把项目的审批上限定为越界询问或仅白名单。审批时以 ` *` 结尾的命令只能批准一次，不能记住。
- 网络采用上游域名、IP 和可选端口规则，允许 `*.example.com`，不允许全网 `*`。目前拒绝 localhost 及回环 IP 的授权，避免沙箱内进程访问尚未鉴权的本机控制接口；普通域名解析到回环或本机地址也由上游代理拦截。
- 系统工具链与 Git 配置的基础读取权限由宿主提供；宿主认证、数据库、会话记录和 Git 元数据保护不能用额外路径许可解除。额外路径通过 shell 使用，`read` / `patch` 仍限当前工作区。
- PUT 版本不匹配返回 409。相同配置不重复通知。运行中或停止中拒绝修改，先 stop 再更新；失败后等待继续时可以修改，下一次执行用到。不会自动停止或重放命令。例外是审批时的「允许并记住」：运行中只追加一条网络许可，在后续连接与调用生效，见 [工具审批与提问](工具审批与提问.md)。
- 越出执行授权的请求按审批模式处理，`GET / PUT /instances/:id/approval-mode` 读写实例的 `{mode}`，读取时另给按项目上限收紧后实际用的 `effective` 与上限 `max`。新建代理时依次取草稿的选择、角色给的默认与工作机的默认（`ask` 问人，`/roles` 的 `defaultApproval` 给出），写进实例配置。
- 授权与对应通知共同保存，后续工具使用新策略。告知模型的时机按后端交接边界处理，保留已经发送的前缀，详见 [线程通知投递](线程通知投递.md)。
- 模型和插件没有修改执行授权的操作。它们创建的新 agent 使用目标定义的默认权限；父实例仅有工作区读取权限时，新 agent 也不会自动获得工作区写权限。额外目录和网络许可不自动继承。已经创建的实例仍按各自授权工作；跨实例控制受协作授权限制。

执行机制与平台边界见 [Agent 与插件契约](Agent与插件契约.md#71-插件与-harness-共用操作系统沙箱)。

## 重试、取消与结果

| 操作 | 重试依据 |
| --- | --- |
| list | 重新只读查询 |
| send | 沿用 Thread 输入 ID 与内容去重 |
| stop | 沿用 Thread 停止 ID 和停止收据 |
| start / resume | 同一调用方的 operationId 标识同一请求，跨重启返回原结果 |
| monitor 的 start、stop 与界面操作 | 复用持久操作收据 |
| files.select | 复用持久操作收据；expectedRevision 防止覆盖另一端的新选择 |
| files.write | 按内容：文件已是这份内容时直接返回，不再写、不再打快照；baseVersion 防止覆盖别人的新改动 |
| plugin.call | 插件宿主保存调用方、目标实例及 operationId 收据；丢失结果不重放 |

同一调用的并发重试等待同一结果，错误同样保留 outcome 与 HTTP 状态码。执行后无法可靠保存结果时返回 unknown，不能以重试再次执行；插件进程停止失败也须明确报告。

start / resume 的同一 operationId 不能换参数。已完成请求跨重启返回保存的结果，不再次创建或继续。执行中被 kited 退出打断（或工作区被接管）、没留下结果的返回 unknown；调用方先查询实例状态，再决定是否以新 operationId 发起动作。不能承诺任意崩溃下外部动作恰好执行一次。

提交前可取消；提交后须等待明确结果，不撤销已发生的动作。kited 关闭期间拒绝新操作，已受理的操作仍须等待明确结果。

操作错误包含 `{error, outcome}`：

- denied：参数、身份、目标或授权不允许；
- failed：服务明确报告业务失败，例如工作区忙或会话正在停止；
- cancelled：提交前已取消；
- unknown：无法确认结果，包括崩溃后缺失结果或执行后的收据写入异常。

模型侧分别映射为 error、not_executed 或 unknown 工具结果，失败正文保留 outcome；unknown 和其他结果一样交给模型，不让调用方的回合停下。停止与被打断后的处理以 [会话状态机](会话状态机.md) 为准。

## Monitor

`kite.monitor` 实例由代理用 `monitor.start` 开启，或启用 Line 时由宿主建（收件箱）；界面不能直接新建。代理默认获准开启、列出和停止自己开的 monitor。语义见 [Monitor](Monitor.md)。

| 操作 | 输入（均带 instanceId） | 输出 |
| --- | --- | --- |
| monitor.read | 无额外参数 | 代理开的：标题、来源与是否结束、今天的唤醒次数、时间线；Line 的：收件箱 `{items, period, records, delegation}` |
| monitor.delegate | operationId、item | 交给 Line 的那一项；只用于 Line 的收件箱 |
| monitor.dismiss | operationId、item | `{ok: true}`；只移得掉回合结束 |
| monitor.hosting | operationId，until、timeoutMinutes（null 关闭，省略不变） | 当前的托管设置 |

这四个只供界面调用。monitor 的时间线或来源状态变化时，目录与工作区事件流推 `monitor.changed`（`instanceId`），正在看它的设备重新读取。

## 终端

`kite.terminal` 实例一个实例一个进程，lifetime 为 `process`（见 [实例生命周期](Agent与插件契约.md#33-plugininstance工作区中的业务对象)），提供 terminal 视图；进程监听的端口上的网页用 [浏览](#浏览) 看。来源有两种：

- 用户新建终端时，工作机在工作区目录起用户的登录 shell，跑在 PTY 里，不加沙箱；zsh 打开 interactivecomments，粘贴进去的注释行不当命令。新建时可以带 `command`（shell 代码块的「在终端中执行」）：shell 起好后像粘贴那样打进去并回车，跑完 shell 还在；同一请求重试不再执行。
- agent 的 shell 命令到时限、用户插话或传 `background: true` 时转来，建一个终端实例，创建来源记为那次工具调用，进程结束即回收；仍在 agent 的沙箱里，只有输出，转过去之后名单外的主机直接拒绝，不再问人。

| 操作 | 模型工具 | 输入 | 输出 |
| --- | --- | --- | --- |
| terminal.read | `terminal_read` | instanceId，可选 offset（从 1 开始）、limit 默认 200 | 进程状态（phase、exitCode、signal、reason）与按行的输出；不给 offset 时取最后 limit 行 |
| terminal.stop | `terminal_stop` | operationId、instanceId | 先挂断，等不到退出再停整个进程组，确认结束才返回 `{ok: true}` |
| terminal.list | `terminal_list` | 无 | 协作范围内的终端，字段见 [列出实例](#列出实例) |

转来的命令读完整输出，交互终端读屏幕与回滚里的文字。命令结束时，工作机用 `terminal.exit` 模板给启动它的 agent 投一条 Kite 来源的输入，带结果和输出末尾，agent 空闲时因此开始新回合；agent 自己用 terminal_stop 停的不再通知，agent 归档时它的后台命令随之停止。它的后台命令还在运行时，修改它的执行授权会被拒绝。

### 运行中的网页

不变式与取舍见 [成果查看与位置 · 运行中的网页](成果查看与位置.md#运行中的网页)，这里是端口探测与链接解析的接口，看网页的接口见 [浏览](#浏览) 与 [预览](#预览)。

- 运行中的终端与预览实例每隔约 2 秒从自己的进程树（进程及其后代）找正在监听的 TCP 端口，写进实例状态（两种实例的进程状态都在 `state.terminal`，端口是 `state.terminal.ports`），每项 `{port, http}`，按端口号排；`http` 是工作机直接连本机回环试过能用 HTTP 打开，一个端口最多试 5 次。结束后状态里没有端口。脱离进程树的进程（守护化、交给 launchd）不算。
- 本机全部运行中终端与预览实例的端口合在一起，整组交给组网转发；实例结束、停止，工作区交接、冻结、归档时随之去掉。kited 与 kite-net 自己的端口不转发。
- 终端的卡片在进程有能用 HTTP 打开的端口时提供「打开网页」，打开第一个这样的端口的浏览实例。
- 消息里 `localhost`、`127.0.0.1` 上带端口的 `http(s)` 链接，以及正文里裸写的 `localhost:<端口>`、`127.0.0.1:<端口>`（都可以带路径），在所属工作区内解析：端口属于本工作区运行中的预览实例时，打开它的网页画面；属于终端时，打开这个端口的浏览实例（已有的优先取本机台面上的，没有就新建）；都到链接的路径、查询与锚点；否则报错，不交给系统浏览器。在设备自己的网页视图里看时，打开到哪个路径只在点链接的设备上，不共享；在工作机上的浏览器里看时，在那个共用的页面里打开。
- 消息里其他的 `http(s)` 链接在浏览里打开：已有在看外网的浏览实例（本机台面上的优先）就选到这个网址，没有就新建一个。
- agent 的命令在沙箱里不能监听本机端口，agent 转到后台的服务没有网页可看；要看的服务做成预览的[目标](#目标)，由 preview_open 在沙箱外起。

### 接入

卡片经 WebSocket `GET /instances/:id/terminal` 接上，可带 `cols`、`rows`。工作机先发当前画面，再推后续输出；PTY 尺寸跟最近一次输入或接入的设备。断线不影响进程，重连从当前画面接上。工作区交接、冻结、归档时终端停止；kited 退出时终端随之结束，重启后不再拉起，实例回收。重启前就已结束、用户还没关的照旧留着，显示最后的画面。协议细节以 [terminals.ts](../kited/src/terminal/terminals.ts) 为准。

## 预览

**状态：** 已实现（2026-10-22），待手测。与下文不同的一处：设备上实时看模拟器现在用 simctl 截全分辨率的屏幕（约半秒一帧），没有截 DeviceHub 的窗口，原因见[模拟器](#模拟器)。工作机上的 Firefox 用的是 Playwright 的构建，在 macOS 27 上起不来（2026-10-22 实测），待上游跟进。

定位与不变式见 [成果查看与位置 · 预览](成果查看与位置.md#预览)，原生 App 的三档显示方式见 [原生 App](成果查看与位置.md#原生-app)。

- `kite.preview` 一个实例是一种[目标](#目标)跑起来的全部进程加画面，`config.preview` 为 `{target, device?}`，建好不变。lifetime 为 `process`：进程结束后标为已结束、留到用户关闭，缩小不停进程，kited 重启后进程没了的回收。`device` 是装到哪台设备，只有要装 App 的目标用：`{simulator: 型号}` 是工作区的模拟器，`{physical: 设备编号}` 是与这台工作机配对过的真机，见[目标](#目标)。同一工作区里同一 `{target, device}` 同时只有一个实例，真机按编号算。实例属于工作区，agent 停与重起不限创建来源。
- 视图三个：`screen`（画面）、`grid`（并排，只有网页画面有）、`output`（输出，进程的日志，同终端视图）。进程的状态与终端相同，在 `state.terminal`。画面的种类由进程产生什么决定，写在 `state.preview.screen`（网页的主端口在 `state.preview.port`）：`web`（进程树里有能用 HTTP 打开网页的端口，主端口是分给目标的 `PORT`，探测见 [运行中的网页](#运行中的网页)）、`simulator`（目标用了工作区的模拟器）、`app`（进程树里开着窗口的 Mac App）、`none`。几种同时出现时按 app、simulator、web 取。
- 网页画面：`state.preview.browser` 是在哪看，各设备共用。省略为 `device`，设备自己的网页视图经端口转发打开，工作机不参与，与[浏览](#浏览)同一个组件；`webkit`、`chromium`、`firefox`、`safari` 是工作机上的浏览器，首页 `http://localhost:<主端口>`，画面传到设备上，人和 agent 操作同一个页面。前三种宿主用 Playwright 无界面运行（第一次用时下载到 Playwright 的默认缓存目录），每个画面一个独立的浏览器上下文。`safari` 是真的 Safari，经系统自带的 safaridriver 驱动：Safari 没有无界面模式，每个画面是工作机桌面上的一个 Safari 自动化窗口，开的时候 Safari 会到前台；Safari 同时只认一个 WebDriver 会话，所有 Safari 画面共用一个、各开一个窗口，会话的浏览数据用完即丢；要用户在 Safari 的设置里打开一次「允许远程自动化」。agent 操作 `device` 的实例时，宿主在工作机的 WebKit 里另开同一个地址，与设备上的内核一致，但不共享状态。
- 并排视图：同一实例的几个工作机浏览器画面铺在一张卡片里，每格一个 `{browser, width, height}`，哪几格由各设备自己定、不共享；agent 的 preview_action 带同样的 browser 与尺寸时，操作的就是那一格的页面。
- 工作机上的浏览器联网不另设限制，同用户在工作机上自己开的浏览器；每个画面的浏览器上下文不带用户的登录状态，Service Worker 关闭。agent 只能打开本实例端口上的路径（preview_action 的 navigate），kited 的接口自己挡浏览器里的页面：只认本机主机名、要自定义请求头、不开放跨源。
- 模拟器：实例设备型号对应的那台，见下文；同一实例的几个画面接入看的是同一块屏幕。
- App 窗口：`state.preview.app` 是本实例进程树里开着窗口的 Mac App 的路径，见下文。
- 工作机上的画面（浏览器页面、模拟器屏幕或 App 窗口）有设备在看或 agent 要用时才开，没人看、agent 也没用十分钟后关掉，再要时重开（浏览器的页面从首页重来）；进程不受影响。

| 操作 | 模型工具 | 输入 | 输出 |
| --- | --- | --- | --- |
| preview.open | `preview_open` | operationId、target（目标名），可选 device（`{simulator}` 或 `{physical}`，见[目标](#目标)）、restart | 已在跑的返回那个（reused 为真）；新起的限时等到画面就绪（端口能用 HTTP 打开、模拟器里 App 到前台或 App 开出窗口）或进程退出，返回 instanceId、画面种类、分给目标的端口段（assignedPort）、进程状态、端口与输出末尾，画面就绪的另带等稳定后的一帧（同 preview.action）。只给模型与插件，界面用新建实例 |
| preview.action | `preview_action` | operationId、instanceId、action，网页可带 browser 与 width、height 指定画面，按需 coordinate、start_coordinate、text、scroll_direction、scroll_amount、duration | 做完等画面稳定，返回 instanceId、title、画面种类、网页的 port 与 browser、App 窗口的 app、url、pageTitle、截图的 width 与 height（画面超过给模型的图片上限时缩小，坐标照截图给）、settled（是否等到了稳定）与一帧截图 |
| preview.inspect | `preview_inspect` | instanceId，网页可带 browser 与 width、height（同 preview.action，指定并排的那一格） | `{text}`：网页是无障碍树（Safari 是近似的轮廓），模拟器和 App 窗口是控件、文字与位置 |
| preview.read | `preview_read` | instanceId，可选 offset（从 1 开始）、limit 默认 200 | 进程状态与按行的输出，同 terminal.read |
| preview.list | `preview_list` | 无 | 本工作区的预览实例：instanceId、title、target、device、画面种类、端口、进程状态、createdBy |
| preview.stop | `preview_stop` | operationId、instanceId | 照 terminal.stop 停整个进程树，确认结束才返回 `{ok: true}`；实例随之回收 |
| preview.select | 无，只供界面 | operationId、instanceId；browser，并排的格子 | 改后的 `{browser?}`；工作机上已开着页面时换浏览器重开 |

- 动作照 computer use 的写法：`screenshot`；`left_click`、`double_click`、`right_click`（模拟器没有）、`long_press`（duration 秒）点 coordinate；`left_click_drag` 从 start_coordinate 拖到 coordinate，模拟器上是滑动；`scroll` 按 scroll_direction 滚 scroll_amount 格（一格约 100 像素）；`type` 输入 text；`key` 按 text 写的键名或组合键（Playwright 的写法，也认 xdotool 的 `Return`、`ctrl+a`）；`wait` 等 duration 秒；网页另有 `navigate`（text 是本端口上的路径）、`back`、`forward`、`reload`，模拟器另有 `home`。各厂商的模型都用这一个函数工具，不接厂商自带的 computer use 工具。
- 坐标是画面的逻辑尺寸：网页是 CSS 像素，模拟器是点，App 窗口是点、原点在窗口左上角（含标题栏）；给模型的截图按逻辑尺寸截，坐标照截图。
- 每个动作之后等画面稳定再返回：每 0.1 秒截一帧比较，连续约 0.3 秒不变算稳定；动作之后画面一直没变的要等满 1 秒，App 冷启动、页面跳转常要一秒多才出第一帧；转圈、动画不会停，最多等约 3 秒，到时给当时的画面，settled 为假。模拟器例外，见[模拟器](#模拟器)。
- 截图作为工具结果的图片交给模型，JSON 里不带；操作收据不存图片，同一 operationId 重放时没有截图。
- agent 操作预览不另经审批，起目标照[目标](#目标)的规则。截图随会话发给模型厂商，agent 操作的模拟器、浏览器与 App 里不登录真实账号。

### 目标

- 目标是项目 `.kite/preview/` 下的可执行文件，文件名就是目标名，一个目标是产品的一种运行方式：开发服务器、跑在模拟器或真机上的 iOS App、Mac App。构建、迁移、跑测试不是运行产品，不放这里，agent 用 shell 跑。`.kite/setup` 由宿主在建工作区时调用，`.kite/check` 由代理经 check 工具调用，都不算目标。写法见 kite-onboard skill。
- 目标在 PTY 里于工作区目录运行，环境与用户新建的终端相同，不加沙箱；脚本退出，实例的进程就结束。
- 端口：宿主按「工作区 + 目标 + 设备」分一段 10 个端口，第一个经环境变量 `PORT` 交给脚本、是网页画面的主端口，其余留给同一目标另起的服务（`PORT+1` 往后）。同一工作区的同一目标与设备再起仍用原来那段，被别的程序占着时另分；不同工作区、同一目标装到不同设备时各用一段，互不重叠，并行的工作区不抢端口。
- 设备：目标用不到的设备不算（脚本里没写 `KITE_SIMULATOR` 的不装模拟器，没写 `KITE_DEVICE` 的不装真机），新建实例时选的设备对每个目标都带着。`device` 选的是模拟器时，宿主按型号为工作区建一台模拟器（见[模拟器](#模拟器)），编号经 `KITE_SIMULATOR` 交给脚本；目标写到 `KITE_SIMULATOR` 又没给设备时用默认型号。选的是真机时，宿主核对它与这台工作机配对过，把编号经 `KITE_DEVICE` 交给脚本，脚本自己构建、装上并启动，跑完就退出；真机没有画面（拿不到实时画面，实测见 spikes/device-mirror），实例只有输出，装上后人拿起设备用。设备要连着线或与工作机在同一局域网。一个目标可以两种都支持（有 `KITE_DEVICE` 装真机，否则装模拟器），也可以拆成两个目标。
- 设备候选是模拟器型号与配对过的真机（`xcrun devicectl` 列出的，带名字、型号与连没连着，没连着的选不了）。界面新建实例时选；在 iPhone、iPad 上打开时默认选中手上这台，按硬件型号对（iOS 不给 App 设备的名字）。agent 在 preview_open 里传同样的 `device`，找不到时错误里列出可选的。
- 同一工作区的同一目标与设备同时只跑一份：再起时返回正在运行的实例；带 `restart` 时先照 preview.stop 停掉再起，卡片接着原来的实例。
- 用户在界面上起的直接运行。agent 用 preview_open 起时，脚本与这台工作机检出主线上的同名文件内容一致才直接运行；不一致或主线上没有，先经审批，卡片给出目标名与脚本内容，受审批模式约束；「允许并记住」按脚本内容记在这个代理实例上，内容再变要重新问；核对之后、启动之前脚本又被改了的不起。agent 装到真机每次都先经审批，与审批模式无关，卡片给出目标名与装到哪台，不记住：装上去会覆盖用户设备上正在用的版本。随意的命令仍经 shell 转到后台，不经 preview_open，沙箱外能跑什么只由项目声明的目标与主线比对把关；`.kite/check` 照同一规则，见 [项目检查](kited.md#项目检查)。
- agent 起的目标进程退出时，照后台命令用 `terminal.exit` 模板通知它；它自己停的、preview_open 等待期间就退出的（结果里已有）不通知。实例属于工作区，不随起它的 agent 归档而停止；工作区交接、冻结、归档时照常停止。
- 目标清单不进工具定义与提示词：`target` 是普通字符串，调用时才在本工作区的工作树里找，运行中途新加的目标下一次调用就能用；找不到时错误里列出现有的目标。工具说明只写目录约定，agent 要知道有哪些就自己列目录。目标跟着工作区的代码走，别的工作区新加并合回主线的，本工作区同步主线后才有。
- 界面新建预览时列出本工作区的目标，每次打开向工作机取当前的目标清单与设备候选（[`GET /workspaces/:id/preview-targets`](kited.md)）；点了以它新建预览实例，创建请求带 `preview: {target, device?}`，已经在跑时返回那个实例、放上本机台面。

### 模拟器

- 画面与操作都用 Xcode 自带的，宿主不另做私有接入（实测见 spikes/xcode-device-interaction）：
  - agent 的动作、截图与界面结构（preview_action、preview_inspect）经 Xcode 27 的设备操作工具：宿主连着 `xcrun mcpbridge`（Xcode 的 MCP 服务，DeviceInteraction 系列），按这台模拟器的编号开会话，没开机的由它开机，第一次启动约半分钟。不用开 Xcode 的界面，它的后台服务第一次连上时自己起来。点按、滑动、长按、按 Home、打字（中文、emoji 都行）都能做，它的命令里没有组合键；坐标的单位是点，界面结构的位置同一套，每个控件带可点的位置。做完一个动作它截一帧并给出界面结构，一次约 0.4–1 秒，不按上面每 0.1 秒截一帧比较的办法等稳定，直接给这一帧。会话闲置几分钟会被 Xcode 关掉，用过的会话名短时间内不能再用，宿主自己重开。
  - 设备上实时看：宿主让当前选中的 Xcode 里的 DeviceHub 打开 `devices://device/open?id=<编号>`（不抢前台），开出这台模拟器的窗口，再像 [App 窗口](#app-窗口)那样截这个窗口、裁到屏幕区域传给设备；人点的位置照样交给 Xcode 的工具。窗口在工作机桌面上，被别的窗口盖住不影响，最小化截不到。没人看时关掉这个窗口。**未实现：** 屏幕在窗口里的位置只能从 DeviceHub 的辅助功能树里读（子角色为 iOSContentGroup 的那一块，窗口的关闭按钮也在这棵树上），2026-10-22 实测只有第一次读得到，之后 DeviceHub 的窗口在辅助功能里都报成整个 App，裁不出屏幕、人点的位置也对不上。现行用 `xcrun simctl io <编号> screenshot` 截全分辨率的屏幕给设备，约半秒一帧，实时画面因此只有一两帧每秒；人点的位置照样交给 Xcode 的工具。
  - Xcode 只认用户批准过的程序：宿主连上后 Xcode 说没批准时，打开 Kite 目录 `xcode/` 下的占位项目（第一次新建）发起批准请求，错误里给出命令，用户在工作机的终端里跑一次（Kite 与这个文件夹各一条 `sudo xcrun mcp-server approve --always <请求编号>`）。`--always` 只给签了名的程序，kited 跑在签了名的 bun 上；批准按程序认，这台机器上用同一个 bun 跑的程序都算批准过的。
  - Xcode 的这套工具只支持模拟器（iOS、watchOS、tvOS 27 以上），Mac App 仍经 kite-window，真机没有实时画面（实测见 spikes/device-mirror）。
- 没有实例在跑、也没人看三十分钟后关机；工作区交接、冻结时关机，归档或随项目删掉时删掉；流转回来接着用原来那台。kited 退出时只断开画面，模拟器照开着。

### App 窗口

- 只看本实例进程树里开着窗口的 Mac App：扫描端口时一并找出，写进状态的 `apps`（名字与路径），只在 Mac 工作机上有。目标脚本要直接运行 App 的可执行文件，经 `open` 起的 App 归 launchd，不在终端的进程树里，看不到。`app` 是 .app 或可执行文件的路径：App 退出、脚本重启后按路径找到新的进程接着看，没在跑时显示原因。
- 看的是 App 最前面的那个窗口，尺寸由 App 自己定，设备按比例显示。只截这个 App 的窗口：别的 App 盖在上面不影响，菜单、弹出框落在窗口范围里的一起截到；输入只发给这个进程，工作机上真的鼠标不动，App 也不用调到前台，人在工作机上照常用别的。最小化、在别的桌面空间里的窗口截不到。App 不在前台时，自己画的、不接受首次点按的 AppKit 视图会吞掉左键，标准控件和 SwiftUI 不受影响（实测见 spikes/mac-app-window）。
- 截图与输入经宿主首次使用时编译的辅助程序 kite-window。系统的「录屏与系统录音」「辅助功能」两项权限按这个辅助程序算，不给 kited，免得 kited 起的进程（含 agent 的命令）都跟着有了这两项权限：第一次用时工作机上会弹系统提示，要用户在系统设置里允许，辅助程序的源码变了要重新允许。谁都能运行这个辅助程序，所以它只操作起它的进程的子孙进程，起它的进程退出就退出；例外是 DeviceHub 为本工作区模拟器开的窗口，只截、不发输入（未实现，见[模拟器](#模拟器)）。
- 在另一台 Mac 上看时，可以把这个 App 装到那台 Mac 上直接用：工作机把 .app 打成 zip（[`GET /instances/:id/preview/bundle`](kited.md)），那台 Mac 上的 App 下载下来交给本机的 kited（[`PUT /apps/:name`](kited.md)）解开到 Kite 目录的 `apps/` 下并打开。不由 App 自己解开：App 开着沙盒，它写出的文件带隔离标记，开发签名的 App 过不了 Gatekeeper。直接跑的可执行文件不是 .app，不能这样装；那台 Mac 上没有运行 kited 时也不行。

### 画面接入

窗口经 WebSocket `GET /instances/:id/preview` 接上，带 `width`、`height`（窗口放得下的逻辑尺寸）与 `mode`（`live` 实时或 `step` 逐帧，默认逐帧）。在设备自己的网页视图里看的网页不接。网页的视口跟着最近操作的设备的窗口尺寸（没人操作过时是第一台接入的），只是打开来看不改视口；agent 上次截图之后视口变了，它再给坐标会被拒，要先重新截图；模拟器屏幕和 App 窗口的尺寸由它们自己定，设备按比例显示。

- 工作机发 `{type: "state", phase, ...}`（phase 为 `waiting` 进程还没产生画面、`starting`、`ready`、`failed`，带 error、url、pageTitle）；`{type: "frame", width, height, settled?, point?}` 后紧跟一条二进制消息，是这一帧的 JPEG，按设备像素截；`{type: "waiting"}` 是开始等画面稳定；`{type: "dropped"}` 是等的期间收到的逐帧输入丢掉了。
- 设备发 `{type: "action", action, wait}`、`{type: "resize", width, height}`、`{type: "mode", mode}`、`{type: "frame"}`（要一帧当前画面）。action 的坐标同上，字段以 [screen.ts](../kited/src/preview/screen.ts) 为准。
- 逐帧（wait 为真）：做完等画面稳定，把这一帧带 settled 与动作的位置发给所有在看的设备；等的期间收到的逐帧输入丢弃、不排队，免得在没看到的画面上操作。agent 的动作同样把稳定后的一帧发给在看的设备。实时：画面变了就发，设备读得慢时跳过中间的帧。

## 浏览

**状态：** 文件部分已实现；网页部分（本工作区运行中的网页与互联网）2026-10-23 实现，待在 Mac、iPhone、iPad 上手测。定位见 [成果查看与位置](成果查看与位置.md#定位) 与 [运行中的网页](成果查看与位置.md#运行中的网页)。

`kite.files` 实例（界面上叫「浏览」，id 沿用文件插件的）lifetime 为 `closable`，提供一个 files 视图，看所属工作区的文件（目录、原文、渲染预览、历史 diff 与历史版本），也看网页：本工作区运行中终端或预览实例监听的端口，或互联网上的网址。文件经同一 HTTP 操作入口读取；图片、PDF 这类需要整份文件的格式经下面的字节接口读取。各格式怎么呈现见 [成果查看与位置](成果查看与位置.md#文件格式)。

看什么是实例状态里的选择，各设备共用：一个文件（可带 diffId，或带 version 看一个历史版本），或一个网页（`port` 与 `url` 二选一，这时 `path` 为 null）。`port` 须是本工作区运行中终端或预览实例此刻监听的，选的时候核对，服务停了选择保留，同一端口再被监听时接着显示；`url` 只收 http、https，本机地址（localhost、回环地址）的不收，按端口选。网页在设备自己的网页视图里打开，工作机不参与：本工作区的网页经端口转发，路径、前进后退与滚动只在各自的设备上。网页只供界面，没有模型工具；agent 看网页用[预览](#预览)。新建实例的请求可带 `page`（`{port}` 或 `{url}`）直接打开到一个网页，见 [kited · 接口](kited.md)。

| 操作 | 输入（均带 instanceId） | 输出 |
| --- | --- | --- |
| files.list | path 默认 `.`，offset 从 0 开始，limit 默认 200、最多 1000 | path、entries（name / path / kind）、total、nextOffset |
| files.search | query（1 到 200 字），limit 默认 200、最多 1000 | query、entries（name / path / kind）、truncated |
| files.read | path，offset 从 1 开始，limit 默认 200、最多 2000，可选 version | path、text、offset、totalLines、nextOffset、version |
| files.write | path、text、baseVersion（64 位十六进制 sha256），可选 force | path、version |
| files.history | path | versions（commit / at / label / 可选 threadId）、current、truncated |
| files.diff | diffId | id、files（path / before / after） |
| files.state | 无额外参数 | path（可为 null）、可选 diffId 或 version、可选 port 或 url、revision |
| files.select | operationId、expectedRevision、path（null 表示清除或选网页）、可选 diffId 或 version；选网页时带 port 或 url | 保存后的 path、可选 diffId 或 version、可选 port 或 url、revision |

files.diff 的 before / after 为修改前后全文；新增文件的 before 为 null，删除文件的 after 为 null。

历史版本取自[工作区快照](成果查看与位置.md#大文件)：history 沿本工作区的快照链列出这个文件内容变过的那些快照，新的在前，最多 100 个，更早的还有时 truncated 为 true；工作区开始前就在项目里的文件，最早一版是本工作区的第一枚快照，即开始时的内容；commit 是快照的完整提交号，at 是快照时间（毫秒），label、threadId 是触发快照的那一批的标签与线程。文件在某枚快照里被删掉的不列；还没有快照、文件从没变过时 versions 为空。current 是内容与工作区里现在的文件相同的那一版（只比最新一版），不同或文件已不在时为 null。read 带 version 时读那一枚快照里的文件，上限与 413、415 同读现在的文件。不进快照的文件（见下文 `X-Kite-Snapshot`）没有历史版本。

list 按目录优先、名称排序，分页是本次查询的结果，不承诺目录变动中的稳定快照。search 按名字找整个工作区里的文件和目录，不分大小写；工作区是 Git 仓库时跳过 `.git` 和被忽略的路径，不是仓库时逐层查找、跳过 `.git`，只看有限数量的文件。名字与 query 相同的排在最前，其次是以它开头的，再按路径长短；超过 limit 时 truncated 为 true。read 返回最多 2 MiB 文本文件的指定行，version 是完整内容摘要；超过 2 MiB 返回 413，不是文本（含 NUL）返回 415，查看器据此改为按字节查看。服务拒绝工作目录外的路径和越界符号链接；agent 的 read 与 patch 共用同一边界。文件读取（含按版本读）不启动 Thread、不保存对话，也不修改文件或创建 Git 快照；保存见下面的 write。

select 接受工作区内的普通文件，或一个网页；携带 diffId 时，文件须属于该历史差异；携带 version 时，须是本工作区的快照且文件在其中是普通文件，diffId 与 version 不同时带。这两种都不要求当前文件仍存在。选择成功返回规范化的相对路径（或网页）和新 revision，并通知其他设备。同一实例的目录与内容区域共用选择；缩小和重启服务保留选择，关闭时随实例回收。文件被删除时保留所选路径，预览报告读取错误。文件的实际内容由文件系统持有，目录页码与文本页码由客户端管理，刷新读取最新内容；当前没有后台文件监听。

按字节读取不经操作入口，只给 UI：

```text
GET | HEAD /workspaces/:id/files/content?path=<相对路径>[&version=<快照提交号>]
→ 原始字节；ETag 是文件版本（大小、修改时间、inode；带 version 时是快照里的对象号），Content-Type 按扩展名
```

边界与 files.read 相同，只读普通文件；带 version 时读那一枚快照里的文件，校验同 select。带 If-None-Match 且版本未变时返回 304，设备按版本缓存；支持单段 Range（206，超出文件大小时 416），多段时整份返回。超过 10 MiB 且项目 Git 未跟踪的文件带 `X-Kite-Snapshot: skipped`，表示它没进工作区快照、没有历史版本；按 version 读的不带。

write 把工作区内一个已有的文本文件整份改成 text，不新建文件；text 与现在的文件都要能按文本读（上限与 413、415 同 read），现在的文件还须是合法的 UTF-8，GBK、Latin-1 等其他编码的返回 415、不写，免得按 UTF-8 写回改坏原有内容。version 是 read 给的那种完整内容摘要（UTF-8 内容的 sha256），baseVersion 是编辑开始时的 version：文件现在的内容已经和它不同（agent 或另一台设备改过），又没带 force 时返回 409，不写；force 为 true 时照样覆盖。文件已经是 text 时直接返回成功，不写也不打快照，网络重试因此不会重复执行。写成了在工作区打一枚快照（标签「编辑 <文件名>」，不归属线程），时间线里多一版，目录与工作区事件流推 `workspace.snapshot`。原地改写，保留文件权限。

这些文件操作声明给 UI 与获准插件调用，不额外生成模型工具。模型继续使用现有 read / patch / shell，两者遵守相同的工作区访问边界。App 在浏览里编辑文本文件经 write；符号链接仅列出，不提供目录访问。引用与历史差异见 [资源引用](资源引用.md)。
