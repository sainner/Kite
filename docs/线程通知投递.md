# 线程通知投递

本文规定线程如何得知配置与环境变化：普通通知在自然请求边界追加到历史，保留已发送内容，不独立唤醒线程。当前已接 agent 配置、执行授权、插件工具授权，以及请求边界发现的基础上下文变化；四类正文模板均可在资源库「代理上下文」的事件通知中编辑。普通文件监听、关注范围合并和自动触发尚未接入。

## Claude 的交接边界

自研 harness 在自己的模型请求边界纳入输入与通知；Claude 由 SDK 的实际输入纳入事件确认交接。运行中输入可以进入 SDK 队列，不能把写入输入流当作已被模型请求纳入。首次系统提示固定，后续基础上下文与通知在下一次自然模型请求前追加，不取消在途请求或独立唤醒会话。历史保留实际投递正文，App 仍显示用户原始输入。

Claude 配置只在空闲且没有恢复阻塞时修改；模型、思考强度、请求预算或工具集合变化后，在下一回合开始前重启进程使其生效，撤权在执行前再次核验。共享工具遵守 Kite 的授权和收据契约。异常退出需人工核查；确认交接不等于模型服务成功回答。当前接入范围见 [工作机说明](kited.md#claude-会话的上下文)。

## 保存与生效

`GET /instances/:id/agent-capabilities` 提供按厂商分组的模型、各模型支持的思考档位、这个代理可开的工具与角色必需的工具，以及配置和新增工具的生效边界；读取不会请求模型。`GET /instances/:id/agent-config` 返回实例绑定配置及 `revision`；`PUT` 接收 `{expectedRevision, agent}` 完整替换配置，版本冲突返回 409。修改只针对该实例，工具不能超出创建时角色的规则；修改角色或重启不能覆盖已经绑定的配置。

配置与对应通知共同保存，但提交不启动模型或消费队列。当前请求使用已固定的模型、工具、设置和材料，之后的新修改留给下一次自然交接。执行授权另有停止与恢复确认前置条件，见 [实例执行授权](实例操作.md#实例执行授权)。

通知一旦纳入请求，就保留在该次历史中；失败或停止不会把它重新排队。重启沿已保存的交接位置继续，不能丢失未交接的通知，也不能改写已经交接的内容。

这里“纳入”仅表示宿主把内容固定到一次请求，不保证模型服务接收、理解或成功回答。网络失败沿用回合失败与显式恢复语义。

## 保留已发送的前缀

首次请求的基础指令固定。后续上下文有变化时，继续使用相同的顶部指令，并在历史末尾追加独立的更新条目，明确新内容替代之前的基础上下文。已发送的消息、工具调用、结果和通知保留原顺序，恢复使用当时保存的内容。

实际使用的项目规则、日期等材料在自然请求边界取值；有效正文变化时追加上下文更新，正文相同不重复告知。配置通知说明设置变化，上下文通知保留实际的新正文，两者各有来源。

自研 harness 的工具声明在首个请求固定，之后只能改变已登记工具的可调用范围。新声明或已有 schema、描述变化需新建会话；已发出的请求也不能绕过最新授权。模型及推理强度变化可影响提供方缓存；固定前缀不保证实际缓存命中率。

依据是上游的 [工具选择](https://developers.openai.com/api/docs/guides/function-calling#tool-choice) 与 [前缀缓存](https://developers.openai.com/api/docs/guides/prompt-caching) 约定。2026-09-29 曾通过 ChatGPT 订阅入口验证固定工具列表配合 `allowed_tools` 的最小请求；该实验未测量缓存命中率，不作当前性能保证。

## 公共通知边界

通知须能追溯来源、权限层次和实际正文。配置、执行授权与插件工具授权通知使用提交时的模板和实际值；基础上下文通知使用发现变化时的内容。编辑模板不会重写已生成的待投递通知，也不会生成业务事件或改变权限。

历史可还原通知的段落、分支选择、变量与来源，重启不重新读取最新材料。模板契约见 [上下文模板](harness-上下文组装.md#通知正文)。

- 指令性通知仅来自用户授权的配置或指令材料；外部文件和插件数据只能提供观察事实，不能自行升级为指令。
- 当前只有内部宿主入口，尚未开放任意插件提交通知的 HTTP 接口。后续插件入口需要校验来源、目标及授权。
- 普通事件到达不启动执行；主动启动工作的触发器单独实现。
- 当前配置通知保留提交顺序。文件变化通知的关注与合并规则尚未接入。

界面已显示变更不代表模型已经获知。客户端重连不能造成通知重复或丢失；模型通知的恢复与界面订阅相互独立。
