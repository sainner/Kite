# 线程通知投递

配置修改、文件变化和插件状态变化共用“来源保存事实 → 按归属提供通知 → 自然请求边界纳入 → 追加历史”的路径。当前已接 agent 配置、执行授权、插件工具授权，以及请求边界发现的基础上下文变化；四类正文模板均可在设置中编辑。普通文件监听、关注范围合并和自动触发尚未接入。

## Claude 的交接边界

自研 harness 在自己的模型请求边界纳入输入与通知；Claude 由 SDK 的实际输入纳入事件确认交接。运行中输入可以进入 SDK 队列，不能把写入输入流当作已被模型请求纳入。首次系统提示固定，后续基础上下文与通知通过原生请求前回调追加：用户输入纳入和工具批次结束时检查更新，不取消正在运行的请求、不独立唤醒会话。历史保留实际投递正文，App 仍显示用户原始输入。

Claude 配置只在空闲且没有恢复阻塞时修改，工具集合在下一次启动或恢复进程时重建，撤权在执行前再次核验。共享工具遵守 Kite 的授权和收据契约，不模拟 harness 的内部请求事件，也不根据通知自行唤醒 Claude。异常退出需人工核查；确认交接不等于模型服务成功回答。当前接入范围见 [工作机说明](kited.md#claude-会话的上下文)。

## 保存与生效

`GET /instances/:id/agent-capabilities` 提供模型、各模型支持的思考档位、可选工具，以及配置和新增工具的生效边界；读取不会请求模型。`GET /instances/:id/agent-config` 返回实例绑定配置及 `revision`；`PUT` 接收 `{expectedRevision, agent}` 完整替换配置，版本冲突返回 409。修改只针对该实例，更新默认模板或重启不能覆盖已经绑定的配置。

配置与对应通知共同保存，但提交不启动模型或消费队列。当前请求使用已固定的模型、工具、设置和材料，之后的新修改留给下一次自然交接。执行授权另有停止与恢复确认前置条件，见 [实例执行授权](实例操作.md#实例执行授权)。

通知一旦纳入请求，就保留在该次历史中；失败或停止不会把它重新排队。重启沿已保存的交接位置继续，不能丢失未交接的通知，也不能改写已经交接的内容。

这里“纳入”仅表示宿主把内容固定到一次请求，不保证模型服务接收、理解或成功回答。网络失败沿用回合失败与显式恢复语义。

## 保留已发送的前缀

首次请求的 `instructions` 固定为基础上下文。后续上下文有变化时，继续使用相同的顶部指令，并在历史末尾追加独立的更新条目，明确新内容替代之前的基础上下文。已发送的消息、工具调用、结果和通知保留原顺序，恢复时使用 journal 中保存的内容。

实际使用的项目规则、日期等材料在自然请求边界取值；有效正文变化时追加上下文更新，正文相同不重复告知。配置通知说明设置变化，上下文通知保留实际的新正文，两者各有来源。

自研 harness 的工具声明在首个请求固定，之后只能改变已登记工具的可调用范围。新声明或已有 schema、描述变化需新建会话；传输端的工具选择限制和宿主执行前授权检查共同生效。模型及推理强度变化可影响提供方缓存；固定前缀不保证实际缓存命中率。

工具选择格式来自 [OpenAI 官方工具调用文档](https://developers.openai.com/api/docs/guides/function-calling#tool-choice)，缓存原则见 [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)。2026-09-29 已通过当前 ChatGPT 订阅入口验证固定工具列表配合 `allowed_tools` 的最小请求；没有用该次验证推断缓存命中率。

## 公共通知边界

通知保留身份、来源、类型、权限层次和当次正文快照。配置、执行授权与插件工具授权在业务提交时固定模板和实际值；基础上下文更新在发现变化时固定。编辑模板不会重写已生成的待投递通知，也不会生成业务事件或改变权限。

历史可还原通知的段落、分支选择、变量与来源，重启不重新读取最新材料。模板契约见 [上下文模板](harness-上下文组装.md#通知正文)。

- `instruction` 仅由宿主根据用户授权的配置或指令材料生成，映射为 developer 消息。
- `observation` 表达环境事实，映射为普通上下文消息；来源及事实提示由场景定义展开，适配器原样传输正文。外部文件或插件数据不能自行选择指令权限。
- 当前只有内部宿主入口，尚未开放任意插件提交通知的 HTTP 接口。后续插件入口需要校验来源、目标及授权。
- 普通事件到达不启动执行；主动启动工作的触发器单独实现。
- 来源可以在投递前筛选、合并尚未纳入的状态更新；已经纳入的通知不改写。当前配置通知按提交顺序保留，文件的关注、版本复核和合并策略后续接入。

App 的 SSE 继续负责界面刷新。其进程内游标不作为模型投递凭据；模型投递根据各线程持久保存的交接记录恢复。
