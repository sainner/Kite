# Monitor

本文适用于 kited、harness 与 Claude 线程、App，规定 monitor：工作区里常驻观察事件、记录时间线并唤醒代理的插件实例。Line 的收件箱是其中一个实例，它的路由规则见 [Line 与工作区流转](Line与工作区流转.md#monitor-的事件路由)；操作入口见 [实例操作](实例操作.md#monitor)。

**状态：已实现（kited 与 App 的 monitor 窗口、收件箱）；App 部分尚未经真机验收。**

## 定位

- monitor 是 Kite 主动启动工作的通用入口。普通通知仍不唤醒线程，见 [线程通知投递](线程通知投递.md)；只有 monitor 投递的输入会让空闲的代理开始回合。
- monitor 自己不运行模型：它观察来源、记录事件、决定唤醒，唤醒后的回合是对象代理的普通回合。
- 所有 monitor 是同一种插件实例（内置定义 `kite.monitor`），共用一个时间线视图。代理自己开的来源单一；Line 的由宿主建，来源与规则最复杂，它的视图就是收件箱。
- 只有 Line 的 monitor 找用户（系统通知）。代理开的只唤醒开它的代理；代理需要用户时用提问或审批，Line 的 monitor 会看到。

## 对象与生命周期

- 代理用 `monitor_start` 开 monitor。实例放在代理所在的工作区，来源（`origin`）与对象都是这个代理；默认在后台，没有窗口，用户可以打开它的时间线窗口。界面不能直接新建 monitor。
- 每个代理同时最多开 10 个。代理用 `monitor_stop` 或用户归档就停掉它，时间线保留；对象代理归档时，它的 monitor 随之归档。来源都结束后不再有事件，实例保留到被停掉。
- monitor 是常驻的：工作区交接、冻结或归档时停下来源进程，不算结束；工作区回到打开（包括流转后在目标机打开）或工作机重启后重新开始，时间线上记一条，期间的事件可能重复或遗漏。时间线随工作区的恢复材料流转。

## 来源

| 来源 | 事件 | 结束 |
|---|---|---|
| 命令 | 标准输出的每一行；同一来源 200 毫秒内的几行合成一个 | 命令退出，退出码记为结束事件 |
| 定时 | 到点；可按天或按周重复 | 不重复的触发一次后结束 |
| 账号（只供 Line） | 各工作机的会话状态与关注设备 | 随 Line |

命令的写法沿用 Claude Code 的 Monitor 工具：只输出会据此行动的行，成功和失败的信号都要覆盖，等一件事完成就让命令在那时退出。文件监听与 WebSocket 来源待定。

## 唤醒与刹车

- 事件在 1 秒内合成一条 Kite 来源的输入投给对象代理，正文用 `monitor.events` 模板；代理空闲时开始回合，运行中在下一次请求纳入。先落盘再投递，失败用同一输入 ID 补送。
- 每个 monitor 每天最多唤醒对象代理 40 次，超了只记时间线。
- 同一来源一分钟里超过 60 个事件就停掉这个来源，记为结束并告诉代理。
- 时间线保留最近 500 条。

## 执行边界

- 命令在对象代理的操作系统沙箱里、按它此刻的执行授权运行；环境只有约定变量，不能使用密钥。
- monitor 的命令不挂在任何工具调用上，越界时没有可以等的人：网络与文件越界一律按白名单拒绝，不问人，也不受审批模式影响。
- 完整输出写日志，只有标准输出的行成为事件。
