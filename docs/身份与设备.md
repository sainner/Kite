# 身份与设备

适用于 Kite App 的首次配置、设备入网、远程授权与撤销。身份与组网交给 Tailscale，Kite 不运营账号服务；模型登录仍由各工作机自行完成。整体分工见 [分布式架构](分布式架构.md)。

## 身份

登录 Tailscale 即登录 Kite，没有单独的 Kite 账号与密码。同一 Tailscale 用户名下加入 tailnet 的设备，就是这个用户的 Kite 设备；共享 tailnet 里其他用户的设备、从别的 tailnet 分享进来的设备都不算。

首次配置时，Mac 先选择本机执行（安装 kited）或仅远程控制，iPhone 和 iPad 作为控制端；然后登录 Tailscale。本机执行的 Mac 由 kited 的组网节点（kite-net）取得登录地址，其余设备由 App 内的 TailscaleKit 节点取得。App 在应用内的网页登录页里打开地址，设备上线后自动关闭；没有 Tailscale 账号时在登录页里注册。首次登录可能遇到上游的错误页，用户关掉登录页后可以重试，见 [官方组网实测](research/2026-10-15-官方组网实测.md)。

登录状态保存在各自的节点目录：kited 在数据目录的 `tailnet/node`，App 在应用支持目录，重新上线不用再登录。节点要求重新登录（例如节点密钥过期）时，账号页提示并可就地重新登录。退出登录注销这台设备的节点并删除节点状态，下次要重新登录，其他设备不受影响。

## 设备

设备列表来自组网：同一用户、不带标签的节点。读得到 `/machine` 的是工作机，其余是控制端。Mac 本机执行模式由 kited 维护一个持久网络节点，App 复用它访问其他工作机；控制模式由 App 维护节点。同一台 Mac 不因同时运行 App 和 kited 重复入网。

撤销设备在 Tailscale 管理后台把它移出 tailnet；App 不删除设备，只给出管理后台的入口。

## 授权边界

工作机入口由 kite-net 通过 tsnet 的 WhoIs 核验：来源与本节点属于同一 Tailscale 用户、不带标签、节点密钥未过期，不接受客户端自报的身份。kite-net 覆盖内部认证字段并把来源的组网 IP 交给 kited，kited 的远程监听只接受本次进程生成的随机内部凭据；应用层的 `X-Kite-Machine` 防止地址复用时操作错机器。只给工作机用的接口（账号级数据的同步、工作区副本、检出的拉取、交接的完成通知）还按来源 IP 核对它是目录里的一台工作机，见 [工作机](kited.md#远程连接)。

节点被移出 tailnet 或密钥过期后，WhoIs 不再通过，已有的远程请求随状态变化关闭，新请求不再放行；网络通路消失时，远端关闭不保证立即传到客户端。

信任边界：Tailscale 的协调服务有能力往 tailnet 里加节点。需要更强的保证时开启 Tailnet Lock，是否默认开启待评估。

App 把这台设备的身份设置（用途、登录的用户、本机节点 ID）存在本机，退出登录时清空，同时清空工作机连接与目录缓存。会话正文、插件实例的配置与数据、模型登录与账号级数据都留在工作机。

## 目录与工作机的职责

每台 kited 负责本机项目、检出与工作区的完整目录快照。摘要包含稳定 ID、名称、机器与目录归属、路径、分支、状态与 `epoch`，不包含会话、窗口、插件配置和文件内容。App 合并目录时以项目 ID 关联，不能按同名目录推断为同一项目；同一工作区 ID 出现在几台工作机上时，未冻结且 `epoch` 最高的是当前宿主，见 [工作区的稳定身份与执行权](Line与工作区流转.md#工作区的稳定身份与执行权)。

摘要随账号级数据在工作机之间同步，见 [远程连接](kited.md#远程连接)。App 按 Tailscale 用户在本机保存导航缓存，先显示缓存，再从任一台连着的工作机读目录，按组网地址对上设备，并独立订阅各机目录事件。实时窗口、会话和操作直接访问所属 kited。工作机断开只影响它自己的内容；离线缓存不授予新的网络权限，也不保证过期连接继续可用。目录过时与设备离线不等同于目录删除；仅目录摘要不能用来删除设备上已保存的窗口布局，必须等工作机返回完整窗口集合。

## 运维与验证入口

Tailscale 账号与 tailnet 由用户自己在 Tailscale 管理后台管理。网络授权与 App 目录的验证脚本见 [手动验证入口](../kited/test/manual/README.md)，测试结果不能代替其他设备与网络组合的验收。

原生 iPhone 的首次登录（应用内网页登录）、前后台切换与蜂窝网络仍缺少真机验收。
