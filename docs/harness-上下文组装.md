# 上下文模板与生效规则

本文适用于角色提示词、事件通知、上下文压缩与辅助生成的模板。上下文编排允许用户查看、编辑和保存内容，界面和实际请求使用同一份结构化定义；模板、材料和历史分别保存。

模板覆盖角色提示词（创建会话场景）、标题生成、工作区名称、上下文压缩、点阵签名和五类通知。文件变化通知只由上下文压缩生成，不收集普通文件事件；压缩时机与 token 估算由执行宿主管理，见 [上下文压缩](harness-主循环.md#上下文压缩)。

## 模板归属与生效

角色与模板保存在资源库，资源库是账号级数据，在工作机之间同步，各工作机使用同一份内容，见 [账号级数据](kited.md#账号级数据)。内置的只保存用户改过的，没改过的跟随 kited 版本的默认；改回与默认一样或恢复默认时从资源库删掉，不留等于默认的副本，kited 升级换了默认后跟着换。资源库的「代理上下文」把角色与模板放在一起，按进入代理上下文的方式分四类：角色是新建代理时的初始上下文与配置；事件通知是插进会话的通知正文；上下文压缩由代理用自己的模型和上下文写摘要，替换一段历史；辅助生成即会话标题、工作区名称、点阵签名、语音识别与提交 PR 时的标题和说明，由辅助模型另外生成，结果不进入代理上下文。工具只属于角色；辅助生成的模板另带模型与思考强度，只能选工作机 ChatGPT 订阅里的型号；语音识别模板改带识别模型，没有思考强度，模板展开的文字作为识别的背景文本，见 [语音识别](kited.md#语音识别)。

| 场景 | 生效规则 |
|---|---|
| 创建会话 | 提示词属于角色，随角色保存；新建代理时拷贝进实例，角色的后续修改不改变已有代理 |
| 会话标题、工作区名称、点阵签名 | 每个场景共用一份模板，生成规则、材料、模型与思考强度共同保存；每次生成读取最新内容 |
| 上下文压缩 | 共用一份模板；每次压缩读取最新内容，生成的摘要与包装随压缩结果固定 |
| 五类通知 | 各场景共用对应模板；新通知保存生成时的内容，不重写已生成通知 |

已有代理显式修改基础上下文时，在后端允许的交接边界追加更新，保留原有历史前缀。角色选择及其对配置与授权的影响统一见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。

`GET /context-templates` 返回后台场景的模板（`definition`，辅助生成另有 `model: {model, reasoning}`）、`revision` 与默认内容的 `defaultRevision`（二者不同即改过），以及场景目录；场景带可引用的变量（显示名称、说明与分组 `group`：场景材料或公共变量所在的层；公共变量另带层的标识 `layer`）与所属分类 `kind`（`notification`、`compaction`、`generation`），辅助生成的场景另带可选的模型目录与调用凭据的说明（`models`）。`PUT /context-templates/:id` 携带 `expectedRevision`、`definition` 与辅助生成的 `model` 更新，不能改变场景或名称，也不新建模板；`POST /context-templates/:id/reset` 携带 `expectedRevision` 恢复默认，等同于保存默认内容。冲突返回 409，编辑器保留草稿。标题及通知不提供脱离实际调用的无效副本。角色经 `/roles` 读写，接口见 [工作机](kited.md#接口)。公共变量按所在的层选取值对象：`GET /context-variables/:name` 按工作机，`/workspaces/:id/…` 按工作区（项目层也按工作区取），`/instances/:id/…` 按代理；范围取不到变量所在的层时返回 400，场景材料返回 404。返回 `{name, text}`，项目规则与记忆索引另带 `files: [{path, content, sha256}]`（由外到内），一份都没有时带新建的位置 `create`。`PUT /workspaces/:id/context-variables/:name/file` 以 `{path, content, expectedSha256}` 把其中一份写回这个工作区的工作树，新建时 `expectedSha256` 为 `null`，越出查找位置返回 400，摘要对不上返回 409。

首消息创建请求可携带 `role: {id, revision}`；已创建的空代理可通过 `PUT /instances/:id/role` 携带实例配置 revision、角色 ID 和角色 revision 改选。两条路径均须在发出第一条消息前完成，对话开始后改选会被拒绝。未选择时使用默认角色「工作」。

## 场景与变量

变量分两类。公共变量描述代理所处的环境、项目、工作区和实例，在所有场景中含义与格式一致，用户据此自由组装上下文；场景专有变量是某种用途才有的材料，只在该场景可用。场景声明自己开放哪几层公共变量和哪些专有变量；它不是调度器，新增场景不意味着已有事件来源，也不自动触发模型。

### 公共变量

公共变量只收变化不频繁的状态。基础上下文在每次请求边界重新组装，正文一变就追加一整份基础上下文更新；未提交改动、diff、检查结果、快照和排队输入这类随工具批次变化的状态不做公共变量，由工具按需读取。每个变量的说明写明内容、何时为空和何时变化，编辑器据此提示。

| 层 | 变量 | 内容与变化 |
|---|---|---|
| 环境 | `environment.date` | 取值时的 UTC 日期，每天变化 |
| | `machine.name` | 工作机名称；工作区流转到别的机器后变化 |
| 项目 | `project.name`、`project.remote` | 项目名称与归一化的远程地址；仓库迁移后远程地址变化 |
| | `project.rules` | 从仓库根目录到工作目录逐级找到的 `AGENTS.md`，由外到内；一个都没有时为空，文件修改后变化 |
| | `project.memory` | 同一范围内的 `.kite/memory/MEMORY.md`，取法同上 |
| | `project.skills` | 可用 skill 的清单，系统、用户、机器、项目四层合成：系统层随 kited 提供，用户层在资源库，机器层是工作机上的 `~/.agents/skills` 与 `~/.claude/skills`，项目层是同一范围内的 `.agents/skills/` 与 `.claude/skills/`；每条一行，名字接一句说明，说明截到 1536 字符，同名里层盖外层；一个都没有时为空，skill 文件增删改后变化。名字与说明照 Claude Code 的读法取自 SKILL.md 的 YAML 头：严格解析失败时给带特殊字符的值加引号再解析一次，仍失败只列文件夹名 |
| 工作区 | `environment.cwd` | 工作目录的真实路径；流转到别的机器后可能变化 |
| | `workspace.name` | 工作区名称 |
| | `workspace.branch` | 工作区的当前分支；分离 HEAD 时为空 |
| 代理实例 | `agent.title` | 会话标题，纯文本；生成新标题或改名后变化 |
| | `agent.role` | 创建代理时所选角色的名称，随实例保存，之后修改角色不影响 |
| | `agent.model`、`agent.reasoning`、`agent.tools` | 实例配置；工具用顿号分隔，一个都没有时是「无」 |
| | `execution.grants` | 当前执行授权，JSON |
| | `plugin.tools` | 已授权的插件工具及目标实例，JSON；全部撤回时是 `[]` |

规则是指令，记忆索引是背景，两者分开提供，角色各自决定标题、引导语和位置；例如 Line 的记忆索引是关于用户的记忆，普通代理的是项目里积累的决定。工作树边界写在默认角色的提示词里，宿主不在工作树里另外追加段落。规则的来源分层见 [产品架构](产品架构.md#两层协议与上下文)：角色提示词就是用户层，项目层经 `project.rules` 进入模板，机器层有内容时再加变量。

skill 清单只给名字和说明，正文由模型用 `skill` 工具按名字加载（契约见 [主循环](harness-主循环.md#skill)），skill 自带的文件用 `read` 读、脚本用 shell 跑。系统层的 skill 随 kited 的运行目录提供，用户层的同步后落在工作机数据目录的 `skills/` 下，机器层在用户主目录，项目层可能在工作目录以上的仓库根目录里。这些位置对代理放行只读，按来源区分可信程度：系统、用户、机器三层是宿主给的位置，根目录整个放行；项目层随仓库走，工作目录以上的根目录只在真实路径仍在仓库以内时放行，仓库里指向 / 或主目录的软链接放不开整片目录；软链接到别处的单个 skill 文件夹另行放行。清单、skill 工具、`read` 认的 skill 文件夹和沙箱放行用同一份清单，宿主在每次请求前重扫，请求之间增删改的 skill 下一次请求生效。随 kited 发布的 skill 正文要自足，引用的文件都放在自己的文件夹里：安装版的运行目录只带 skill 文件夹，仓库里的 docs、AGENTS.md 不随 kited 发布。Claude 后端用同一份清单和同一个工具，Claude 自己的 skill 发现与 Skill 工具保持关闭。用户在输入框里以 `/名字` 开头发消息时，宿主按收下那一刻的 SKILL.md 固定正文，跟在这条输入后面交给模型，输入框按这个工作区的清单列候选；压缩后已加载的 skill 正文重附，见 [上下文压缩](harness-主循环.md#上下文压缩)。

公共变量在组装时取值，只取模板实际引用的：基础上下文在请求边界取值，通知在生成时取值并随通知固定，压缩与辅助生成在生成时取值。角色提示词引用实例配置后，修改配置会同时产生配置通知和基础上下文更新，这是自由组装的代价，由编辑器提示。

### 场景

| 场景 | 公共变量 | 专有变量 | 用途 |
|---|---|---|---|
| `thread.create` | 全部 | 无 | 角色提示词，即代理的基础上下文 |
| `thread.title` | 全部 | `title.current`、`title.messages` | 带引号的当前标题与近期对话，均为 JSON |
| `thread.voice` | 环境 | `voice.messages` | 近期对话，作为语音识别的背景文本 |
| `thread.compact` | 全部 | `compaction.range`、`compaction.summary` | 压缩指令与摘要在历史中的包装 |
| `thread.file_changes` | 全部 | `files.changes`、`files.origin` | 文件变化与来源；目前由上下文压缩生成 |
| `thread.configuration_changed` | 全部 | `agent.revision` | 实例配置变化 |
| `thread.context_updated` | 全部 | `context.instructions` | 更新后的基础正文 |
| `thread.execution_permissions_changed` | 全部 | `execution.revision` | 执行授权变化 |
| `thread.plugin_tools_changed` | 全部 | 无 | 插件工具授权变化 |
| `line.monitor` | 全部 | `monitor.delegated`、`monitor.results`、`monitor.briefing` | 唤醒 Line：交给它的事项、它发起的工作的结果与回来时的简报 |
| `monitor.events` | 全部 | `monitor.title`、`monitor.id`、`monitor.events` | 代理开的 monitor 投来的新事件 |
| `agent.report` | 全部 | `report.title`、`report.id`、`report.result`、`report.reply` | 交代给子代理的回合结束了：子代理的标题与实例 ID、结果、最后回复的末尾 |
| `agent.workspace` | 全部 | `child.workspace`、`child.id`、`child.result` | 用 isolation 开出的子工作区有了结果：合回或没能合回、没准备好 |
| `template.emblem` | 环境 | `template.title`、`template.content` | 按角色名称与提示词设计点阵签名 |
| `workspace.pull_request` | 环境、项目、工作区 | `pull_request.commits`、`pull_request.files` | 提交 PR 时按工作区相对远程主线的提交说明与改动文件起草标题和说明 |
| `workspace.commit` | 环境、项目、工作区 | `commit.recent`、`commit.files`、`commit.diff` | 集成时按这次要提交的改动与最近的提交说明起草提交说明 |
| `workspace.naming` | 环境、项目、工作区 | `naming.current`、`naming.agents` | 有几个用户开的代理时按它们的标题起工作区名称；当前名称与各标题均为 JSON |

- 同一变量在所有场景格式一致。作为待处理数据、须用特定格式的材料（标题场景的当前标题与对话、语音识别的近期对话）是场景专有，名称按场景区分。
- revision 是内容摘要，只在对应变更通知里有意义，留在该场景；`template.*` 描述正在设计签名的角色，不是当前代理。
- 场景取不到某一层时不开放该层，不以空值代替：语音识别可能还没有线程，点阵签名面向资源库里的角色，二者只开放环境层。
- 模板只能引用场景公布的变量，不能自行增加变量。变量的保存期限由业务确定；文件或插件的观察材料不能自行取得指令权限。

## 定义与变量

HTTP 模板定义使用 `version: 2`，包含标识、名称、场景和有序内容块。标题、工作区名称、压缩、点阵签名、PR 与提交说明场景另有 `input` 区域，与 `blocks` 共享版本和一次保存，其他场景不能有：标题的 `blocks` 用作命名指令，`input` 用作对话材料；工作区名称的 `blocks` 用作命名指令，`input` 用作当前名称与各代理的标题；压缩的 `blocks` 用作摘要指令，`input` 用作摘要在历史中的包装；点阵签名的 `blocks` 用作设计规则，`input` 用作角色材料；PR 与提交说明的 `blocks` 用作起草规则，`input` 用作改动材料。标题模板不能用作角色提示词。

| 结构 | 含义 |
|---|---|
| `paragraph` | 稳定 ID、标题和由文字、变量组成的 `parts` |
| `condition` | 检查一个变量，精确匹配 `cases`，否则采用 `otherwise` |

例如，一个可编辑的运行环境段落：

```json
{
  "type": "paragraph", "id": "environment", "title": "运行环境",
  "parts": [
    {"type": "text", "text": "当前工作目录："},
    {"type": "variable", "name": "environment.cwd"},
    {"type": "text", "text": "。日期："},
    {"type": "variable", "name": "environment.date"}
  ]
}
```

条件可以嵌套，空分支不产生正文；不执行 JavaScript 或表达式。变量为具名引用，普通文字里的 `${...}` 不作为模板解释，变量内容也不二次解析。

段落和分支 ID 在定义内唯一，匹配值不得重复。所有分支的引用名称必须有效，但只要求实际选中路径具备材料；隐藏分支缺少运行材料不阻止当前路径。未知变量、无效定义或缺少必需绑定明确报错，不静默遗漏。

段内文字直接连接，非空段落之间以两个换行分隔。标题、标识及未选中分支不进入模型正文。历史内容不随模板格式变化而改写。

## 预览与历史

编辑不改变条件求值规则，实际展开由当次变量决定。编辑器展示模板文字与变量说明，可以查看单个公共变量现在的取值，取值对象随变量所在的层：环境层选工作机，项目层与工作区层选工作区，代理层选代理。不提供按真实变量展开的整段正文预览；场景材料只在生成时才有，不能这样查看。

项目规则与记忆索引在编辑器里显示从工作区根目录逐级找到的各份文件，可以直接修改并写回，只能写这个变量逐级查找的位置；文件在读取后被别处改过时拒绝写入。取值与写回都对着所选的工作区：写进它的工作树，随这个工作区集成进主线，其他工作区的副本随各自的分支变化；这个工作区里的代理下一次请求组装时生效。其他变量只读。

请求发出后修改模板或材料，不改变在途请求及历史。历史展示当时的内容与来源，不受当前文件、插件状态、模板或变量目录增删的影响；有效正文相同不重复发送。

历史须能还原当次上下文与执行设置，但不包含凭据。可编辑模板不能篡改用户原文、模型原生记录或工具结果。

## 基础上下文的生效

首次基础指令固定，后续有效正文变化在自然请求边界追加，保留已经发送的历史。组装失败不消费待处理输入、不调用模型。harness 与 Claude 的交接差异、配置和工具变更统一见 [线程通知投递](线程通知投递.md)。模板可编辑不表示任意执行阶段都可改变配置。

项目规则与记忆索引分别来自工作目录到最近仓库根目录之间适用的 `AGENTS.md` 与 `.kite/memory/MEMORY.md`；无仓库时沿父目录查找，按由外到内的顺序提供。子目录规则与记忆正文按需读取。项目层的 skill 在同一范围内的 `.agents/skills/` 与 `.claude/skills/` 下查找，一个文件夹经软链接重复到达只算一次。

独立终端沿用自身入口定义，只提供日期、工作目录、分支、规则与记忆索引，工作区类型按直接在文件夹里工作算；App 编辑的资源库模板按账号同步，但不会自动改写独立终端配置。

## 通知正文

五类通知与角色提示词使用同一种段落编辑器。保存模板只影响此后生成的通知，不能重写已生成或已投递内容，不生成业务事件、不唤醒模型，也不改变权限。基础正文不变时，仅编辑通知模板不会额外追加更新。

通知何时固定正文、何时纳入请求，以及重启和失败后的处理，统一见 [线程通知投递](线程通知投递.md)。
