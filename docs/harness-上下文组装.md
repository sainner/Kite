# 上下文模板与生效规则

上下文编排为用户提供可见、可编辑、可保存的入口。段落可编辑，动态变量显示为 chip，条件分支显示为页签；界面和实际请求使用同一份结构化定义。本文规定模板、材料与历史的关系，不解释组装函数的实现。

当前已接创建会话、标题生成和四类通知模板。文件变化场景只定义了契约，事件收集与投递尚未接入；自动压缩与 token 预算也不由模板系统提供。

## 模板编辑与使用入口

模板目录属于工作机，Mac 与 iPhone 读取同一份保存内容，重启不覆盖用户编辑。

| 场景 | 使用与编辑规则 |
|---|---|
| 创建会话 | 设置中管理；空会话发送前可选择，也可复制、修改并保存新模板；已有实例绑定当时选中的内容 |
| 会话标题 | 设置中一份固定模板，命名规则与材料分区编辑、一起保存；每次生成读取最新内容 |
| 四类通知 | 设置中编辑对应固定模板；新通知保存生成时的内容，不重写已生成通知 |

修改创建模板不自动改已有实例。已有会话显式修改基础上下文时，在后端允许的交接边界追加更新，保留原有历史前缀。选择模板只改变上下文，保留模型、工具、预算与授权；保存期间禁止发送。

`GET /context-templates` 返回模板、revision 和场景变量目录；`POST /context-templates` 新建创建会话模板；`PUT /context-templates/:id` 携带 `expectedRevision` 更新，不能改变场景。冲突返回 409，编辑器保留草稿。标题及通知不提供脱离实际调用的无效副本。

首消息创建请求可携带 `contextTemplate: {id, revision}`；已创建的空会话可通过 `PUT /instances/:id/context-template` 携带实例配置 revision、模板 ID 和模板 revision 绑定。两条路径均须在首个模型请求前完成。未选择时使用对应 agent 的默认模板。

## 场景契约

场景规定模板适用的用途和可引用变量；它不是调度器。新增场景不意味着已有事件来源，也不自动触发模型。

| 场景 | 可用变量 | 用途 |
|---|---|---|
| `thread.create` | `environment.cwd`、`environment.date`、`project.documents` | 基础上下文 |
| `thread.title` | `thread.title`、`thread.messages` | 当前标题与近期对话材料 |
| `thread.file_changes` | `files.changes`、`files.origin` | 文件变化与来源；尚未接投递 |
| `thread.configuration_changed` | `agent.revision`、`agent.model`、`agent.reasoning`、`agent.tools`、`agent.max_requests_per_turn` | 实例配置变化 |
| `thread.context_updated` | `context.instructions` | 更新后的基础正文 |
| `thread.execution_permissions_changed` | `execution.revision`、`execution.grants` | 执行授权变化 |
| `thread.plugin_tools_changed` | `plugin.tools` | 已授权插件工具及目标 |

前后端使用工作机提供的场景目录，不分别维护可选变量。定义不能自行扩展场景变量。变量的取值、来源、使用时机和保存期限由业务确定；文件或插件的观察材料不能自行取得指令权限。

## 定义与变量

当前定义格式为 `version: 2`，包含标识、名称、场景和有序内容块。标题场景另有 `input` 材料区域：`blocks` 用作命名指令，`input` 用作对话材料，两者共享版本和一次保存。标题模板不能绑定为创建会话模板。

| 结构 | 含义 |
|---|---|
| `paragraph` | 稳定 ID、标题和由文字、变量组成的 `parts` |
| `condition` | 检查一个变量，精确匹配 `cases`，否则采用 `otherwise` |
| `ContextBinding` | 变量文本及可选的来源路径、摘要 |
| 快照 | 当次完整定义、材料与来源，包括未选中的分支 |

例如，一个可编辑的运行环境段落：

```json
{
  "type": "paragraph", "id": "environment", "title": "运行环境",
  "parts": [
    {"type": "text", "text": "当前工作目录："},
    {"type": "variable", "name": "environment.cwd"},
    {"type": "text", "text": "。日期："},
    {"type": "variable", "name": "environment.date"}
  ]
}
```

条件可以嵌套，空分支不产生正文；不执行 JavaScript 或表达式。变量为具名引用，普通文字里的 `${...}` 不作为模板解释，变量内容也不二次解析。

段落和分支 ID 在定义内唯一，匹配值不得重复。所有分支的引用名称必须有效，但只要求实际选中路径具备材料；隐藏分支缺少运行材料不阻止当前路径。未知变量、无效定义或缺少必需绑定明确报错，不静默遗漏。

段内文字直接连接，非空段落之间以两个换行分隔。标题、标识及未选中分支不进入模型正文。格式更新与记录版本是不同边界，旧格式不被悄悄改写为新内容。

## 预览与历史

编辑器可查看和编辑全部分支，页签选择不改变运行条件；实际展开仍由当次变量决定。预览能查看选择了哪个分支、变量值和材料来源。

请求使用内容固定后的快照。请求发出后修改模板或材料，不改变在途请求及历史；历史查看不重新读当前磁盘、插件状态或最新模板。来源摘要变化而正文未变，不需要再向模型发送相同正文。

快照保留上下文定义和材料，执行配置另保留模型、工具与预算；都不保存凭据。用户输入、原生 reasoning、工具结果仍保持各自结构，不能为方便编辑而拍平成任意提示词。

## 基础上下文的生效

自研 harness 在每次自然请求前取得当次配置和材料；组装失败不消费待处理输入、不调用模型。首次顶部指令固定，后续有效正文变化以更新通知追加，明确替代范围，保留已发送前缀。当前请求期间产生的修改留给下一次请求。

Claude 共用模板与材料契约，但按 SDK 的实际输入纳入事件确认交接，具体差异见 [线程通知投递](线程通知投递.md#claude-的交接边界)。不能将模板可编辑解释为可在任意执行阶段改变配置。

项目材料默认来自工作目录到最近仓库根目录之间适用的 `AGENTS.md` 与 `.kite/memory/MEMORY.md`；无仓库时沿父目录查找，按由外到内的顺序提供。子目录规则与记忆正文按需读取。只采集实际选中路径用到的材料，不为隐藏分支额外读取文件。

普通材料变化不打断当前请求、不唤醒空闲线程。独立终端沿用自身入口定义；App 的模板目录属于工作机，不因编辑目录自动改写独立终端配置。

## 通知正文

配置、基础上下文、执行授权、插件工具授权四类通知共用段落、变量与条件编辑器。配置和授权保存时固定对应模板与实际值；基础上下文在发现有效正文变化时固定更新通知。

保存模板本身不生成业务通知、不唤醒模型、不改变权限。已生成但尚未投递的通知保留原快照；后续编辑只影响之后生成的通知。基础正文不变时，仅编辑通知模板不会额外追加更新。

通知的权限层次由宿主决定，文字不能改变模型参数、预算和执行授权。来源、投递顺序、重启和失败后的处理统一见 [线程通知投递](线程通知投递.md)。
