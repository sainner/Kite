# 上下文模板与生效规则

上下文编排允许用户查看、编辑和保存内容，界面和实际请求使用同一份结构化定义。本文规定模板、材料与历史的关系，不解释组装函数的实现。

当前已接创建会话、标题生成、上下文压缩和五类通知模板。文件变化通知目前只由上下文压缩生成，普通文件事件的收集与投递尚未接入；压缩时机与 token 估算不由模板系统提供，见 [上下文压缩](harness-主循环.md#上下文压缩)。

## 模板归属与生效

模板目录属于工作机，Mac 与 iPhone 读取同一份保存内容，重启不覆盖用户编辑。

| 场景 | 生效规则 |
|---|---|
| 创建会话 | 首次请求前绑定选定的模板内容，目录中的后续修改不自动改变已有实例 |
| 会话标题 | 共用一份模板，命名规则与材料共同保存；每次生成读取最新内容 |
| 上下文压缩 | 共用一份模板；每次压缩读取最新内容，生成的摘要与包装随压缩结果固定 |
| 五类通知 | 各场景共用对应模板；新通知保存生成时的内容，不重写已生成通知 |

已有会话显式修改基础上下文时，在后端允许的交接边界追加更新，保留原有历史前缀。选择模板只改变上下文，保留模型、工具、预算与授权。

`GET /context-templates` 返回模板、revision 和场景变量目录；`POST /context-templates` 新建创建会话模板；`PUT /context-templates/:id` 携带 `expectedRevision` 更新，不能改变场景。冲突返回 409，编辑器保留草稿。标题及通知不提供脱离实际调用的无效副本。

首消息创建请求可携带 `contextTemplate: {id, revision}`；已创建的空会话可通过 `PUT /instances/:id/context-template` 携带实例配置 revision、模板 ID 和模板 revision 绑定。两条路径均须在首个模型请求前完成。未选择时使用对应 agent 的默认模板。

## 场景契约

场景规定模板适用的用途和可引用变量；它不是调度器。新增场景不意味着已有事件来源，也不自动触发模型。

| 场景 | 可用变量 | 用途 |
|---|---|---|
| `thread.create` | `environment.cwd`、`environment.date`、`project.documents` | 基础上下文 |
| `thread.title` | `thread.title`、`thread.messages` | 当前标题与近期对话材料 |
| `thread.compact` | `compaction.range`、`compaction.summary` | 压缩指令与摘要在历史中的包装 |
| `thread.file_changes` | `files.changes`、`files.origin` | 文件变化与来源；目前由上下文压缩生成 |
| `thread.configuration_changed` | `agent.revision`、`agent.model`、`agent.reasoning`、`agent.tools`、`agent.max_requests_per_turn` | 实例配置变化 |
| `thread.context_updated` | `context.instructions` | 更新后的基础正文 |
| `thread.execution_permissions_changed` | `execution.revision`、`execution.grants` | 执行授权变化 |
| `thread.plugin_tools_changed` | `plugin.tools` | 已授权插件工具及目标 |

模板只能引用工作机公布的场景变量，不能自行增加变量。变量的取值、来源、使用时机和保存期限由业务确定；文件或插件的观察材料不能自行取得指令权限。

## 定义与变量

HTTP 模板定义使用 `version: 2`，包含标识、名称、场景和有序内容块。标题与压缩场景另有 `input` 区域，与 `blocks` 共享版本和一次保存：标题的 `blocks` 用作命名指令，`input` 用作对话材料；压缩的 `blocks` 用作摘要指令，`input` 用作摘要在历史中的包装。标题模板不能绑定为创建会话模板。

| 结构 | 含义 |
|---|---|
| `paragraph` | 稳定 ID、标题和由文字、变量组成的 `parts` |
| `condition` | 检查一个变量，精确匹配 `cases`，否则采用 `otherwise` |

例如，一个可编辑的运行环境段落：

```json
{
  "type": "paragraph", "id": "environment", "title": "运行环境",
  "parts": [
    {"type": "text", "text": "当前工作目录："},
    {"type": "variable", "name": "environment.cwd"},
    {"type": "text", "text": "。日期："},
    {"type": "variable", "name": "environment.date"}
  ]
}
```

条件可以嵌套，空分支不产生正文；不执行 JavaScript 或表达式。变量为具名引用，普通文字里的 `${...}` 不作为模板解释，变量内容也不二次解析。

段落和分支 ID 在定义内唯一，匹配值不得重复。所有分支的引用名称必须有效，但只要求实际选中路径具备材料；隐藏分支缺少运行材料不阻止当前路径。未知变量、无效定义或缺少必需绑定明确报错，不静默遗漏。

段内文字直接连接，非空段落之间以两个换行分隔。标题、标识及未选中分支不进入模型正文。历史内容不随模板格式变化而改写。

## 预览与历史

编辑不改变条件求值规则，实际展开由当次变量决定。预览应能核对分支选择、变量值和材料来源。

请求发出后修改模板或材料，不改变在途请求及历史。历史展示当时的内容与来源，不受当前文件、插件状态或模板影响；有效正文相同不重复发送。

历史须能还原当次上下文与执行设置，但不包含凭据。可编辑模板不能篡改用户原文、模型原生记录或工具结果。

## 基础上下文的生效

首次基础指令固定，后续有效正文变化在自然请求边界追加，保留已经发送的历史。组装失败不消费待处理输入、不调用模型。harness 与 Claude 的交接差异、配置和工具变更统一见 [线程通知投递](线程通知投递.md)。模板可编辑不表示任意执行阶段都可改变配置。

项目材料默认来自工作目录到最近仓库根目录之间适用的 `AGENTS.md` 与 `.kite/memory/MEMORY.md`；无仓库时沿父目录查找，按由外到内的顺序提供。子目录规则与记忆正文按需读取。

独立终端沿用自身入口定义；App 的模板目录属于工作机，不因编辑目录自动改写独立终端配置。

## 通知正文

五类通知与基础上下文使用同一编辑器。保存模板只影响此后生成的通知，不能重写已生成或已投递内容，不生成业务事件、不唤醒模型，也不改变权限。基础正文不变时，仅编辑通知模板不会额外追加更新。

通知何时固定正文、何时纳入请求，以及重启和失败后的处理，统一见 [线程通知投递](线程通知投递.md)。
