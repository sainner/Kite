# 台面与停靠栏

**状态：** 2026-10-25 与用户定稿并实现（协议 24），替换此前以共享窗口为中心的呈现模型；Mac 已逐帧核过，iPhone、iPad 待真机验收。

本文适用于 App 与工作机，规定工作区里的实例怎样呈现：停靠栏列什么、台面放什么、实例何时消失、布局是什么。接口见 [工作机接口](kited.md#接口)，实例的定义与存续见 [Agent 与插件契约](Agent与插件契约.md#33-plugininstance工作区中的业务对象)。界面样式、尺寸与动效的具体做法在代码里。

## 原则

- **一个格子就是一个实例。** 工作区里每个未归档的实例在停靠栏占一格，不分它在不在台面上、有没有在跑。没有「窗口」这个共享对象，也不再有「有窗口的实例」与「没窗口的实例」两种样子。
- **看哪几个是设备自己的事。** 台面上放哪几个实例、怎么摆、焦点在哪，由每台设备各自保存，不同步。实例本身、它当前的视图和状态在各端一致。
- **实例只在用户不要它时消失**，怎么消失由插件的存续方式决定。缩小、关掉 App、断线都不改变实例。
- **规则尽量少。** 台面只有缩小、展开与还原、关闭或归档、拖动四类动作，加上布局；没有固定，没有多步的排布记忆。

## 实例与消失

| 存续方式 `lifetime` | 怎么消失 | 当前用途 |
|---|---|---|
| `closable` | 用户关闭即回收，没有要保留的数据 | 浏览 |
| `persistent` | 用户归档：停止执行、保留数据 | 代理、monitor、待办 |
| `process` | 进程在跑时一直在；进程自己结束后标为已结束、留到用户关闭；用户停止进程等于关闭；工作机重启时进程已不在的直接回收 | 终端、预览 |

- 代理转到后台的命令是一个终端实例，创建来源是那次工具调用：进程结束即回收，结果交给启动它的代理。用户开的终端与预览留到用户关闭。
- 「关闭」只对 `closable` 与 `process` 存在，「归档」只对 `persistent`；两者都是对实例的操作，各端一起去掉它。标题栏按存续方式只给其中一个。
- 实例当前显示的视图（文件或网页、画面或输出……）是实例自己的状态，切换同步到各端。
- 子代理不单独占格，归父代理：在父代理的家族格里，随父代理归档。

## 停靠栏

停靠栏是工作区的目录，从前到后（Mac 竖排从上到下，iPhone 横排从右到左、靠近拇指的一头在前）分两组，中间一道分割线：

1. **布局组**：添加布局的入口在第一个，随后是本项目的布局文件夹。
2. **实例组**：每个实例一格，代理在前、工具在后，各按创建先后，状态变化不挪位置；添加实例的入口在最后。

- 每格一个头像；布局文件夹是一个带描边的格子，里面是成员头像的网格。
- 放不下时不折叠、不分页：靠末端的照原间距，溢出的一头堆叠起来、越靠后越透明，滚动翻看。Mac 与 iPhone 同一套排法。
- **家族格**：父代理一格，带着它各层的子代理。叠着时露出前几个头像、往后渐隐；点开原地展开成一排，展开后的排法与停靠栏同一套，再点收回。子代理在跑、等人回应，都反映在家族格上，不看它们也不会漏事。
- 点一格：实例在本机台面上就聚焦，不在就放上台面。
- 状态画在格子上：执行中、等你回应、回合结束后本机还没看的「完成待查看」。「完成待查看」是本机阅读状态，不同步。

## 台面

台面是本机正在看的几个实例，排成卡片。

- **放上台面**：从停靠栏点或拖，打开布局，新建实例，或代理请你看（见跨设备）。已在台面上的只聚焦。
- **缩小**：本机把它从台面拿掉，卡片飞回它在停靠栏的那一格；对实例什么都不做。拖进停靠栏也是缩小。
- **展开与还原**：展开让一张卡片占满台面，别的暂时离开；还原回到展开前的排布。这是台面唯一记住的上一步。展开中打开别的实例、缩小或关掉展开的那张，先按还原处理再做那个动作。
- **关闭或归档**：按实例的存续方式，实例消失，各端的台面与停靠栏一起去掉它。
- 拖缝改尺寸只动相邻的卡片。拖标题栏换位置：落在一张卡片中间就顶替它，被顶替的回停靠栏，同缩小；落在卡片靠边处就切开放在旁边。不吸附、不对齐点阵。
- 台面上一个实例都没有时显示新建实例的选择页，它是底，不能关；选了插件就原地变成那个实例的卡片，身份与位置不换。
- 代理草稿与新建实例的选择页只在本机，不是实例，关掉就丢；发出第一条消息或选定插件后原地变成实例。

## 布局

布局属于项目，是一张配方，不是具体实例的清单：

```text
{ id, name, members: [{kind: "agent", role} | {kind: "files", page?} | {kind: "terminal"} | {kind: "preview", target, device?} | {kind: "plugin", definition}], arrangement }
```

- `arrangement` 是成员的摆法：分栏树（方向、比例）与成员顺序；iPhone 只用顺序。
- **保存**：把本机台面上现有的卡片翻成配方：代理记角色，浏览记当前网页（看文件的不记路径），预览记目标与设备，其余记类型。要改就重新保存覆盖；改名与删除在文件夹上操作。
- **打开**：整个台面换成这组。每个成员先用本机记的这一格上一次的实例，它还开着、种类也对得上就用它；其余的在当前工作区找现成的：代理按角色，先取已在台面上的，再取最近活动过的；浏览、终端、插件按类型，预览还按目标与设备；找不到的新建，代理新建为这个角色的草稿。排布照配方。
- **正在用的布局**：本机最后打开或保存的那个，到打开另一个为止。各格上一次的实例在保存、打开时记下；正在用时，台面上它的某一格原地换成同一种的另一个实例（拖到卡片中间顶替、清空上下文），这一格就记成新的。展开与还原、换位、改尺寸都不改变正在用的布局，也不改配方；换成别种实例、改排布要重新保存覆盖。这些记录只在本机，别的设备、同项目的别的工作区照配方找。
- 文件夹里画的是角色头像与工具图标，与具体实例无关；成员实例仍在实例组里照常显示。
- 布局是账号级数据，随项目登记同步到各工作机，任一台都能改，见 [账号级数据](kited.md#账号级数据)。

## 跨设备

- 代理要给用户看一个实例（`agent.start` 带 `show`）：工作机在工作区事件流推 `instance.show`，此刻在看这个工作区且处于前台的设备把它放上台面，其他设备不动。
- 「完成待查看」、台面、焦点、阅读位置、正在用的布局与各格上一次的实例都只在本机。
- 重连以工作机当前的实例集合为准：本机台面上已不存在的实例去掉，不能复活。

## 过渡

缩小、放上台面、展开、还原、关闭、归档、新建与打开布局都要有连续的过渡：卡片在台面位置与停靠栏那一格之间飞，新建从添加入口展开，让位的卡片同时动，没有回弹。打开布局时已在台面上的成员挪到新位置，新来的从各自的格子展开，离开的飞回格子。过渡中的点阵、悬停与点击规则沿用 [界面设计原则](视觉风格.md) 与现行实现。
