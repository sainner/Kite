# Kite 项目规范

> 这里的「项目」指被 Kite 管理的任意文件夹，不是 Kite 自己的代码仓库。
>
> 规范只规定**文件夹该长什么样**：什么东西放在哪里，由谁维护。怎么运作、为什么这样定，看[任务书](任务书.md)对应章节。状态标注沿用任务书：**已决定**是用户确认过的，**建议**是还没明确表态的，**待验证**是还没测过的前提。

## 规范本身的规矩

1. **优先用上游原生格式**：AGENTS.md、`.claude/`、`.gitignore`、`.worktreeinclude`。不用 Kite，项目照样能用。
2. **Kite 自己的东西只放 `.kite/` 一个目录**，而且越少越好。
3. **加一条规则前先问三个问题**：上游有没有？一个约定能不能解决？几行指令能不能解决？
4. **每条规则都要能被检查。** Kite 的能力视图（任务书 §13）按规范给项目体检，比如「还有 3 个大文件在项目里」。检查不了的规则不写。

## 一个项目长这样

```
论文项目/
├── .git/                  版本库，访达默认看不到
├── .gitignore             排除规则，Kite 初始化时写入默认值
├── AGENTS.md              给 agent 的项目说明，唯一的指令源
├── CLAUDE.md              只有一行：@AGENTS.md
├── .claude/
│   ├── rules/             只在碰到特定路径时适用的约定
│   └── settings.json      工作树的软链接配置等上游设置
├── .worktreeinclude       建工作树时要复制过去的被忽略文件
├── .kite/
│   ├── memory/            agent 记住的项目知识
│   └── setup              工作树初始化脚本，可选
├── docs/                  完整的机制说明，可选
├── assets -> 资源库里这个项目的目录
└── 正文文件……
```

**不在项目文件夹里的东西**：会话记录（在 Kite 服务器）、会话的工作树（在 Kite 管理的目录）、大文件本体（在资源库）、只关于某个人的记忆（在用户级目录）。

## 规则

### 一、项目是一个标准 git 仓库（**建议**，用户未明确确认）

- 已有的 git 仓库直接用。普通文件夹由 Kite 执行 `git init`，主线分支就是「这个文件夹的样子」，提交由 Kite 代做。
- 文件夹在 iCloud、Dropbox 这类同步目录里时，仓库本体放到同步目录之外，文件夹里只留一个一行字的 `.git` 指针文件（`git init --separate-git-dir`）。它仍是标准仓库，标准 git 工具照样认。
- 不存在第二种模式。这条确认后，取代任务书 §7 里给普通文件夹建隐藏仓库的方案。
- 为什么：会话工作树、合并、多机推送都需要带分支的正常仓库；历史留在项目里，才符合「不锁定」。

### 二、项目文件夹不放大文件（**已决定**；链接和资源库的具体形态是**建议**）

- 图片、PDF、视频这类大文件放资源库（任务书 §8），项目里只放一个指向资源库对应目录的链接，默认叫 `assets`，名字待定。
- Kite 初始化的仓库，`.gitignore` 默认排除这些类型：位图、PDF、视频、音频、压缩包和镜像、设计源文件、二进制数据格式，扩展名大小写都排除。svg 和 Office 文档不排除，它们是正文的一部分。完整清单见 `spikes/snapshot/snap.ts`。
- 已有的代码仓库按它自己的 `.gitignore`，Kite 不改。
- 为什么：图片、PDF 压不动，进快照约等于再存一份；被忽略的文件又不会出现在会话工作树里，散落在项目各处 agent 就看不到。集中到资源库，再用一个进 git 的链接，每个工作树都自动带上。
- **待验证**：Claude Code 沙箱能否挡住 agent 经链接改写资源库。

### 三、密钥不进仓库（**建议**）

- Kite 初始化的仓库，`.gitignore` 默认排除 `.env`、`*.pem`、`*.key` 这类文件。
- 提交或同步到远程之前自动扫描密钥，发现了就拦下，告诉用户在哪一行。
- 会话需要的密钥文件，用 `.worktreeinclude` 复制进工作树。
- 为什么：非技术用户的脚本里很可能直接写着密钥，进了 git 历史很难删（任务书 §9）。

### 四、指令只有一个源：AGENTS.md（**建议**）

- 始终适用的项目约定写在 AGENTS.md。
- CLAUDE.md 里只有一行 `@AGENTS.md`，保证 Claude Code 在任何设置下都读得到。
- 为什么：除 Claude Code 外其他 agent 都已统一到 AGENTS.md（任务书 §13）。

### 五、知识按类型各有一个归宿（**已决定**做法，细节**建议**）

| 知识 | 放哪 | 加载方式 |
|---|---|---|
| 始终适用的约定 | AGENTS.md | 每轮加载 |
| 只在碰到特定文件时适用的约定 | `.claude/rules/*.md`，用 `paths:` 限定 | 碰到对应路径时注入 |
| 值得带到以后会话的单条事实 | `.kite/memory/`，一事一文件，`MEMORY.md` 做索引 | 索引每轮加载，正文按需读 |
| 完整的机制说明 | `docs/` | 索引注入，正文按需读 |

- 记忆目录通过上游的 `autoMemoryDirectory` 指到 `.kite/memory/`，跟着 git 走。
- 进项目的只有关于项目的记忆。关于某个人的偏好和协作方式留在用户级，不进共享仓库。
- 写下的内容只描述系统现在怎样、为什么，不写「做到哪了」；过时就改或删。
- 为什么：见任务书 §12。

### 六、会话在工作树里做，完成后合并回主线（**已决定**）

- 每个会话一个工作树，放在项目文件夹之外，由 Kite 管理。
- 会话需要的被忽略文件用上游格式声明：`.worktreeinclude` 列要复制的，`.claude/settings.json` 的 `worktree.symlinkDirectories` 列要软链接的。依赖目录不软链接，每个工作树直接装。
- 需要初始化命令（比如装依赖）的项目，提供 `.kite/setup` 脚本（**建议**，名字待定）。Kite 用环境变量告诉它主仓库在哪；它用退出码报告成败，不自己判断身份，也不写状态文件；每个工作树只跑一次，在 agent 开工前跑完。
- 为什么：见任务书 §21。

### 七、Kite 的历史不占用户的命名空间（**建议**）

- 快照是 `refs/kite/<会话>` 下的提交，不建分支，不动用户的 HEAD、分支和暂存区。普通推送不会带上它们。
- 会话记录不进项目文件夹（**已决定**，任务书 §11）。
- 由 Kite 会话产生的提交带一行 `Kite-Session: <会话 id>`，会话记录在保留期内时可以跳回去看过程。
- 每个快照记下当时资源库的版本号，项目回退时可以选择让资源一起回退。这样「这版论文用的是哪版图」有答案。

### 八、放在统一路径下（**建议**）

- 代码仓库放在 `~/code/<域名>/<owner>/<repo>`（ghq 约定，任务书 §4）。
- 普通文件夹的统一位置未定。放在同步目录里的项目，按规则一处理。
- Kite 扫描家目录发现散落的仓库，一键登记或迁移。
