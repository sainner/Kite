# 跨后端上下文翻译实验（2026-10-08）

历史验证材料，保留当时的条件与结果，不代表上游格式永远不变。现行契约见 [工作机说明](../kited.md#会话后端与宿主边界)，脚本与复现方法见 [spikes/handoff](../../spikes/handoff/README.md)。

## 问题

同一会话在 Claude 与自研 harness 之间切换时，上下文能否无损交接；哪些内容只能丢失。

## 条件

- Claude Agent SDK 0.3.280 自带的 Claude Code 2.1.280，使用 kited 当时的 Claude 配置（空工具集、提示过滤插件、`verbatimPrompts`），本机假 Anthropic 端点，隔离配置目录。
- harness 一侧使用 kited 的 ChatGPT 订阅适配器与真实订阅端点，模型 gpt-6.1-sol，共 3 次小请求。
- 真实 Anthropic API：本机 Claude 订阅登录，模型 sonnet（claude-sonnet-5），合成条目由 kited 的生产翻译代码生成，共两组、每组 2 次请求。

## 结果

| 验证 | 结果 |
|---|---|
| 只用中立内容（人发消息、hook 注入的通知、助手文字、thinking、并行工具调用与结果）合成 Claude 会话文件后 resume | 发给模型的请求与原生会话除 `metadata` 外逐字节一致，包括 system、tools、messages 和 thinking 配置 |
| 合成文件省去 cwd、version、userType 等外围字段 | 模型请求不受影响 |
| 合成运行中插话（`queued_command` 附件）与带图片的工具结果 | 历史前缀与原生一致；插话按原生包装并进最后一个工具结果 |
| 在已运行过、带 `last-prompt` 的会话文件末尾追加合成条目 | resume 从追加的新叶子续接，额外的 `kite` 字段被容忍 |
| MCP 结果带 `structuredContent` | 记录与请求中的正文为字符串，`structuredContent` 不发给模型；失败时带 `is_error` |
| Claude 的 `toolu_` 调用 ID、不带 id 的助手消息作为 Responses 输入 | 订阅端点接受，模型能用翻译来的工具结果正确回答 |
| 只带摘要、没有加密内容的 reasoning 输入条目 | 端点不报错但静默丢弃，模型看不到其中内容 |
| 真实 Anthropic API：历史中的工具调用使用 OpenAI 风格的 `call_` ID，harness 的加密 reasoning 被丢弃 | 请求成功，模型从翻译来的工具结果中答出只存在于结果里的暗号 |
| 真实 Anthropic API：上一轮 Claude 回复带有签名的 thinking，其后接无 thinking 的 harness 回合 | 请求成功；上一轮未产生 thinking 时同样成功 |

## 结论与限制

- 记录层可以无损：两份原生记录都只追加，各自的推理和恢复字段留在自己的记录里，切回原后端时仍然可用。
- 模型可见层，除推理外的输入、通知、文字、工具调用与结果、图片都可以无损交接；跨厂商的推理无法传递：Claude thinking 的签名只有 Anthropic 能校验，harness 的加密 reasoning 只有 OpenAI 能解密，摘要形式会被丢弃。用户确认推理丢失可以接受。
- 切换只在回合结束后进行。合成的历史停在回合中途时，CLI 会补一句 “Continue from where you left off.”。
- Messages API 不保存会话状态，官方文档允许历史中使用合成的助手消息；只有 thinking 签名受服务端校验，翻译不伪造签名。
- 会话文件属于 CLI 内部格式，升级 SDK 须重跑这组实验。
