# 托管账号与设备

适用于 Kite App 的首次配置、同账号设备发现、目录汇总和远程授权。Kite 账号与模型供应商账号相互独立；模型登录仍由各工作机自行完成。

## 设备角色与入网

Kite 托管账号服务与 Headscale。用户使用邮箱和密码注册或登录，无需自行部署服务器。Mac 可以作为工作机或控制端，本机执行时安装并运行 kited，远程控制时只运行 App；iPhone 和 iPad 作为控制端。

两种角色都加入账号网络，无需预先绑定某台工作机或创建项目。账号目录跨机器汇总，离线工作机的已上报检出仍保留。设备角色与项目、检出和工作区归属分开，见 [产品架构](产品架构.md#对象与归属)。

新设备可扫描已登录设备生成的二维码登录。二维码五分钟内有效，只能使用一次；重新生成会使本设备此前的未用二维码失效。接受邀请后创建独立会话，不复用签发设备的会话，因此可单独撤销新设备。二维码持有者能够加入该账号，必须由用户主动签发。

Mac 本机执行模式由 kited 维护一个持久网络节点，App 通过该节点访问其他工作机；控制模式由 App 维护节点。同一台 Mac 不因同时运行 App 和 kited 重复入网。

## 授权边界

Better Auth 负责密码和登录会话，Headscale 负责设备网络。Kite 维护账号与网络设备的对应关系、一次性邀请、工作机发现和导航目录索引。Headscale 管理密钥仅存在托管服务器的受控配置中，不下发给 App 或工作机。

每次设备登录持有独立会话。入网授权使用短期、不可复用、未加标签的预授权密钥；完成登记时，服务器同时核验节点所属用户和实际使用的密钥，不能凭客户端报告的地址抢占其他节点。

Headscale 策略只允许同用户设备互通。工作机入口还通过 tsnet 的 WhoIs 核验来源用户与自身用户一致，不接受客户端自行声明的账号。代理覆盖内部认证字段，kited 的远程监听仅接受本次进程生成的随机内部凭据。应用层的 `X-Kite-Machine` 继续防止地址复用时操作错机器。

移除设备时先撤销入网密钥与网络节点，再删除该设备的账号会话。已入网但未完成 App 配置的节点同样撤销；网络服务失败时保留设备记录供重试。签发设备退出后，其尚未消费的二维码失效。节点移除传播到工作机后，旧请求会被关闭，新请求不再放行。网络通路消失时，远端关闭不保证立即传到客户端；前台 App 每十五秒核验账号会话，收到 401 后主动关闭本机网络并清空工作机连接。会话过期或通过认证接口退出造成的残留设备，由账号服务定期回收。

App 将账号会话放在本机钥匙串，退出账号时清空当前工作机与工作区状态。目录摘要允许上传；会话正文、插件配置与模型凭据保留在工作机。用户绑定的 Git 凭据与通用密钥由账号服务加密保存，按需分发给本账号的工作机；托管项目的仓库内容保存在托管服务，见 [项目与远程仓库](项目与远程仓库.md)。当前注册不发送验证邮件，尚未提供邮件找回密码。

## 目录与工作机的职责

每台 kited 负责本机项目、检出与工作区的完整目录快照。摘要包含稳定 ID、名称、机器与目录归属、路径、工作区类型、分支与状态，不包含会话、窗口、插件配置和文件内容。App 合并目录时以项目 ID 关联，不能按同名目录推断为同一项目。

工作机用独立上报凭据发布自身目录。仅完成入网的工作机会话能签发此凭据，绑定设备与机器 ID；它不能读取账号目录或操作其他设备。工作机只保存此凭据，不保存用户密码或通用账号会话。设备撤销时目录与凭据同时移除；来源会话过期后停止接受上报。

目录变化时上报完整快照，失败后重试；空闲期间不重复上传目录，在线状态由组网服务提供。版本号由工作机在发送前持久化并递增，旧版本不能覆盖新版本；相同版本与内容可重试，相同版本不同内容返回冲突。轮换凭据开始新的版本序列，旧凭据立即失效，成功收到新快照前保留旧目录。目录过时与设备离线不等同于目录删除。

App 按账号在本机保存导航缓存，先显示缓存，再读取托管目录，并独立订阅各机目录事件。实时窗口、会话和操作直接访问所属 kited。工作机断开只影响它自己的内容；托管服务故障不停止已经运行的任务，App 可继续尝试缓存中的地址。首次登录、加入或撤销设备仍需要托管服务；离线缓存不授予新的网络权限，也不保证过期连接继续可用。仅目录摘要不能用来删除设备上已保存的窗口布局，必须等工作机返回完整窗口集合。

## 账号服务接口

公共入口为 `https://hs.sainner.top`。下表除注册、登录和接受邀请外均需账号会话 `Authorization: Bearer <token>`。响应禁止缓存。

| 方法与路径 | 调用者约定 |
|---|---|
| `POST /api/auth/sign-up/email` | `{email, password, name}`；密码至少十字符，返回独立会话与用户 |
| `POST /api/auth/sign-in/email` | `{email, password}`；返回独立会话与用户 |
| `GET /api/account` | 当前用户；会话无效返回 401 |
| `POST /api/invitations` | 生成 `{token, expiresAt}`；二维码内容为 `kite://join?token=…` |
| `POST /api/invitations/accept` | `{token}`；原子消费邀请，返回新设备的独立会话；过期、已用或来源会话失效时拒绝 |
| `POST /api/devices/enroll` | `{name, role, kind?}`，角色为 `controller` 或 `worker`；设备类型为 `phone`、`tablet`、`computer`、`unknown`，省略时为 `unknown`；返回设备 ID、控制服务器与一次性入网密钥 |
| `POST /api/devices/:id/complete` | `{ip, port?}`；仅该设备会话完成绑定，节点未就绪或身份不符返回 409 |
| `GET /api/devices` | 直接返回本账号设备数组，包含设备自身上报的 `kind`；工作机条目含组网访问地址和在线状态 |
| `PATCH /api/devices/:id` | `{kind}` 补报设备类型，只允许该设备自身的登记会话；同账号其他会话返回 403，非本账号设备返回 404，成功返回 `{ok: true}`，可幂等重试 |
| `DELETE /api/devices/:id` | 撤销本账号的指定设备及目录；其他账号的设备返回 404 |
| `POST /api/devices/:id/catalog-publisher` | `{machineId}`；仅本设备工作机会话可调用，返回 `{deviceId, url, token}`；每次调用轮换凭据，设备或机器重复绑定返回 409 |
| `GET /api/catalog` | 本账号已设置上报的工作机数组；每项为 `{device, machineId, revision, updatedAt, snapshot}`，首次上报前后两项为 null |

`PUT /api/catalog/:deviceId` 单独使用目录上报凭据作为 Bearer，正文为 `{revision, snapshot}`。`snapshot` 包含 `machine`、`projects`、`checkouts`、`workspaces` 四项，项目与检出都带归一化的 `remote`（检出的 `remote` 是 origin 当前指向的远程），身份与工作区摘要沿用 [工作机契约](kited.md)；拒绝重复身份、错误归属和额外字段。失效凭据返回 401，非法快照返回 400，旧版本或同版本不同内容返回 409；成功返回 `{ok: true}`。请求正文上限为 2 MiB。

账号接口与工作机上的 HTTP 接口属于两个服务。客户端不将账号密码或账号会话转发给工作机；连接工作机时使用网络身份。

原生 App 的账号 HTTP 会话只使用显式 Bearer，不接收或自动携带浏览器 Cookie，退出后重新登录不受旧 Cookie 影响。服务器继续校验携带 Cookie 的请求来源。

## 项目与 Git 远程

目录上报凭据同时是工作机凭据：工作机用它登记项目、取用凭据，不能读取账号目录或操作其他设备，设备撤销后立即失效。项目接口同时接受工作机凭据与账号会话，只返回本账号的项目。

| 方法与路径 | 调用者约定 |
|---|---|
| `POST /api/projects` | `{remote}` 按归一化地址幂等，同一账号同一远程返回同一项目，新建返回 201；托管地址只能查到本账号已有的托管项目。`{hosted: {name}}` 新建托管项目及空仓库 |
| `GET /api/projects`、`GET /api/projects/:id` | 返回 `{id, name, remote, url, hosted, createdAt, icon, color}`；`remote` 为归一化地址，`url` 为访问地址 |
| `PUT /api/projects/:id/appearance` | 仅账号会话，`{icon?, color?}` 至少提供一项，未提供项不变。`icon` 为内置 SF Symbol 名称（1–100 个 ASCII 字母、数字或句点，默认 `folder`）；`color` 为 `primary`（默认，跟随系统文字色）、`accent`、`buttercup`、`dewy`、`sunwashed`、`cloud` 或 `breeze`。返回完整项目；重复设置幂等，非法输入 400，工作机凭据 403，非本账号项目 404。外观由账号保存，不随工作机目录上报覆盖 |
| `POST /api/projects/:id/migrate` | 仅账号会话，`{remote}`；把托管项目的全部分支和标签推到新远程后改用新地址，项目 ID 不变。推送失败返回 409，项目不变 |
| `POST /api/git/credential` | 仅工作机凭据，`{url}`；托管远程返回一小时有效的 `{username, password, expiresAt}`，其他主机返回账号绑定的凭据，未绑定返回 404 |
| `GET /api/git/accounts` | 列出已绑定的主机与账号名，不返回凭据 |
| `GET /api/git/accounts/github.com/repos` | 已绑定 GitHub 账号可访问的仓库 `[{fullName, url, private, pushedAt}]`，按最近推送排序，最多 100 个；未绑定返回 404，GitHub 拒绝时返回 502 |
| `PUT /api/git/accounts/:host`、`DELETE /api/git/accounts/:host` | `{username?, token}` 绑定或替换该主机的 token，`username` 默认 `oauth2`；删除即解除绑定 |
| `POST /api/git/accounts/github.com/device` | 开始 GitHub 设备码授权，返回 `{flow, userCode, verificationURI, expiresAt, interval}`；服务未配置 GitHub 时返回 503 |
| `POST /api/git/accounts/github.com/device/:flow` | 按 `interval` 轮询，返回 `pending`、`slow_down`、`expired`、`denied` 或 `{status: "authorized", account}` |

托管仓库位于 `/git/<项目ID>.git`，只提供 Git 智能 HTTP 协议，以 Basic 认证的口令携带托管凭据；只能访问本账号的托管项目。迁移开始后只读，之后各工作机上报的检出都改用新地址或已没有该项目的检出时，删除托管仓库。

## 凭据服务

凭据服务内置于账号服务，Git 授权与通用密钥共用加密存储。加密密钥由账号服务密钥派生，密文绑定用户、作用域、名称与类型。通用密钥不与 Git 授权互相覆盖，也不包含模型供应商登录凭据。

账号共享密钥供同账号各项目的 agent 使用；项目专用密钥只对所属项目的执行开放。同名密钥按引用前缀明确区分，不回退或互相覆盖。管理由账号会话完成；工作机只能列出元数据和按需领取。工作机是可信执行宿主，须按实例实际归属固定项目 ID，不接受模型自报的项目或用户身份。当前不细分项目内各 agent 的密钥权限，保存到相应范围即允许该范围内的 agent 使用。

| 方法与路径 | 调用者约定 |
|---|---|
| `GET /api/secrets?projectId=` | 仅账号会话；省略项目时只列账号共享，提供项目时只列该项目。返回 `[{name, kind, projectId, updatedAt}]`，不返回内容；账号范围的 `projectId` 为 null |
| `PUT /api/secrets/:name` | 仅账号会话；`{kind, value, projectId?}` 保存或替换，同一用户、范围、名称幂等；项目在正文指定。`kind` 为 `text` 或 `file`；成功返回 `{ok:true}` |
| `DELETE /api/secrets/:name?projectId=` | 仅账号会话；删除相应范围的密钥，不存在也成功；返回 `{ok:true}` |
| `GET /api/secrets/available?projectId=` | 仅工作机凭据；列出账号共享及指定项目的元数据，并附 `reference`，不返回内容 |
| `POST /api/secrets/resolve` | 仅工作机凭据；`{references, projectId?}` 返回 `[{reference, kind, value}]`。引用为 `{account.name}` 或 `{project.name}`，项目引用必须有项目 ID；一次 1–32 条，重复引用合并 |

名称以英文字母开头，仅含英文字母、数字、下划线与短横线，最长 64 个字符；内容为 1–65536 个 UTF-16 单元的文本，不含 NUL，文件类型也按 UTF-8 文本使用。非法输入返回 400，管理接口拒绝工作机凭据（403），无效工作机凭据返回 401，其他账号项目或缺失密钥返回 404，项目引用缺少项目身份返回 409。批量领取中任一引用失败，整次不返回明文。响应均禁止缓存。

执行前按需读取，不缓存明文。替换、删除、工作机凭据轮换或设备撤销影响后续领取；已经启动的命令不会因此中断。取消请求不自动重试或重放命令。App 只在新建或替换时提交内容，保存后只显示元数据。执行中的环境变量、临时文件、输出与清理约定见 [基础工具契约](harness-主循环.md#shell)。

## 托管与验证

部署位置是 `hk-server` 的 Kubernetes `kite` 命名空间，账号与 Headscale 各一份持久卷，域名和证书共用现有 Ingress。部署配置、升级与凭据位置见 [托管服务运维入口](../kited/deploy/account/README.md)。旧个人组网的配对信息不转换为新账号，设备通过账号流程重新加入。

自动测试覆盖密码认证、账号间隔离、邀请并发消费与过期、设备撤销、目录上报权限、版本冲突、离线保留，发布器的在途变化、取消和真实进程重启，以及用真实 git 经托管远程克隆与推送、跨账号拒绝、不同写法的远程归入同一项目、迁移推送全部分支与标签后只读并在检出切换后删除、GitHub 设备码授权后工作机取用凭据。2026-10-06 在 Mac 上用三个临时 tsnet 节点和香港托管服务验证了同账号访问、跨账号拒绝、撤销后会话 401 与新连接拒绝，以及模拟客户端收到 401 后关闭网络、结束事件流。真实 Headscale 与 tsnet 的跨账号和撤销验证使用 [手动验证脚本](../kited/test/manual/verify-account-network.ts)。原生 iPhone 的扫码、前后台切换、蜂窝网络及代理 App 共存仍需真机验收；不能从服务端验证推断已完成这些场景。

2026-10-06 的 [App 目录手动验收](../kited/test/manual/verify-directory-app.ts) 使用实际 Debug App 与本机两个独立 kited，验证同项目汇总、仅摘要时保留布局、选择另一台机器时仍按工作区路由、单机断开与旧响应隔离。账号目录在此验收中由夹具提供，不能据此认定公网组网、iPhone 或异地设备组合已经通过。
