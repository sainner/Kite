# 自研 harness 的执行约定

本文说明自研 harness 必须保证的执行、工具与恢复语义，适用于独立终端及 kited 中的 harness 会话。Claude 是另一套完整后端，接入边界见 [工作机说明](kited.md#claude-会话的上下文)。代码入口见 [kited README](../kited/README.md)，本文不维护内部调用流程。

## 范围与职责

harness 管理模型请求、结构化历史、工具执行及回合结束；模型适配器负责上游协议，工具负责实际资源操作，宿主负责工作区、快照与持久生命周期。空闲不请求模型，同一会话最多一个模型请求。

一个回合从处理输入开始，可包含多次模型请求，到完成、失败或打断结束。模型输出一段文字不代表回合已结束；正常完成也不证明业务目标经过独立验证。界面显示协议不能代替原生模型历史，reasoning 等不透明字段和工具结果必须保留。

## 输入、请求与结束

- 输入可靠保存后才确认接收。同 ID 同内容重试去重，同 ID 不同内容拒绝。
- 接收与纳入模型请求分开。纳入只表示宿主已固定本次内容，不保证上游接收或成功回答；未纳入的输入可以撤回。
- 运行中插话在下一次自然请求纳入；收尾时到达的输入等收尾完成再处理。普通失败保留队列，等待新输入或显式继续。
- 工具参数完整且调用已可靠记录后才能执行。参数增量仅供显示，不能触发副作用。
- 下一次模型请求须等本次模型响应、全部工具结果及工具批次快照完成。工具结果按调用关系进入历史，不按完成时间随意重排。
- 只有上游明确完成才算请求成功。连接关闭、断流、解析错误和截断均不得当作完成，也不自动重试。
- 请求预算耗尽时暂停并报告原因；停止反馈同样消耗预算，不能借此无限推进。

基础指令、通知和历史快照见 [上下文模板](harness-上下文组装.md)；停止、队列退回与继续接口见 [会话状态机](会话状态机.md)。

## 工具执行约定

工具默认排他；宿主明确声明可并发的工具才允许重叠。调用顺序中的排他操作必须等待此前工具，之后的工具不能越过它。模型不能自行打开并发，不能通过猜测 shell 字符串来放宽隔离。

每个已保存调用都有明确结果：成功、错误、未执行或结果未知。普通工具错误可以交给模型处理；记录失败阻止后续副作用。取消时未启动的调用为 `not_executed`，已启动且无法确认效果的调用为 `unknown`。未知不是回滚，必须先核查再继续。

当前基础工具为 `read`、`patch`、`shell`。文件与命令访问均受 [统一执行边界](Agent与插件契约.md#71-插件与-harness-共用操作系统沙箱) 约束。

### read

按行读取文本。返回部分行不代表全文进入模型上下文；运行内记录的文件版本也不能证明压缩后仍携带内容。图片、PDF、持久观察账本和自动上下文压缩尚未接入这一契约。

### patch

参数为 `{ operations: [...] }`，每项包含 `type`（`create_file`、`update_file`、`delete_file`）和 `path`，创建、修改还需无文件头的 V4A `diff` 正文。

创建带末尾换行的文件：

```json
{"operations":[{"type":"create_file","path":"note.txt","diff":"+甲\n+乙\n+丙\n+"}]}
```

修改中间一行：

```json
{"operations":[{"type":"update_file","path":"note.txt","diff":"@@\n 甲\n-乙\n+丁\n 丙"}]}
```

同批不得重复操作同一文件，新建不能覆盖已有文件。无效路径或补丁在写入前拒绝；文件系统落盘不是事务，写入阶段失败时结果列出已完成项和失败文件，不自动回滚或重放整批。补丁需提供足够上下文定位；无法匹配当前内容就失败。

未在本次运行中读取过文件，或文件自上次读取、修改后发生变化，都只提示，不另设读后版本锁；删除同样按当前路径执行。成功修改更新已知版本。运行内版本提示不构成持久观察账本，shell 读取也不能据此视为已观察。

成功操作可携带稳定的历史差异引用，后续文件修改或删除不改变已保存的差异，格式见 [资源引用](资源引用.md)。

### shell

必须填写非空 `description` 说明用途，命令原文保留在详情中。模型结果中的输出限长，完整输出留在日志；截断须显式说明。

取消或超时后须确认受管进程停止才能结束，不能只关模型连接。无法确认时返回未知结果。当前不支持后台任务，进程组停止确认不覆盖自行脱离进程组的程序。权限放宽后不自动重跑原命令。

## 停止与宿主收尾

手动停止冻结并退回未纳入请求的输入，等待模型、工具和快照收尾；已经产生的文件修改保留。收尾完成前仍占用执行，不能启动下一回合、回退或采纳。

关闭执行实例用于停机，保留未处理输入，不等同于用户手动停止，也不向客户端退回草稿。只读历史和管理操作不得为恢复对象而自动执行队列。

宿主快照失败会暂停会话。回合已完成结束裁定而仍在收尾时，停止可以退回队列并等待收尾，但不追溯改写已经确定的回合结果。

## 恢复约定

| 恢复时发现 | 处理要求 |
|---|---|
| 已接收但未纳入的输入 | 保留队列；管理宿主等待显式输入或继续 |
| 未结束的回合 | 保留已知历史，暂停并记录中断 |
| 调用已保存但未开始 | 标记未执行，不自动执行 |
| 调用已开始但没有结果 | 标记 unknown，阻止后续副作用 |
| 结果已可靠保存 | 沿用原结果，不重新调用工具 |
| 记录损坏或存储故障 | 拒绝不可信恢复；不能跳过中间损坏继续运行 |

外部副作用不承诺恰好发生一次。确认恢复只能在实际检查残留执行与文件状态之后进行；它解除阻塞但不自动续跑。存储故障不能在原对象上直接确认消除，需重新打开并核查。

原生模型条目、输入、工具结果和请求所用上下文共同构成可恢复历史；不能从展示用文字重建。当前验证入口与手动实验入口见 [kited README](../kited/README.md) 和 [手动验证](../kited/test/manual/README.md)，早期订阅接入的条件与取舍见 [接入评估](harness-接入评估.md)。
