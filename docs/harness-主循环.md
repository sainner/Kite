# 自研 harness 的执行约定

本文规定独立终端及 kited 中自研 harness 的执行与恢复语义，以及两种后端共用的输入来源、基础工具和上下文压缩契约。Claude 的模型循环由上游负责，接入边界见 [工作机说明](kited.md#claude-会话的上下文)，代码入口见 [kited README](../kited/README.md)。

## 范围与职责

harness 管理模型请求、结构化历史、工具执行及回合结束；模型适配器负责上游协议，工具负责实际资源操作，宿主负责工作区、快照与持久生命周期。空闲不请求模型，同一会话最多一个模型请求。

一个回合从处理输入开始，可包含多次模型请求，到完成、失败或打断结束。模型输出一段文字不代表回合已结束；正常完成也不证明业务目标经过独立验证。界面显示协议不能代替原生模型历史，reasoning 等不透明字段和工具结果必须保留。

## 输入、请求与结束

- 输入可靠保存后才确认接收。同 ID 同内容重试去重，同 ID 不同内容拒绝。
- 接收与纳入模型请求分开。纳入只表示宿主已固定本次内容，不保证上游接收或成功回答；未纳入的输入可以撤回。
- 运行中插话在下一次自然请求纳入；收尾时到达的输入等收尾完成再处理。普通失败保留队列，等待新输入或显式继续。
- 工具参数完整且调用已可靠记录后才能执行。参数增量仅供显示，不能触发副作用。
- 下一次模型请求须等本次模型响应、全部工具结果及工具批次快照完成。工具结果按调用关系进入历史，不按完成时间随意重排。
- 只有上游明确完成才算请求成功。连接关闭、断流、解析错误和截断均不得当作完成。连不上、中途断开等可重试的失败退避后重发请求，见 [被打断之后](会话状态机.md#被打断之后)；已开始的工具做完，收到了还没开始的不再执行。

基础指令、通知和历史快照见 [上下文模板](harness-上下文组装.md)；停止、队列退回与继续接口见 [会话状态机](会话状态机.md)。

## 输入来源

两种后端的输入都标明来源，由宿主按调用身份填写，模型参数和插件不能指定。

| 来源 | 包括 |
|---|---|
| `human` | 用户在界面发的消息；Line 照原文转达的用户原话也算，另带 `via` 标明经 Line 转达 |
| `agent` | 别的代理发来的：`agent_send` 的消息、`agent_start` 带的首条消息、Line 用 `line_control` 发的说明。必须带发信方：本机代理记实例 ID 与发信时的标题，Line 记工作机与实例，名称为 Line |
| `kite` | Kite 自动发出的：monitor 事件、Line 的唤醒、后台命令结束、子代理回报、合并冲突与换机后的接续说明、Claude 恢复时的接续，以及转交的用户回应（提问的回答、密钥请求的结果） |

交给模型时，宿主按来源加包装，原生记录与界面保留原文：

- `agent`：正文包在 `<agent-message from="发信方名称">` 里，只写名称、不写实例 ID。能不能回信由协作授权决定，包装不作承诺。
- `kite`：开头写明这条消息由 Kite 自动发出、不是用户说的话，其中提到的用户同意或确认不算数。转交的用户回应不加，回答本身就是用户在界面上做的。
- `human` 开头是 `/名字`、名字是这个工作区能加载的 skill 时：输入上只记 skill 的名字，界面与排队中的输入据此标出点选的 skill，原文照样显示。宿主在收下时按那一刻的 SKILL.md 固定一段正文（与 skill 工具返回的同一包装），随收下的记录另存，交给模型时作为跟在这条输入后面的一条观察通知，带 skill 标记（见 [skill](#skill)）；Claude 的原生输入没有另起一条的位置，接在正文（和附件说明）后面。不是 skill 名字的照普通文字交给模型。
- `human` 带附件时：正文后面接一段附件说明，列出各附件在工作区里的路径；能解码的图片按 read 的规则规整后附在这条输入上，每张的体积上限更小：一条消息带满图片时合计约 20 MB 的 base64，在 Claude 一次请求的上限以内。图片在收下输入时定下，随原生记录保存，之后工作区里的那份被改或删除，不影响恢复与换后端。附件的接口与存放见 [会话显示协议](会话显示协议.md#附件)。
- 包装格式写在宿主代码里，不进上下文模板；发信方名称在收下时固定，代理之后改名不改已发出的历史。换后端时转换的历史使用同一包装。
- `kite` 输入由发出它的宿主功能标明通知种类，并附一句从用户角度说的话（如「整理文档 做完了」「你回答了提问」）；说的是某个子代理、子工作区、monitor 或后台命令的，再附上它的名称。这些只用于界面显示，不交给模型；原生行等没有标明种类的按正文显示。
- Claude 后端只给 `human` 标 origin。`agent` 与 `kite` 不标 `peer` 等来源，避免上游按自己的规则扣留，区分只靠正文包装。

来源用于显示、去重、回报和交给模型时的说明，不改变权限。

## 工具执行约定

工具默认排他；宿主明确声明可并发的工具才允许重叠。调用顺序中的排他操作必须等待此前工具，之后的工具不能越过它。模型不能自行打开并发，不能通过猜测 shell 字符串来放宽隔离。

每个已保存调用都有明确结果：成功、错误、未执行或结果未知。错误和结果未知都交给模型处理；记录失败阻止后续副作用。取消时未启动的调用为 `not_executed`，已启动且无法确认效果的调用为 `unknown`。未知不是回滚，模型须先检查实际效果再决定是否重做，宿主不重放。

当前基础工具为 `read`、`skill`、`patch`、`shell`、`web_search`、`web_fetch`、`credentials`；另有加载插件工具的 `tool_search`，见 [Bun 插件](Bun插件.md#模型工具与插件间调用)。文件与命令访问均受 [统一执行边界](Agent与插件契约.md#71-插件与-harness-共用操作系统沙箱) 约束。

### read

参数为 `{path, offset?, limit?, pages?}`，按文件头区分文本、图片和 PDF，不看扩展名。读取范围是工作目录，以及这个工作目录能加载的 skill 的文件夹：后者用 skill 工具给出的文件夹拼绝对路径，文件夹里的软链接不能越出文件夹。

- 文本：按行读取，offset 从 1 开始，结果带行号。
- 图片：PNG、JPEG、WebP、GIF、BMP、TIFF、HEIC 作为工具结果中的图片交给模型。长边超过 2000 像素或体积过大时先缩放、重新编码，结果文字说明原始与实际尺寸。
- PDF：用 macOS Vision 的文档识别转换为 Markdown，按页返回，每页以 `<!-- 第 k 页 -->` 开头。没有文本层的页使用 OCR 并附上页面图片，一次最多 5 张；文字识别与标题层级可能有误。`pages` 取 `"3"` 或 `"3-5"`，一次最多 20 页，省略时从第 1 页开始。输出按页限制长度，结果给出总页数和续读用的 `pages`；首个返回页单独超过上限时截断该页文字，并明确提示。

`pages` 只用于 PDF，`offset`、`limit` 只用于文本，混用直接报错。图片随工具结果写入会话记录，ChatGPT 与 DeepSeek 适配为 `function_call_output` 中的 `input_image`（不收图片的 DeepSeek 型号换成一句说明），Claude 适配为 MCP 图片内容；界面只显示结果文字。PDF 转换只支持 macOS 26 或更新版本，其他系统直接报错。首次使用须有 Xcode 命令行工具用于编译转换程序，冷启动可能较慢。转换进程使用适合 Vision 的独立沙箱，禁止联网，用户目录中只读目标 PDF，仅允许写入 Vision 缓存。停止读取时结束转换进程并返回错误，不产生结果未知。

返回部分内容不代表全文进入模型上下文；记下的文件版本（见 patch）只针对文本，也不能证明压缩后仍携带内容。压缩后不会自动重新提供读过的文件；用 skill 工具加载过的 skill 正文会重附，见下文。

### skill

参数为 `{name}`，返回这个 skill 的正文：一个 `<skill name=… layer=… folder=…>` 包装块，开头写所在层、文件夹的绝对路径和文件夹里的其他文件（真实位置越出文件夹的软链接不列，`read` 也读不到），再接去掉 YAML 头的 SKILL.md，其中的 `${CLAUDE_SKILL_DIR}` 换成文件夹路径（沿用 Claude Code 的写法）。每次加载都给全文，不按「加载过」去重：压缩可能截掉或丢下先前的正文，上下文里还有完整正文时由模型自己判断不必再加载。工具只给正文，与 Claude Code 的 Skill 工具一样：文件夹里的其他文件用 `read` 按绝对路径读，脚本用 shell 跑；代理没有 `read` 时 `skill` 也不可用，见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。可加载的 skill 就是基础上下文清单里的那些（`project.skills`，见 [上下文模板](harness-上下文组装.md#公共变量)），名字不存在时报错并列出可用的；清单、这个工具、`read` 认的 skill 文件夹和沙箱的只读放行用同一份，宿主在每次请求前重扫。

结果带 skill 标记（名字），正文就是结果本身；`/名字` 点选跟在输入后面的正文、压缩后重附的正文也带同样的标记。压缩只按标记认出加载过哪些 skill，不认工具名、不解析正文。

### patch

参数为 `{ operations: [...] }`，每项包含 `type`（`create_file`、`update_file`、`delete_file`）和 `path`，创建、修改还需无文件头的 V4A `diff` 正文。

创建带末尾换行的文件：

```json
{"operations":[{"type":"create_file","path":"note.txt","diff":"+甲\n+乙\n+丙\n+"}]}
```

修改中间一行：

```json
{"operations":[{"type":"update_file","path":"note.txt","diff":"@@\n 甲\n-乙\n+丁\n 丙"}]}
```

同批不得重复操作同一文件，新建不能覆盖已有文件。无效路径或补丁在写入前拒绝；文件系统落盘不是事务，写入阶段失败时结果列出已完成项和失败文件，不自动回滚或重放整批。补丁需提供足够上下文定位；无法匹配当前内容就失败。

文件在本线程上次看到或修改之后被别处改过，成功结果会提示按需重读；只提示，不另设读后版本锁，删除同样按当前路径执行。没看过的文件不提示：补丁对得上，说明模型知道那段原文。看到与修改除了 `read`、`patch`，也算 shell 的：本线程命令执行期间的改动算本线程自己的，输出里给出过的文件内容算看过。记录随会话保存，kited 重启后接着用。

成功操作可携带稳定的历史差异引用，后续文件修改或删除不改变已保存的差异，格式见 [资源引用](资源引用.md)。

### shell

参数为 `{description, command, timeout_ms?, secrets?}`。必须填写非空 `description` 说明用途，命令原文保留在详情中。普通命令的模型输出限长，完整输出留在日志；截断须显式说明。

`secrets` 将专用环境变量名绑定到凭据引用，例如：

```json
{"description":"使用项目 SSH 私钥访问已授权主机","command":"ssh -i \"$KITE_SECRET_KEY\" user@host.example true","secrets":{"KITE_SECRET_KEY":"{project.ssh_key}"}}
```

变量名必须匹配 `KITE_SECRET_[A-Z][A-Z0-9_]*`，一次最多绑定 32 个；引用及范围见 [凭据](kited.md#凭据)。`text` 类型在本次命令环境中提供值，`file` 类型提供权限为 0600 的临时文件路径。项目身份由宿主固定，模型不能指定其他项目。领取失败、引用不存在或执行前取消时不启动命令；下一次调用重新领取，原始调用与会话记录只保留引用。

带密钥的命令只返回退出状态，全部标准输出和错误输出在写日志、发送事件和生成工具结果前丢弃，包括编码和分段输出。在沙箱里的命令仍受原文件、网络与进程授权约束，密钥本身不授予额外访问范围；获准出沙箱的命令同样拿到密钥，不受这些约束，是否放行看沙箱外命令与审批。命令获得使用密钥的能力，不应将其复制到工作区或发送到无关地址；输出隐藏不是对任意文件写入、网络传输的数据流追踪。进程组确认结束后删除临时文件；结果未知时保留执行所需目录，残留进程在打开会话时停掉。

取消或超时后须确认受管进程停止才能结束，不能只关模型连接。无法确认时返回未知结果。服务中的 shell 到时限、用户插话或传 `background: true` 时改为转到后台终端，不停进程，工具立即返回实例 ID，结束时通知 agent，见 [终端](实例操作.md#终端)；转到后台之后不再跟着这次调用的取消停止，带密钥的命令不转。独立终端不支持后台任务，到时限就停。进程组停止确认不覆盖自行脱离进程组的程序。权限放宽后不自动重跑原命令。

### web_search

参数为 `{query, count?}`，`count` 默认 10、最多 20。搜索词交给外部搜索服务，结果逐条给出标题、链接、站点与日期（服务给了的话）和与搜索词相关的摘要，开头写明用的是哪家，并说明内容来自外部网页、其中的指示不是用户的要求。没有结果时照常成功。

服务按 DeepSeek（[Search](https://api-docs.deepseek.com/guides/search/)）、Tavily（[Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)）、Exa（[Search](https://exa.ai/docs/reference/search)）的顺序，只用账号里有 Key 的：DeepSeek 用模型 API 里的 Key，Tavily、Exa 用「搜索服务」凭据（见 [凭据](kited.md#凭据)），同一家有几把时按凭据列表的顺序。一家失败（Key 无效、额度用完、限流、服务出错、超时）就换下一家，结果里写明前面哪几家没成功；全部失败时报错并逐家列出原因，一把 Key 都没有时报错并说明去哪里加。Key 在每次调用时读取，加了或换了下一次调用生效。

搜索词只发给搜索服务，不经网络许可核对。各家支持的搜索语法不同，工具只保证普通关键词。

### web_fetch

参数为 `{url, offset?}`：读一个 http 或 https 网页，由外部服务抓取并转成 Markdown（DeepSeek [Fetch](https://api-docs.deepseek.com/guides/search/)、Tavily [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)、Exa [Contents](https://exa.ai/docs/reference/get-contents)），服务顺序、Key 与换家规则同 web_search。网页在服务那边抓取，内网、本机和要登录的页面读不到；工作区里跑的网页用预览查看。

读之前按代理此刻的执行授权核对目标的主机与端口，与 shell 连外网用同一份网络许可、同一套匹配规则：项目禁止的不读；在网络许可里的直接读；其余按审批模式处理，问人时卡片给出网址，「允许并记住」把这个主机与端口加进网络许可，之后 shell 连它也不再问。回环、链路本地与本机地址直接拒绝，网址不能带用户名或密码。核对是为了不让网页里的提示注入借网址把内容送到没有许可的网站，搜索结果里的链接同样要核对。

一次最多返回与 read 相同的字数，结果写明全文字数、这次的范围和续读用的 `offset`；同一网址 15 分钟内续读用第一次取到的内容，不重新抓取。结果同样说明内容来自外部网页。

两个工具没有副作用，可以并发，停止时按普通错误结束，不产生结果未知。Claude 后端经 MCP 拿到同名工具，Claude Code 自带的 WebSearch、WebFetch 保持关闭。独立终端没有这两个工具。

### credentials

参数为 `{}` 时列出当前账号共享和当前项目的 `{reference, kind, path?}`，不返回内容。列出不授予新权限，密钥只在 shell 的 `secrets` 参数中使用，设了路径的由宿主写进工作区。

请求动作向用户要密钥，语义见 [密钥请求](工具审批与提问.md#密钥请求)。请求不阻塞回合：不用问人的项直接存好，其余的发出后立即返回请求 ID，用户在卡片里填好或拒绝后，结果作为一条输入交给代理；`{withdraw: 请求 ID}` 收回。`request` 是要的各项组成的数组，1 到 10 项，同一项不能要两次：

- 独立的密钥：`{name, reason, kind?, value?}`，`kind` 为 `text`（默认）或 `file`，存好后结果给出引用。
- 环境变量文件里的一项：`{file, key, reason, value?}`，`file` 是工作区里的路径（如 `.env`），`key` 是变量名，存好后结果给出文件与变量名。
- `value` 是代理自己给的值，不用问人时直接存，否则卡片预先填好；不给时由用户填写。用户可以只填其中几项，结果逐项写明存好的和没填的，不带用户填的值。

服务内 harness 与 Claude 共用这些工具；独立终端尚未连接账号凭据服务，调用时明确报错。

## 上下文压缩

压缩把模型上下文中的一段连续历史换成摘要和必要的状态材料，范围之外的历史原样保留。原生记录只追加，原文仍可查看，压缩可以撤销；保持历史前缀不代表保证上游缓存命中。压缩由 Kite 管理，Claude Code 的原生压缩保持关闭。

范围以输入为界。手动压缩选起止两条消息，范围从起点所在的请求开始，到终点之后下一条输入纳入之前为止；终点之后没有输入时到最新。不选起止的手动压缩（压缩全部）与自动压缩一样覆盖全部已有历史，内容规则仍按手动。新范围只能完整包含或完全避开已有压缩，部分重叠拒绝；包含时，已有摘要成为新的压缩材料。整段导入的历史只能作为完整范围选择。

范围内的内容按类型处理：

| 内容 | 处理 |
|---|---|
| 人发的消息、代理来信 | 手动压缩并入摘要；自动压缩在保留预算内优先保留近期原文，其余并入摘要。`/名字` 点选的 skill 正文不随消息保留，按已加载的 skill 正文处理 |
| Kite 发的输入、助手文字、工具调用与结果、图片 | 并入摘要 |
| 状态通知：基础上下文更新、配置、执行授权、插件工具授权、工作区现况 | 范围之后还有同类通知时丢弃，否则保留范围内最新一条；顶部基础指令不变 |
| 文件变化 | 原有通知丢弃，另生成一条范围内的净变化通知 |
| 已加载的 skill 正文 | 调用与结果并入摘要，另行重附：一条说明写明是读过的材料、不要重新执行，后面每个 skill 一条带标记的正文。按 skill 标记认（skill 工具的结果、`/名字` 带的正文、上次重附的），同名取最近一次，每个最多 5000 token、合计不超过 25000，超出的截断并提示要看全文再加载 |
| 停止与恢复反馈、推理 | 丢弃 |
| 已有压缩的摘要 | 作为新摘要的材料 |

摘要使用线程当前的模型和思考强度，禁止调用工具。指令与摘要包装使用 `thread.compact` 模板。文件净变化使用 `thread.file_changes` 模板，依据范围两端的工作区快照，包含 agent 自己与其他来源的改动；没有快照的独立终端不生成此通知。

手动压缩与撤销只能在空闲时进行。压缩期间线程处于忙碌，停止会取消本次压缩，并按停止语义退回队列。摘要请求连不上、中途断开等可重试的失败与普通请求一样退避重发；重试用尽或不可重试时，手动压缩只报告错误，历史不变，自动压缩使本回合失败，等待显式继续。

harness 在每次模型请求前按估算用量检查自动压缩；Claude 在回合结束时按实测输入检查。两者使用该次执行的实际运行窗口，窗口未知时不自动触发，不能拿模型目录中的最大能力替代。触发比例和原文保留预算由 [压缩策略](../kited/src/harness/compaction.ts) 维护。

撤销只针对最外层的压缩，撤销后恢复原历史，被它包含的旧压缩重新生效。

Claude 的模型循环在 CLI 内，Kite 只能在回合之间压缩。压缩后的上下文用于下一回合恢复，也用于后端切换，规则见 [会话后端](kited.md#会话后端与宿主边界)。运行窗口取自 CLI；查询失败只沿用同一配置模型最近成功取得的值，换模型后不复用。回合中途撑满窗口时按普通失败暂停，摘要请求同样可能因超限被拒绝；当前没有回合中途压缩能力。

## 停止与宿主收尾

收尾完成前仍占用执行，不能启动下一回合、回退或采纳。宿主快照失败会暂停会话；已经产生的文件修改保留。

手动停止、服务关闭和回合结果的关系，以及队列退回和草稿重试，统一见 [会话状态机](会话状态机.md#手动停止与消息交接)。只读历史不打开会话、不执行队列。

## 打开会话时

宿主打开会话时按记录补齐上次被 kited 退出打断的部分，不开始执行；是否接着做由 kited 按 [会话状态机 · 被打断之后](会话状态机.md#被打断之后) 决定。

| 打开时发现 | 处理要求 |
|---|---|
| 已接收但未纳入的输入 | 退出前收下、还没开始的停在等待继续，接着做时处理；停下后留在队列里的照旧等继续 |
| 未结束的回合 | 保留已知历史，记为被退出打断，停在等待继续；已收到手动停止的按停止收尾 |
| 调用已保存但未开始 | 标记未执行，不自动执行 |
| 调用已开始但没有结果 | 标记 unknown，交给模型检查，不重放 |
| 结果已可靠保存 | 沿用原结果，不重新调用工具 |
| 登记的命令进程组还在 | 先停掉，停不掉的写进接着做时的继续说明 |
| 记录损坏 | 拒绝打开；不能跳过中间损坏继续运行 |

外部副作用不承诺恰好发生一次。独立终端 `--resume` 打开会话时同样接着做被打断的回合。

原生模型条目、输入、工具结果和请求所用上下文共同构成可恢复历史，不能从展示用文字重建。验证入口见 [kited README](../kited/README.md) 和 [手动验证](../kited/test/manual/README.md)。
