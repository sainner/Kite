# 工作区并行

本文适用于 kited 与 App，规定同一工作区里多个线程同时执行时如何协调。工作区与线程的生命周期见 [工作机](kited.md#工作区与线程的生命周期)，状态语义见 [会话状态机](会话状态机.md)。

**状态：方向已确认，尚未实现。** 当前实现仍是同一 cwd 执行互斥：有线程运行、等待恢复确认时，不能启动另一线程。

## 原则

线程之间默认并行，只有动整个工作区的操作才要求全员空闲。这与 Claude Code、Codex 允许同一目录同时跑多个会话一致；需要隔离时由用户另开独立工作区，独立工作区本来就是为隔离准备的。单个执行者内部的工具并行，不代表跨线程写入安全，所以文件写入另有宿主的协调。

## 各方面的协调

| 方面 | 约定 |
|---|---|
| 启动、发送、继续 | 不再互斥，同一工作区的多个线程可以同时执行 |
| 改文件 | patch 要求修改的上下文与当前文件一致，两个线程改到同一处时后到的明确失败，不悄悄覆盖；宿主对同一文件的写入短暂加锁，避免写到一半被另一次写入插入 |
| shell | 不协调，构建、测试可能互相干扰；需要隔离时用独立工作区 |
| Git | 不变：代理只能读 Git 元数据，提交只由宿主在采纳和现场推送时做 |
| 快照 | 仍按整个工作区拍，任一线程的工具批次之后都拍；快照记下触发的线程，内容可能含其他线程的改动。按文件的历史差异仍归属到具体线程 |
| 压缩时的文件净变化 | 说明里已区分 agent 自己与其他来源的改动，不变 |
| 回退、采纳、归档工作区、交接 | 仍要求这个工作区的线程全部空闲，这些是工作区级操作 |
| 恢复阻塞、等你回应 | 只卡住它自己那个线程，不再挡同一工作区的其他线程 |
