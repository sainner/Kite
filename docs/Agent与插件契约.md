# Agent 与插件契约

本文适用于内置 agent、文件、终端与 Bun 自定义插件，规定定义、实例、窗口、操作和权限的共同边界。产品对象关系见 [产品架构](产品架构.md)，具体可调用接口见 [实例操作](实例操作.md) 与 [Bun 插件](Bun插件.md)。

## 1. 统一边界

agent 是一种插件，与其他插件共用实例身份和公开契约。统一不要求所有插件使用相同的执行状态机。

| 边界 | 约定 | 理由 |
|---|---|---|
| 定义与实例 | PluginDefinition 描述可创建的类型，PluginInstance 表示工作区中的一份业务对象 | 身份、归属、标题、配置和持久生命周期有明确主来源 |
| 专有数据 | agent 拥有一个 Thread；终端、待办保留各自的业务状态 | 对话回合、PTY 和待办数据不能互相替代 |
| 操作 | 按实例调用有类型的操作，分别声明向界面、模型或内部逻辑开放的范围 | 同一业务动作可复用，界面操作不必全部成为模型工具 |
| 窗口 | 一个实例至多一个窗口，显示它的一个视图；公共容器管理呈现与视图切换 | 原生内容与 Web 内容共用工作区窗口机制 |
| 工作区能力 | 文件、进程、快照、线程与存储由宿主提供授权入口 | 插件不能绕过宿主扩大权限 |
| 上下文 | 共用场景、模板与历史快照契约 | 用户编辑的内容与实际请求一致 |

例如，一份待办实例可以提供看板和列表两个视图；整理待办的 agent 是另一份实例，通过授权操作访问它。创建来源只表示关系，不自动赋予权限或建立父子生命周期。

## 2. 已开放能力与限制

当前内置 agent、文件和终端，以及 Bun 自定义插件，共用实例和窗口身份。浏览（`kite.files`）提供目录、文本、Markdown 预览与历史差异，也看运行中的网页与互联网；终端提供工作机上的 PTY 会话，也接管 agent 转到后台的命令。自定义插件已接包登记、工作机逻辑、MCP 工具与资源、宿主持久状态、协作授权及 App Web 视图。

自研 harness 与 Claude 是并列的完整 agent 后端，共用 Kite 的实例、工具服务、授权与显示契约，保留各自的原生恢复记录。两者的配置生效和输入交接边界不同，见 [线程通知投递](线程通知投递.md)。不能因共享界面而把一方的模型循环规则套给另一方。

同一工作区的线程默认并行，工作区级操作才要求全员空闲，见 [工作区并行](工作区并行.md)；一个执行者内部允许工具并行，不表示不同线程可以安全并发修改同一工作区，文件写入由宿主协调。主动启动工作只经 [monitor](Monitor.md)，后台命令结束时通知启动它的 agent 是 agent 自己工作的延续；普通文件监听与通用外部 MCP 尚未开放。

## 3. 定义、实例、专有数据与窗口

### 3.1 PluginDefinition 与 manifest：可以创建什么

定义声明稳定标识、名称、配置、提供的视图与操作、执行入口和实例生命周期。内置的代理插件只有一个，另声明它支持的全部工具与兜底默认值；代理的提示词、工具规则、默认模型与预算由角色给出。自定义包的实际登记格式以 [Bun 插件契约](Bun插件.md) 为准，不把架构示意字段当作已支持的 manifest 参数。

manifest 表达提供和请求的能力，宿主决定实际授权。内置身份由宿主注册，不能由自定义包自行声明获得。内置组件可直接调用核心服务，不为形式统一增加进程通信。

### 3.2 角色与代理配置

代理 = 角色 + 实例配置。角色是资源库中可复用的配置，包含提示词、工具规则、执行授权的增减、默认审批模式、默认模型与思考强度；新建代理时拷贝所选角色，叠加草稿中的调整后成为实例配置，之后修改角色不改变已有代理。后端由所选模型的厂商决定：Claude 模型经 Claude Code 订阅运行，其他厂商的模型由自研 harness 运行，界面只按厂商分类模型，不单独提供后端选择。

授权分项目、角色、实例三层，三层管同一套维度：工具；执行授权（工作区读写、额外读路径、额外写路径、网络许可、沙箱外命令）；审批模式；外部 MCP 服务。

| 层 | 内容 | 生效 |
|---|---|---|
| 项目 | 基础与硬边界。执行授权分「允许」与「禁止」：允许是本项目所有代理的起点，禁止任何层和审批都打不开；工作区可定为只读；审批模式给上限。工具规则是白名单或黑名单 | 实时，下一次请求与工具调用即按新的 |
| 角色 | 在项目之上增减执行授权，给工具规则、必需工具与默认审批模式 | 新建代理时拷进实例，之后修改角色不改变已有代理 |
| 实例 | 默认值 = 项目 + 角色，之后在其上放宽或收窄；审批时「允许并记住」是实例层的放宽 | 立即 |

实际生效 =（项目允许 + 角色增减 + 实例增减）− 项目禁止，审批模式取实例的选择与项目上限中较严的。工具离开另一个工具用不全时，依赖的工具不在有效集里，它也不在：`skill` 只交 skill 正文，文件夹里的其他文件要用 `read` 读，所以没开 `read` 或 `read` 被禁用时 `skill` 也不可用。外部 MCP 服务默认关闭：角色列出新建代理默认打开的服务，实例在这台工作机装的服务里开关，项目只设禁止；生效的是实例打开、本机装了、项目没禁的，运行中开关在下一次请求生效。实例可以开角色没给的工具与许可，但打不开项目禁止的；被禁的配置保留在实例中，项目放宽后恢复。角色的必需工具被项目禁用时角色在本项目不可选，实例也不能关闭必需工具。宿主保护目录、Git 元数据与本机地址任何层都不开放。

项目约束随项目登记表保存在各工作机上、在工作机之间同步，只由用户修改。项目与角色里的路径可写 `~/` 开头，由各工作机按自己的主目录解析，本机不存在的许可略过。工作机使用本机的约束，在模型请求和工具调用前核验。有效工具或执行授权改变的代理收到配置通知；收紧对已在运行的命令（包括转到后台的终端）不追溯，从下一条命令起生效。模型和思考强度由角色提供初始值，可在实例中调整。

角色在开始对话前可以改选；对话开始后要换角色须新建代理。协作操作的默认授权跟随角色允许的工具，改选角色保留仍适用的用户授权调整；执行授权的增减与审批模式换成新角色给的。配置与授权分开保存，工具可用不代表已经获准访问其他实例。

配置绑定到实例；恢复沿用该实例的配置，不重新套用最新角色。模型、工具选择和提示词各有实际执行含义，提示词文字不能授予工具权限；工具规则也不扩大文件、网络或其他实例的访问范围，它们由授权决定。

显式配置变更留下通知，在对应后端的自然请求或回合边界生效。已发送的历史保留当时内容，配置快照用于还原过去，不能成为另一份可变配置源。细节由 [通知契约](线程通知投递.md) 和 [上下文模板](harness-上下文组装.md) 统一规定。

### 3.3 PluginInstance：工作区中的业务对象

实例有稳定 ID、工作区归属、定义引用、标题、配置和持久生命周期。agent 实例与其 Thread 必须共同存在；原生后端的会话 ID、临时进程和窗口身份与实例身份分开。

| `lifetime` | 窗口关闭后 | 当前用途 |
|---|---|---|
| `window` | 确认执行停止后回收实例、配置和状态 | 文件 |
| `persistent` | 保留实例、数据及已启动的执行 | agent、monitor、待办 |
| `process` | 进程运行中保留，成为没有窗口的后台进程；进程已结束则回收 | 终端 |

`process` 实例在进程结束时没有窗口就回收，有窗口的留到窗口关闭；进程随宿主重启结束的，连窗口一起回收。用户主动停止进程即可结束它，不提供归档。

随窗口回收的实例必须提供视图，并与窗口一起创建。最小化、退出 App、设备断线都不等于关闭工作机上的窗口。独立存续也用于保存空闲的会话与业务数据，不能按空闲状态删除；不再需要时由用户归档，归档停止执行、关闭窗口并保留数据。

用户新建代理时先在本机草稿中选定角色与初始参数，第一条消息连同这些参数一次创建实例、会话与窗口，配置从创建起就是所选值，不经过配置变更通知。草稿不属于共享窗口集合，不同步到其他设备，关闭即丢弃，工作机上不留实例。模型通过 `agent.start` 按角色创建的空代理不经过草稿。

回收失败保留窗口和实例供重试。成功回收后关联授权失效，实例 ID 不复用；迟到的操作重试不能复活对象。工作区文件和历史 diff 不随插件实例清理。后台执行由工作机管理，不依赖 iPhone 保持前台。

### 3.4 WorkspaceWindow：实例的呈现

一个实例最多一个打开的窗口，窗口显示实例的一个视图，可以在定义声明的视图之间切换。窗口目标为 `instanceId + viewId`，`viewId` 是当前视图；目标必须属于当前工作区，且视图已由定义声明。打开已有窗口的实例的某个视图时不创建新窗口，那个窗口换到这个视图；创建实例与打开已有实例的视图是两个动作。一个实例对应一个窗口，关闭窗口就是把实例收进停靠栏或结束它，不会关掉一个还剩另一个；代价是同一实例的两个视图不能并排看。

视图切换由窗口容器提供，插件只声明视图。切换不改变窗口身份，也不改变它在各设备上的位置与尺寸。

同一工作区在各端共享窗口集合、稳定 ID 和目标。添加、关闭与切换视图同步到各端；分栏、尺寸、停靠顺序和焦点由各设备分别保存。重连按工作机的当前集合恢复，旧的本机布局不能复活已经关闭的窗口。

agent 当前提供 conversation 视图；后台实例可以没有窗口。窗口容器负责公共行为，插件只提供业务内容与动作。客户端职责见 [App](App.md)。

## 4. 内置与自定义插件

来源、执行方式和权限分别表达。内置文件与会话可以使用原生界面，自定义视图使用 MCP Apps；自定义工作机逻辑使用 Bun。两类实例通过相同的业务契约访问工作区，宿主私有实现不属于插件接口。

agent 的 shell 命令默认在工具调用内跑完；超时、用户插话或 agent 要求时不停进程，转为一个终端实例继续运行，工具立即返回。转过去的命令仍按 agent 的执行授权跑在原沙箱里，只有输出，结束时通知启动它的 agent；用户开的终端是可交互的 PTY。两者共用终端实例的窗口、停止与回收，输入和执行边界各自保留。插件业务状态留在自己的命名空间；跨实例交换通过结构化操作或明确的上下文来源进行。

## 5. 公共契约

### 5.1 声明

声明负责发现、配置校验和能力登记。单个包加载失败不能破坏工作区与其他插件。没有实际调用方的能力不提前扩充为通用插件框架。

### 5.2 工作区能力

文件、进程、版本、实例与存储能力按实际需求开放。调用方身份、工作区和可访问的目标由宿主绑定，不能信任插件自报的 ID 或路径。模型供应商凭据留在宿主；需要模型工作的插件通过已授权的 agent 操作发起。

### 5.3 操作

操作定义输入、输出、允许的调用方和副作用；拒绝、业务失败、取消、结果未知必须可区分。模型工具保留明确名称与 schema，不压成一个无类型的万能调用入口。

重试不能重复产生副作用，取消不能被解释为撤销已发生的修改；执行效果未知时须显式核查。具体收据、版本与错误语义由 [实例操作](实例操作.md#重试取消与结果) 规定，agent 停止与队列退回由 [会话状态机](会话状态机.md) 规定。

并发能力由宿主确认，插件不能用并发标志绕过工作区的文件、快照和进程协调。

### 5.4 状态与事件

界面从快照与后续事件恢复对象状态；重连和断线不能被解释为业务执行结束。事件保留领域自己的含义，不要求所有插件共用对话状态机。订阅范围受授权限制，不能通过原始执行日志取得其他实例的私有数据。

界面刷新、送给模型的通知和启动新工作的触发器是三种不同用途。普通订阅或读取状态不唤醒 agent；触发器就是 [monitor](Monitor.md)，去重、预算与恢复语义以它为准。

### 5.5 上下文

上下文来源说明名称、来源和用途，业务场景确定可用变量，模板决定如何组织。历史保留当次定义与材料，不能用插件最新状态重建过去。

大段日志和 diff 通过工具按需读取；焦点、选择区、文件内容等外部观察不能悄悄覆盖基础指令。通知文字不能改变宿主决定的权限或执行配置。

## 6. 会话状态与业务生命周期

实例是否归档、线程是否执行、上一回合结果、恢复是否阻塞分别表达。`idle` 或没有窗口都不意味着可安全删除、回退或再次执行。读取历史与管理实例不应自动唤醒排队输入。

详细字段与控制规则只在 [会话状态机](会话状态机.md) 和 [会话显示协议](会话显示协议.md) 维护；终端和待办无需声明同一套 running、stopping 或 waitingForResume。

## 7. 运行位置与执行边界

Mac / iPhone / iPad 负责界面、输入和设备布局；工作机负责业务执行、持久状态、模型连接和工作区操作。断开客户端不自动结束工作机任务。Web 视图与工作机逻辑通过同一实例身份重新连接。

MCP 承载自定义工具和资源，MCP Apps 承载视图；Kite 补充工作区归属、实例生命周期、窗口与授权。协议和平台限制见 [Bun 插件](Bun插件.md)。

### 7.1 插件与 harness 共用操作系统沙箱

可信宿主管理模型连接、认证、实例与持久化。自定义 Bun 插件及 Kite 工具启动的命令受共同沙箱边界约束；不同实例分别绑定权限，不能合并成全局许可。用户在 App 里开的终端是用户自己的登录 shell，不加沙箱，相当于登录到这台工作机，与同账号设备已有的管理信任范围一致；它不是 agent 的工具，agent 不能借它扩权。agent 的命令只有整条匹配生效的沙箱外命令，或申请后经审批放行，才在沙箱外以用户身份运行，见 [工具审批与提问](工具审批与提问.md#审批)。

- 业务授权核验调用方、工作区、目标与操作；manifest、模型参数和网页消息不能扩权。
- 操作系统隔离限制进程及其后代的文件和网络访问，防止绕过宿主接口。
- 宿主内执行的 read、patch 也核验相同的有效资源授权。只限制 shell 不构成完整权限边界。
- 认证、数据库、会话记录和内部控制通道不向插件或模型工具开放。执行环境显式提供，并避免泄露宿主凭据。

默认允许 harness 工作区读写、必要工具链读取，网络关闭；插件默认仅访问安装代码和自己的临时空间，工作区能力经授权入口调用。Git 元数据只读，快照和采纳由宿主执行。目录、符号链接和工作树身份必须保持实际含义，不能因工具访问被拒就开放整个主目录。放行路径的各级上级目录可以打开、列出名字，读不到其中的文件，从根目录逐级打开路径的程序才能运行。

Claude 的原生 SDK 进程与 Kite 命令沙箱的覆盖范围不同，见 [Claude 接入边界](kited.md#claude-会话的上下文)，不能从工具受限推断整个 SDK 进程已隔离。

### 7.2 不可降级的执行约定

- 沙箱不可用、依赖缺失或隔离降级时拒绝执行，不回退到无沙箱模式。
- 撤回业务授权立即阻止后续调用；缩减已启动进程的操作系统权限前，须停止并确认旧执行结束，包括 agent 转到后台、仍在运行的命令。
- 权限变更通知只负责告知模型，不能替代权限执行。拒绝前可能已有副作用，放宽权限后不自动重放命令。
- 文件隔离、网络隔离、超时、CPU 和内存配额分别验证，不能以一种能力代替全部资源限制。

当前 macOS 使用 Seatbelt，Linux 适配使用 bubblewrap；Linux 实机行为、资源配额和脱离进程组的后台任务尚未完成验证或接入。授权编辑和停止确认见 [实例执行授权](实例操作.md#实例执行授权)。

## 扩展范围

当前不提供插件市场、热升级、旧协议迁移、任意表达式触发器或通用工作流编辑器。新增能力从具体插件需求出发，保持公共边界薄而明确。
