# 成果查看与位置

本文适用于 kited、kite-net 与 App，规定用户如何查看 agent 的工作成果：浏览（文件、运行中的网页与互联网）的定位、工作区外的文件、运行中网页的预览、原生 App 的查看，以及大文件与快照的关系。现行的引用格式见 [资源引用](资源引用.md)，浏览的接口见 [实例操作](实例操作.md#浏览)。

**状态：** 文件格式的第一批与静态 HTML、大文件不进快照已实现；网页视图组件与端口转发已实现；预览的目标模型（一个实例是产品一种运行方式的全部进程加画面）、模拟器改用 Xcode 自带的工具已实现（2026-10-22），待手测，模拟器的人看画面未截 DeviceHub 的窗口（见[预览](#预览)）；浏览里看运行中的网页与互联网、按快照看文件的历史版本已实现（2026-10-23），待手测；工作区外的文件、把正在看的一处带回对话尚未实现。

## 定位

- 与 agent 协作的过程是「描述需求、修改文件、查看成果」。文件系统首先是 agent 的工作材料，也是成果存放和被引用的地方；人不在文件系统里工作，人看成果是为了决定继续、回退、采纳或归档。
- Kite 不给人做文件管理器或 IDE。移动、重命名、整理交给 agent 或系统工具。
- 成果包括文件（文本、Markdown、图片、PDF、音视频、幻灯片与文档、HTML）、文件的变化、运行中的网页与原生 App，以及 agent 为证明结果产出的截图和录屏。
- 浏览是成果的查看器，文件与网页在同一个窗口里看。对文件，职责是三件事：显示目录、按格式预览文件的现状、按格式预览文件的变化。
  - 主入口是 agent 给出的引用；目录用来找 agent 没有指出的东西。
  - 变化按格式呈现：文本看差异，其他格式看前后两版。
  - 文件的历史版本取自工作区快照：文件内容变过的每一枚快照是一个版本，工作区开始时的内容算最早一版，按格式看当时的内容，只读。没进快照的文件没有历史版本。
  - 只读，修改经对话交给 agent；可以把正在看的某一处作为引用带回对话，开始下一轮需求。
- 运行中的网页不是文件，同样在浏览里看，见下文「运行中的网页」。浏览也能打开互联网上的网址，查资料、看文档不必离开 Kite。
- 系统已有的预览能力优先；Kite 自己只负责系统做不好或 Kite 特有的部分。

## 文件格式

| 格式 | 由谁呈现 | 可引用回对话的粒度 | 先后 |
|---|---|---|---|
| 文本与代码 | Kite，带行号 | 行范围 | 第一批 |
| 文本的差异 | Kite | 行 | 第一批 |
| Markdown | Kite：整篇渲染，显示相对路径的图片；作为成果打开时默认显示渲染结果 | 段落或行 | 第一批 |
| PDF | 系统的 PDF 组件 | 页 | 第一批 |
| 图片、幻灯片与文档、iWork、音频、短视频、CSV | 系统的通用预览 | 整个文件 | 第一批 |
| 静态 HTML | Kite：网页视图，相对资源从同一位置读取，页面与 App 隔离 | 整页 | 第二批 |
| 大视频 | 边下边播 | 时间点 | 第三批 |
| 非文本的变化 | 前后两版对照 | 整个文件 | 第三批 |

- 第一批的前提是按字节读取文件并按版本缓存；有了它，系统通用预览覆盖的格式不必逐一实现。
- 系统认不出的格式只显示大小、类型和修改时间；本机工作区可以用默认 App 打开，其他设备经系统分享交给别的 App。
- 不做编辑，也不做幻灯片逐页引用（需要在工作机上转换格式）。代码语法高亮以后再定。

## 工作区外的文件

**状态：** 已决定，尚未实现。

- NAS 这类存储不是 Kite 的概念，就是某台工作机上的普通目录：外置盘接在工作机上，或独立的 NAS 设备由工作机经系统挂载。Kite 不实现文件共享协议，不给目录命名，也不做换机提供。
- 人：浏览能看它所在工作机的整个文件系统，以运行 kited 的系统用户能读到的为准，不另设权限；打开时在工作区，可以一直往上翻。使用者是人，人在这台机器的终端里本来就能读到这些文件，只限制浏览不增加安全。
- 整台机器只对人开放：UI 的调用可以读工作区外的路径，获准的插件调用浏览的文件操作照旧限于工作区。
- agent：工作区外的目录按执行授权里的额外读写路径访问，read、patch 与 shell 都认；目录在某台工作机上不存在（没有这块盘、盘没接）时这条许可在那里不生效。不做跨机器的透明挂载，别的工作机上的目录 agent 碰不到，避免远程访问的延迟与失败藏进普通命令，也避免绕过授权。
- 引用：工作区里的文件按「工作区 + 路径（+ 版本）」寻址，跟随工作区换机；工作区外的文件按「工作机 + 绝对路径」寻址，固定在那台机器上。工作机按身份认，不按名字，名字会改、会重名。

两类文件的差别不隐藏，查看时如实标明：

| | 工作区 | 工作区外的目录（如 NAS） |
|---|---|---|
| 历史版本 | 快照中的文件有 | 没有 |
| 跟随工作区换机 | 是 | 否，固定在所在工作机 |
| 可用性 | 取决于执行所在的机器 | 取决于所在的机器与磁盘 |
| agent 访问 | 执行授权的工作区读写 | 执行授权的额外读写路径 |
| 写入者 | 工作区里的 agent | 多个工作区的 agent，以及 Kite 之外的程序 |

## 预览

**状态：** 已实现（2026-10-22），待手测，接口见 [实例操作 · 预览](实例操作.md#预览)。与下文不同的一处：在其他设备上实时看模拟器，现行用 simctl 截屏幕（约半秒一帧），没有截 DeviceHub 的窗口：屏幕在窗口里的位置读不稳，见 [实例操作 · 模拟器](实例操作.md#模拟器)。

- 一个预览实例是产品以某种方式跑起来的全部进程，加上看它的画面。「方式」叫目标，是项目 `.kite/preview/` 下的一个可执行文件：开发服务器、跑在模拟器上的 iOS App、Mac App、装到这台 iPhone，项目有几种运行方式就有几个目标，Kite 不另设分类。人在新建窗口里点选目标，agent 用 preview_open 起，两边得到的是同一种实例。
- 实例随进程存续，不随窗口：关窗口只是不看了，服务照跑；进程结束又没有窗口时回收。同一目标装到同一设备在一个工作区里同时只跑一份，再开就是打开已有的那个，重来用 restart。设备是装到哪台，只有要装 App 的目标有：iOS 装到 iPhone 模拟器和装到 iPad 模拟器是两组进程，算两个实例，要并排看就平铺两个窗口。设备从一张列表里选：模拟器型号，或与工作机配对过的真机；真机拿不到实时画面，只装包，装上后人拿起来用。
- 画面由目标产生什么决定，不由人选：进程树里有能打开网页的端口就是网页画面，脚本用了工作区的模拟器就是模拟器画面，起了带窗口的 Mac App 就是 App 窗口画面，什么都没有（比如装到真机）就只有输出。一个实例的视图是画面、并排与输出：并排只有网页有，同一组进程用几种浏览器、几种尺寸同时看；输出是进程的日志，画面没有时只剩它。
- 网页画面默认用设备自己的网页视图经端口转发打开，和[浏览](#运行中的网页)是同一个组件；也可以换成工作机上的浏览器（Chromium、Firefox、WebKit、Safari）把画面传过来。换的是看法，实例不变。agent 够不着设备上的网页视图，它操作的是工作机上的浏览器；并排视图里的几个画面和 agent 按同样参数开的浏览器是同一些页面。
- 人和 agent 走同一个循环：截一帧、做一个动作、等画面稳定、再截一帧；人在窗口里操作，agent 用 preview_action。模拟器和 App 窗口两边看的是同一块屏幕。
- 模拟器用 Xcode 自带的，Kite 只管给工作区分模拟器和回收：agent 的点按、截图与界面结构经 Xcode 的设备操作工具，人在其他设备上实时看时让 DeviceHub 开出这台模拟器的窗口再截它。Xcode 的这套工具只支持模拟器，Mac App 的窗口仍由 Kite 自己截，真机没有实时画面。
- 不变式：
  - 只有目标能把产品在沙箱外跑起来并成为预览；agent 起与主线不一致的目标要经审批，装到真机每次都要经审批。随手在终端里起的服务只能经浏览看，不成为预览实例。
  - 预览只操作本实例进程树里的端口、本实例用的模拟器和本实例起的 App 窗口。工作机上的浏览器联网不另设限制，同用户在工作机上自己开的浏览器：管住的是 agent 去哪（只开本实例端口上的路径），每个画面一个干净的浏览器上下文、不带用户的登录状态，kited 的接口自己挡浏览器里的页面；设备上的网页视图靠设备上的转发，见 [运行中的网页](#运行中的网页)。Mac App 的窗口在工作机的真实桌面上，只截这个窗口、只向这个进程发输入，不能借此控制整台工作机；要操作整台机器，交给系统的屏幕共享，Kite 只提供入口。
  - 等画面稳定期间收到的输入丢弃，不排队，免得在没看到的画面上操作。

## 运行中的网页

**状态：** 网页视图、端口转发已实现，转发不依赖窗口（2026-10-22）；浏览里看网页与互联网（2026-10-23），均待手测。接口见 [实例操作 · 运行中的网页](实例操作.md#运行中的网页) 与 [浏览](实例操作.md#浏览)。

- 运行中的网页是成果，需要跨设备查看。提供它的服务是一个进程：项目的运行方式做成预览的目标，宿主给每个工作区的每个目标分一段端口，并行的工作区互不抢端口；随手起的服务是一个终端实例，无论由 agent 的后台命令转来，还是用户在终端窗口里启动。终端的契约见 [实例操作 · 终端](实例操作.md#终端)。
- 终端与预览实例从自己的进程树探测正在监听的端口。设备打开着这个工作区期间，本工作区的端口在设备上自动转发，不要求开着任何窗口：Mac 上直接用自己的浏览器打开 `localhost:端口` 就行；iPhone、iPad 上 Kite 进后台就挂起，转发随之停，只能在 Kite 的窗口里看。
- 浏览里的网页在设备自己的网页视图里打开：本工作区的网页指向一个端口，路径、前进后退与滚动只在各自的设备上；也能开互联网上的网址，页面里的链接可以去任何地方。网站数据与 App 的其他网页分开、按工作区分开，同一工作区的浏览窗口共用登录状态。预览的网页画面在设备上看时用的是同一个组件；随手起的服务只能在浏览里看。以后在它上面加标记这类功能。
- 跨设备经端口转发：工作机的组网节点把组网上的同号端口转到工作机本机，只对同一用户的设备开放；保留站点的根路径，并按本机访问的方式转交请求：主机名保持页面所用的本机地址，开发服务器的绝对路径资源、自动刷新、主机检查与来源校验照常工作。设备在自己的回环地址（127.0.0.1 与 ::1）上为本工作区每个运行中实例监听的端口开同号转发，页面里嵌着或调用的另一个端口上的服务照工作机上的地址打开；同号被设备上别的程序占着时另分一个端口，指向原号的地址就打不开。网页视图的首页开在 127.0.0.1 上，不写 localhost，免得 ::1 上同号端口被设备上别的服务占着时打开错的页面。本机就是工作机时直接访问。
- 消息里的 `localhost:<端口>` 链接在所属工作区内解析：端口属于本工作区运行中的预览实例时打开它的网页画面，属于终端时打开这个端口的浏览窗口（没有就新建），都到链接的路径；否则明确报错。agent 不需要另外登记端口。消息里的外网链接也在浏览里打开：已有在看外网的浏览窗口就在它里面打开，没有就新建。
- 进程结束，或工作区交接、冻结、归档时，服务随终端或预览实例停止，进程不随工作区换机。浏览窗口不随服务停止而关闭，同一端口再被本工作区监听时接着显示。Kite 之外启动的服务不能看。
- 不变式：
  - 只转发本工作区仍在运行的终端与预览实例所监听的端口。kited 与 kite-net 自己的端口不在任何实例的进程树里，永不转发。
  - 网页是不可信内容，不能借用户的组网身份访问其他工作机或 kited 接口：网页视图不经组网代理，设备上的转发只通向这台工作机上本工作区的这些端口。本机的网页只按本工作区的端口打开；互联网上的地址同设备自己的浏览器，不另设限制。
  - 设备不为 kited 自己的端口开网页视图，页面也跳不进去：这个端口在本机和组网上本来就开着，网页开在它上面就与接口同源，能带上请求头调用接口。
- 浏览里的网页与静态 HTML、预览的网页画面共用同一个网页视图组件和隔离规则。
- 截图与录屏是证据：由 agent 产出并存进工作区，按图片和视频查看，可以离线看、前后对比，服务停掉后仍在。

## 原生 App

**状态：** 三档的显示方式都已实现：iOS App 跑在工作机的模拟器上、Mac App 的窗口，都在预览里看；Mac App 传到另一台 Mac 打开、iPhone 和 iPad 推装已实现，点链接安装尚未实现。装到模拟器、装到设备都由预览的目标完成，在新建窗口的设备列表里选。

- 原生 App 没有端口可转。构建与安装由预览的目标完成，Kite 负责把 App 交到看的人面前。
- 怎么显示由打开视图的那台设备各自决定，同一个 App 可以同时在几台设备上用不同方式看。agent 主动交给用户看时，按 Line 记录的关注设备选默认方式。
- 按顺序取第一个可行的：
  1. 看的设备就是工作机：Mac App 直接运行；iOS、安卓 App 跑在工作机的模拟器上，直接看模拟器自己的窗口（iOS 是 DeviceHub）。
  2. 看的设备与 App 同平台：用分发包装到这台设备。Mac App 把 .app 传过去打开：工作机打包 App 窗口里那个 App，那台 Mac 上的 kited 解开、打开；iPhone、iPad 由工作机推装（设备要配对过，连线或在同一局域网）：在任一台设备上点选装 App 的目标，从配对过的设备里选这台（在它自己上面点时默认选中），宿主把它交给脚本，构建与安装由脚本完成；或者设备点链接安装（设备要登记在开发证书里）。Kite 没有安卓版，安卓 App 没有这一档。
  3. 其他情况：App 跑在工作机上（模拟器，或 Mac App 的窗口），经预览视图远程看和操作。链路够快时用实时画面，慢时逐帧：做一个动作，等画面稳定后再给一帧。实时还是逐帧按链路快慢定，不按平台定。

## 大文件

- 单个文件超过 10 MiB、且未被项目 Git 跟踪的，不进工作区快照：与被忽略的文件一样，回退不碰，不随副本流转，没有历史版本。项目已经跟踪的文件不受此限。
- 项目规则指定了放大文件的目录（如 NAS）且执行授权允许写入时，agent 把大文件成果写到那里；没有时留在工作区，查看器标明没有历史版本。目录写在项目规则里，不另设机制。
- 原因：快照在每批工具调用后进行，agent 等它完成；已压缩的媒体在 Git 中每改一次就全量保存一份，并随副本同步到其他工作机。
- 10 MiB 让截图、PDF 报告和一般的幻灯片留在快照里保有版本，视频、数据集和嵌入视频的幻灯片放到项目指定的大文件目录。

## 待定

- 引用的具体写法，以及现有 `kite://file` 链接的迁移。
- 成果变化后查看器自动刷新，依赖尚未设计的文件观察来源。
- 人从工作区外带一个文件引用回对话，而 agent 没有它的读许可时怎么处理。
- 单批快照里多个中等文件累计过大时，是否另设总量上限。
- 预览作为测试平台：并排视图按浏览器环境与尺寸铺开，Apple 一侧模拟器能看能点，真机只在设备列表里、选了装包，安卓以后再说；标准的界面测试流程写成项目里的测试脚本（Playwright、XCUITest 或 Maestro），由预览在选定的环境上跑并把每步截图排出来。这是假设，先让一个测试 agent 在一个项目上试一轮再定做多重。
- Mac App 传到另一台 Mac 打开、iOS 包传到另一台 Mac 的模拟器里跑，是留在 App 窗口画面上，还是改成文件的通用动作。

## 与现行文档的关系

- [资源引用](资源引用.md) 现行的 `kite://file` 带 `machine` 字段，并且只支持工作区文件；实现本文后，工作区文件按工作区寻址、工作区外的文件按工作机与绝对路径寻址，资源引用随之更新。
- [实例操作 · 浏览](实例操作.md#浏览) 现行的文件操作与字节接口拒绝工作目录外的路径；实现后 UI 的调用可以读整台机器，获准插件的调用照旧限于工作区。
- [实例操作 · 实例执行授权](实例操作.md#实例执行授权) 现行的额外路径只经 shell 使用，read 与 patch 限于工作区；实现后两者也认额外读写路径。
- 端口探测与链接解析的接口见 [实例操作 · 运行中的网页](实例操作.md#运行中的网页)，浏览的接口见 [实例操作 · 浏览](实例操作.md#浏览)，预览插件与目标的接口见 [实例操作 · 预览](实例操作.md#预览)。
