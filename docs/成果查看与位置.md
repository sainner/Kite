# 成果查看与位置

本文适用于 kited、kite-net 与 App，规定用户如何查看 agent 的工作成果：文件插件的定位、跨机器的文件寻址、运行中网页的预览、原生 App 的查看，以及大文件与快照的关系。现行的引用格式见 [资源引用](资源引用.md)，文件操作接口见 [实例操作](实例操作.md#文件插件)。

**状态：** 文件格式的第一批与静态 HTML、大文件不进快照已实现；网页视图组件与端口转发已实现，网页现由终端的网页视图打开；终端的预置脚本、预览插件（网页改归它，加上模拟器与 App 窗口）、位置与寻址、把正在看的一处带回对话尚未实现。

## 定位

- 与 agent 协作的过程是「描述需求、修改文件、查看成果」。文件系统首先是 agent 的工作材料，也是成果存放和被引用的地方；人不在文件系统里工作，人看成果是为了决定继续、回退、采纳或归档。
- Kite 不给人做文件管理器或 IDE。移动、重命名、整理交给 agent 或系统工具。
- 成果包括文件（文本、Markdown、图片、PDF、音视频、幻灯片与文档、HTML）、文件的变化、运行中的网页与原生 App，以及 agent 为证明结果产出的截图和录屏。
- 文件插件是文件类成果的查看器，职责是三件事：显示目录、按格式预览文件的现状、按格式预览文件的变化。
  - 主入口是 agent 给出的引用；目录用来找 agent 没有指出的东西。
  - 变化按格式呈现：文本看差异，其他格式看前后两版。
  - 只读，修改经对话交给 agent；可以把正在看的某一处作为引用带回对话，开始下一轮需求。
- 运行中的网页不是文件，不归文件插件，见下文「运行中的网页」。
- 系统已有的预览能力优先；Kite 自己只负责系统做不好或 Kite 特有的部分。

## 文件格式

| 格式 | 由谁呈现 | 可引用回对话的粒度 | 先后 |
|---|---|---|---|
| 文本与代码 | Kite，带行号 | 行范围 | 第一批 |
| 文本的差异 | Kite | 行 | 第一批 |
| Markdown | Kite：整篇渲染，显示相对路径的图片；作为成果打开时默认显示渲染结果 | 段落或行 | 第一批 |
| PDF | 系统的 PDF 组件 | 页 | 第一批 |
| 图片、幻灯片与文档、iWork、音频、短视频、CSV | 系统的通用预览 | 整个文件 | 第一批 |
| 静态 HTML | Kite：网页视图，相对资源从同一位置读取，页面与 App 隔离 | 整页 | 第二批 |
| 大视频 | 边下边播 | 时间点 | 第三批 |
| 非文本的变化 | 前后两版对照 | 整个文件 | 第三批 |

- 第一批的前提是按字节读取文件并按版本缓存；有了它，系统通用预览覆盖的格式不必逐一实现。
- 系统认不出的格式只显示大小、类型和修改时间；本机工作区可以用默认 App 打开，其他设备经系统分享交给别的 App。
- 不做编辑，也不做幻灯片逐页引用（需要在工作机上转换格式）。代码语法高亮以后再定。

## 位置与寻址

- **位置**是有名字的根目录，由一台工作机提供；路径相对于位置。工作区是一种位置，它的身份是工作区本身，跟随执行权所在的机器。用户可以另外设立命名位置，例如 `nas`。
- 引用的身份是「位置 + 路径（+ 版本）」。机器名不承担身份：它会改、会重名，工作区也会换机。位置改由另一台机器提供时，引用不变。
- 不开放任意绝对路径。每台机器只提供显式设立的位置，宿主保护目录与凭据始终不可读。
- 独立的 NAS 设备由工作机经系统挂载，成为那台机器上的一个位置；Kite 不实现文件共享协议。

寻址统一，各类位置的差别不隐藏，查看时如实标明：

| | 工作区 | 命名位置（如 NAS） |
|---|---|---|
| 历史版本 | 快照中的文件有 | Kite 不提供 |
| 跟随工作区换机 | 是 | 否 |
| 可用性 | 取决于执行所在的机器 | 取决于提供它的机器与磁盘 |
| 写入者 | 工作区里的 agent | 可能多台机器的多个 agent |

人与 agent 的取用方式不同：

- 人：查看器经提供方的 kited 读取，任何位置都用同一种引用。
- agent：工具和 shell 只认本机文件系统。位置就在本机时，它是一个本地路径，按执行授权读写；位置在别的机器时，显式复制进工作区（取用）或复制出去（发布）。不做透明的远程挂载，避免远程访问的延迟与失败藏进普通命令，也避免绕过授权。

## 预览

**状态：已决定，尚未实现。** 第一步把网页从终端移过来，同时做模拟器和工作机上能在后台跑的浏览器（Chromium、Firefox、WebKit）；Mac App 的窗口、Safari 与分发包在后，Safari 没有无界面模式，要像 Mac App 那样截它的窗口。

- 跑与看分开：服务和 App 的进程归终端（含预置脚本），看归预览插件。一个预览实例是一个要看的对象，分三种：网页（本工作区的一个端口加路径）、模拟器（宿主为工作区开的一台）、App 窗口（预置脚本起的一个 Mac App 的窗口）。
- 预览指向要看的对象，不指向起它的终端：一个页面可以用到几个终端的端口，一个终端的几个页面可以并排看；预置脚本重启后端口不变，开着的网页预览接着用。
- 人和 agent 走同一个循环：截一帧、做一个动作、等画面稳定、再截一帧；人在预览视图里操作，agent 用 computer use 工具。模拟器和 App 窗口两边看的是同一块屏幕。
- 网页有两种看法：
  - 设备自己的网页视图，是默认：经端口转发打开，滚动、选字与开发者工具照常。agent 够不着设备上的网页视图，它在工作机的 WebKit 里打开同一个地址，与设备上的内核一致，但不是同一个浏览器，登录状态、滚动位置各自保存。
  - 工作机上的浏览器：Chrome（Chromium）、Firefox、WebKit、Safari 任选，画面照模拟器的方式显示，实时或逐帧。人和 agent 操作的是同一个页面。
  - 同一个地址可以开几个预览，各用不同的看法并排对比。iPhone、iPad 上的 Safari 用模拟器预览打开这个地址。
- 不变式：
  - 预览只操作本工作区运行中终端监听的端口、宿主为工作区开的模拟器和预置脚本起的 App 窗口。工作机上的浏览器和设备上的网页视图守同一条边界，只通向本工作区运行中终端的端口：前者的请求经宿主的代理，碰不到 kited 与 kite-net 的端口；后者靠设备上的转发，见 [运行中的网页](#运行中的网页)。Mac App 的窗口在工作机的真实桌面上，只截这个窗口、只向这个进程发输入，不能借此控制整台工作机；要操作整台机器，交给系统的屏幕共享，Kite 只提供入口。
  - 等画面稳定期间收到的输入丢弃，不排队，免得在没看到的画面上操作。
- 接口见 [实例操作 · 预览](实例操作.md#预览)。

## 运行中的网页

**状态：** 端口探测、端口转发与网页视图组件已实现；网页改由预览插件打开尚未实现，现行实现是终端的网页视图，接口见 [实例操作 · 运行中的网页](实例操作.md#运行中的网页)。

- 运行中的网页是成果，需要跨设备查看。提供它的服务是一个进程，归终端插件：开发服务器就是一个终端实例，无论由 agent 的后台命令转来，还是用户在终端窗口里启动。项目反复要起的服务做成终端的预置脚本，宿主给每个工作区的每个脚本分一段端口，并行的工作区互不抢端口。终端的契约见 [实例操作 · 终端](实例操作.md#终端)。
- 终端实例从自己的进程树探测正在监听的端口。看网页用网页预览，它指向本工作区的一个端口和路径；设备用自己的网页视图经端口转发打开，页面内的跳转、滚动与登录状态按设备各自保存。
- 跨设备经端口转发：工作机的组网节点把组网上的同号端口转到工作机本机，只对同一用户的设备开放；保留站点的根路径，并按本机访问的方式转交请求：主机名保持页面所用的本机地址，开发服务器的绝对路径资源、自动刷新、主机检查与来源校验照常工作。网页视图打开期间，设备在自己的回环地址（127.0.0.1 与 ::1）上为本工作区每个运行中终端监听的端口开同号转发，页面里嵌着或调用的另一个端口上的服务照工作机上的地址打开；同号被设备上别的程序占着时另分一个端口，指向原号的地址就打不开。网页视图的首页开在 127.0.0.1 上，不写 localhost，免得 ::1 上同号端口被设备上别的服务占着时打开错的页面。本机就是工作机时直接访问。
- 消息里的 `localhost:<端口>` 链接在所属工作区内解析：端口属于本工作区仍在运行的终端实例时，打开这个端口的网页预览（没有就新建）并到链接的路径，否则明确报错。agent 不需要另外登记端口。
- 进程结束，或工作区交接、冻结、归档时，服务随终端停止，进程不随工作区换机。网页预览不随服务停止而关闭，同一端口再被本工作区的终端监听时接着显示。Kite 之外启动的服务不能预览。
- 不变式：
  - 只转发本工作区仍在运行的终端实例所监听的端口。kited 与 kite-net 自己的端口不在任何终端的进程树里，永不转发。
  - 网页是不可信内容，只能访问本工作区运行中终端监听的端口，不能借用户的组网身份访问其他工作机或 kited 接口：网页视图不经组网代理，设备上的转发只通向这台工作机上的这些端口。
  - 设备不为 kited 自己的端口开网页视图：这个端口在本机和组网上本来就开着，网页开在它上面就与接口同源，能带上请求头调用接口。
- 网页预览与文件插件的静态 HTML 共用同一个网页视图组件和隔离规则。
- 截图与录屏是证据：由 agent 产出并存进工作区，按图片和视频查看，可以离线看、前后对比，服务停掉后仍在。

## 原生 App

**状态：已决定，尚未实现。** 顺序见 [预览](#预览)。

- 原生 App 没有端口可转。构建与安装由终端的预置脚本完成，Kite 负责把 App 交到看的人面前。
- 怎么显示由打开视图的那台设备各自决定，同一个 App 可以同时在几台设备上用不同方式看。agent 主动交给用户看时，按 Line 记录的关注设备选默认方式。
- 按顺序取第一个可行的：
  1. 看的设备就是工作机：Mac App 直接运行；iOS、安卓 App 跑在工作机的模拟器上，在预览视图里实时显示。
  2. 看的设备与 App 同平台：用分发包装到这台设备。Mac App 把 .app 传过去打开；iPhone、iPad 由工作机推装（设备要配对过，连线或在同一局域网），或者设备点链接安装（设备要登记在开发证书里）。Kite 没有安卓版，安卓 App 没有这一档。
  3. 其他情况：App 跑在工作机上（模拟器，或 Mac App 的窗口），经预览视图远程看和操作。链路够快时用实时画面，慢时逐帧：做一个动作，等画面稳定后再给一帧。实时还是逐帧按链路快慢定，不按平台定。

## 大文件

- 单个文件超过 10 MiB、且未被项目 Git 跟踪的，不进工作区快照：与被忽略的文件一样，回退不碰，不随副本流转，没有历史版本。项目已经跟踪的文件不受此限。
- 有可用的命名位置时，agent 把大文件成果写到那里；没有时留在工作区，查看器标明没有历史版本。
- 原因：快照在每批工具调用后进行，agent 等它完成；已压缩的媒体在 Git 中每改一次就全量保存一份，并随副本同步到其他工作机。
- 10 MiB 让截图、PDF 报告和一般的幻灯片留在快照里保有版本，视频、数据集和嵌入视频的幻灯片走命名位置。
