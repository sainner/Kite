# 界面设计原则

适用于 Kite 各端的原生界面与公共容器。本文只记录设计取舍，具体呈现以实现和用户预览为准。

界面保持安静，让内容、任务和必要状态优先获得注意。视觉表达服务于信息含义，不以装饰制造新的业务状态，也不暗示无法验证的进度或结果。

同类能力共享一致的表达与操作语义。公共行为由公共组件承担，避免各个窗口和插件分别形成一套约定。

一种界面场景只有一个视图，各处只给数据。场景按用户怎么认来划：用户看作同一种东西、做同样的操作期待同样反应的，就是同一种场景，例如窗口、弹窗、多页弹窗。两处只差显示什么（标题、字段、按钮文字）时，差的是数据；结构或行为本身不同（窗口能拖、能收进停靠栏，弹窗不能）才是不同的场景。场景可以分层，多页弹窗是弹窗的一种，单页是只有一页的情形；不按业务细分，「实例配置弹窗」只是一份数据，也不粗到「所有界面」。准备写第二处同样的结构，或同一个行为要在几处各写一遍时，就该认出场景：已有那种场景的视图就用它，没有就先建出来，再在各处给数据。各处各拼一套时，用户眼里的同一种东西表现不一，换内容也只能整块替换，没有原地过渡。

跨端保持同一产品语义，同时尊重设备空间、输入方式和系统习惯。可读性、可访问性和用户的阅读控制优先于视觉效果，系统辅助功能不应损害信息完整性。

窗口内容只有宽、窄两种排法。紧凑布局里的窗口都按窄排；平铺布局里窗口窄到一定宽度时也按窄排，排出来和紧凑布局里一模一样，不为窄的平铺窗口另做第三种。横滑换窗口、共用标题栏这类外壳行为只随布局变，不随窗口宽度变。

App 与工作机、实例和窗口之间的职责见 [App 设计原则](App.md) 与 [产品架构](产品架构.md)。
