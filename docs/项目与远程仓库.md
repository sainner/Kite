# 项目与远程仓库

本文适用于 kited 与 App，规定项目身份、检出、没有远程的项目和工作区集成的职责。对象关系见 [产品架构](产品架构.md#对象与归属)，项目登记表与凭据的接口见 [工作机](kited.md#账号级数据)，工作区操作与错误语义见 [工作机](kited.md#工作区与线程的生命周期)。

## 项目身份

项目登记表是账号级数据，在工作机之间同步。项目 ID 由先登记它的工作机生成，此后不变。

- 有远程的项目以远程为身份：远程地址按 `域名/owner/repo` 归一化，SSH 与 HTTPS 写法指向同一项目；不同工作机上 clone 了同一远程的目录自动归入同一项目，本机登记以 origin 为准。两台工作机没同步上时各自登记了同一远程，同步后按登记先后合并，保留最早的，另一台的检出改挂过去。
- 没有远程的文件夹登记为没有远程的项目，以 ID 为身份，各工作机上的检出互为远程，不需要另外准备 Git 平台账号也能多机协作。之后可以给它设远程，项目 ID 不变。
- 远程是用户自有平台（GitHub、GitLab 等）上的仓库；Kite 不托管仓库。

## 检出

检出是某台工作机上项目的一份 clone，包含所属工作机、根目录和主线分支。在另一台工作机上添加检出即 clone：有远程的从远程 clone，默认放在 `~/code/<域名>/<owner>/<repo>`；没有远程的从在线、有它检出的工作机 clone，默认放在 `~/code/<项目名>`。添加时可以改位置。

## 添加项目

| 入口 | 行为 |
|---|---|
| 远程地址 | 填写地址或从已绑定账号的仓库中选择，选定工作机后 clone 并登记 |
| 本地文件夹，已有远程 | 读取远程地址，归入对应项目并登记 |
| 本地文件夹，没有 Git 仓库或没有远程 | 必要时由 Kite 初始化仓库并提交初始版本，登记为没有远程的项目 |

## 没有远程的项目

各工作机上的检出互为远程：kited 在组网上只读地提供本机检出的 Git 智能 HTTP，只接受同一用户的工作机，不接受推送。

- 主线只做快进：项目同步时从有它检出的其他工作机拉取全部分支，本机主线干净且落后就快进；两边都有新提交时不合并，提示用户在工作区里集成，与有远程时远程领先且分叉的处理一致。
- 采纳只合回本机主线，现场「提交并推送」只提交，其他工作机同步时快进过来。
- 设远程：在一台有检出的工作机上把全部分支和标签推到用户给的远程，加上 origin，写进登记表；其他工作机的检出随项目同步加上 origin，此后与有远程的项目一样。远程须是空的或与本机同一段历史，推送被拒时不改登记表。

## 工作区与集成

普通工作区由一个工作树和一个本地分支组成。

- 集成由用户触发。kited 把工作区分支合进检出主线，再推送到远程。冲突留在工作区，主目录不进入冲突状态。
- 推送被拒时，拉取远程主线，重新合并后再推送；冲突交给该工作区中的 agent 解决。
- 集成后工作区与线程仍可继续使用，用户可以多轮讨论后再次集成。工作区归档后才进入回收流程。

根工作区是特例，即检出现场：直接编辑检出目录，没有独立分支，不经历普通工作区的集成与回收。现场完全由用户自己控制，Kite 不自动提交现场改动；唯一的例外是 Line 的项目，宿主在 Line 的回合结束与交接前提交并推送现场，见 [Line](Line与工作区流转.md#line)。现场有未提交的改动时，阻止普通工作区集成。App 为现场提供由用户触发的「提交并推送」；远程领先且两边分叉时不在现场合并，提示用户新建工作区处理。

## 远程里的 Kite 引用

除分支与标签外，Kite 在项目远程上只用一类引用：`refs/kite/lease/<工作区>`，流转过的工作区的执行权，记录当前持有的工作机与 `epoch`，读取权限就是仓库权限。会话记录与快照不推到项目远程，由工作机之间的工作区副本跟进。

工作机本机的检出里还有：`refs/kite/snapshots/<工作区>`（快照链）、`refs/kite/peers/<工作机>/`（没有远程的项目从其他工作机拉到的分支）、`refs/kite/replica/<工作区>/`（跟进别的工作机上的工作区时取到的快照链与分支）。日常的拉取、推送与集成不读写这些引用；约定见 [工作区流转](Line与工作区流转.md#工作区流转)。

## 凭据

- 凭据是账号级数据，Git 授权、通用密钥、模型 API Key 与语音识别 Key 在工作机之间同步、落地加密，按类型区分取用方式。Git 凭据在一台工作机上绑定，各工作机都能用，不必逐台配置。
- 用户自有平台通过 OAuth 授权或填写 token 绑定。GitHub 不接受用账号密码访问 API 与 Git，使用 OAuth App 的设备码授权，在工作机上完成，token 不经过 App；`repo` 权限覆盖该 GitHub 账号下的全部仓库。其他平台手填 token。
- 通用密钥分账号共享与项目专用两种范围，供相应范围内的 agent 共用。模型只获得名称、类型与 `{account.api_key}`、`{project.ssh_key}` 这类引用，宿主在执行时注入。凭据不作为模型参数、上下文或工具结果传递；带凭据的命令隐藏全部输出。管理与执行契约见 [凭据](kited.md#凭据)。
- 模型 API Key 当前供工作机查询额度与调用 token 计数接口；保存 Key 不会自动把会话切到 API 后端。订阅登录仍由各工作机自行完成，不算凭据。
