# App 设计原则

Mac、iPhone 和 iPad 共用原生 App，负责用户输入、内容呈现和工作机连接。业务执行、持久状态与权限由工作机管理；工程配置、构建和预览入口见 [App README](../app/README.md)。

## 连接与工作区

项目、检出和工作区构成统一的跨机器目录，操作始终路由到工作区所属机器。机器身份独立于网络地址，不能因地址复用而操作错误的工作机。

托管目录与本地缓存用于发现和浏览，实时内容以所属工作机为准。单台机器离线不影响其他机器，目录过时不等于对象已删除；旧连接的迟到响应不能覆盖新状态。退出账号清除该账号的本地连接与目录状态。

状态按来源分层呈现。账号层的问题由全局入口表达，不写进单个窗口；窗口同一时刻只突出一项状态：所属工作机的连接优先于窗口自身的错误，错误又优先于平时的状态信息。同一种连接状态在各处使用同一判断和措辞。

对象归属见 [产品架构](产品架构.md)，登录、设备角色和授权见 [托管账号与设备](托管账号与设备.md)，项目身份与 Git 操作边界见 [项目与远程仓库](项目与远程仓库.md)。

## 跨端呈现与生命周期

各端共享工作区中的实例和窗口身份，本机呈现状态由设备独立管理。重连以工作机的当前对象集合为准，本地状态不能复活已关闭或回收的对象。

窗口、实例和执行进程分别管理生命周期。关闭窗口不等于停止任务，断线不等于执行结束；实例是否回收取决于其生命周期。后台实例即使没有窗口，也必须仍可管理。

停靠栏是本机找回实例的入口，按类别、有没有窗口和是否需要用户处理来呈现：代理在前，由 agent 创建的子代理挂在创建它的代理下面，用户不必逐个打开；没有窗口的代理集中收纳。后台代理的运行与结果在这里可见，不依赖打开它的窗口；「完成待查看」只在本机记录，不跨设备同步。

公共容器承担跨内容类型的一致行为，插件提供自己的业务内容与动作。跨端保持相同的业务语义，并适应设备空间、输入方式和系统辅助功能；公共设计原则见 [界面设计原则](视觉风格.md)。

## 会话与控制

会话操作以工作机声明的能力和状态为准。消息接收、纳入模型请求、执行结束分别确认，重试不能产生重复输入；停止和恢复须保留用户尚未交给模型的内容，不能把连接中断当作操作成功。

当前执行阶段、上一回合结果、恢复阻塞和客户端连接状态分别表达。新建会话、读取历史和确认恢复本身不启动模型；执行控制与消息交接以 [会话状态机](会话状态机.md) 为主来源。

模型、工具、上下文和授权各有独立含义。新代理先选角色，再在角色允许的范围内调整；模型只按厂商分类，不单独选择后端。配置变更遵守后端声明的生效边界，版本冲突不能静默覆盖用户修改，选择工具或修改角色、模板不能扩大权限。角色的分层见 [Agent 与插件契约](Agent与插件契约.md#32-角色与代理配置)，生效规则见 [线程通知投递](线程通知投递.md) 与 [上下文模板](harness-上下文组装.md)。

## 内容与执行事实

正文、思考、工具参数与工具结果保留各自身份和来源。呈现不能修改用户原文，也不能把参数草稿当作已执行的调用，或从模型文字推断文件已经修改。

结果未知、部分完成和内容截断必须如实表达。耗时、修改量和上下文占比只能使用可靠数据，不能为补齐界面而猜测。流式内容的完整性以 [会话流式展示](会话流式展示.md) 和 [会话显示协议](会话显示协议.md) 为准。

## 插件与资源边界

插件定义、工作区实例和视图是不同对象。原生内容与自定义视图共用实例和授权边界，网页不能接触宿主凭据或自行改变工作机与实例归属。错误和重连不得触发有副作用操作的自动重放，契约见 [Agent 与插件契约](Agent与插件契约.md) 和 [Bun 插件](Bun插件.md)。

资源引用描述稳定内容及定位，窗口只是呈现入口。历史差异不随当前文件变化；共享内容选择与设备本地阅读状态分开管理，格式与身份见 [资源引用](资源引用.md)。
