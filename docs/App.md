# App 设计原则

本文适用于 Mac、iPhone 和 iPad 共用的原生 App，说明客户端职责与状态边界。App 负责用户输入、内容呈现和工作机连接；业务执行、共享持久状态与权限由工作机管理。工程配置、构建和预览入口见 [App README](../app/README.md)。

## 连接与工作区

项目、检出和工作区构成统一的跨机器目录，操作始终路由到工作区所属机器。机器身份独立于网络地址，不能因地址复用而操作错误的工作机。

工作机目录与本地缓存用于发现和浏览，实时内容以所属工作机为准。目录摘要、项目外观、项目约束与凭据都经任一台连着的工作机读写，见 [工作机](kited.md#账号级数据)。单台机器离线不影响其他机器，目录过时不等于对象已删除；旧连接的迟到响应不能覆盖新状态。退出账号清除该账号的本地连接与目录状态。

账号、工作机连接和实例执行的状态保留各自来源，不能把一层的问题当作另一层的状态。同一种连接状态在各处使用同一判断和措辞。

对象归属见 [产品架构](产品架构.md)，登录、设备角色和授权见 [身份与设备](身份与设备.md)，项目身份与 Git 操作边界见 [项目与远程仓库](项目与远程仓库.md)。

## 跨端呈现与生命周期

各端共享工作区中的实例和窗口身份，本机呈现状态由设备独立管理。重连以工作机的当前对象集合为准，本地状态不能复活已关闭或回收的对象。

本机发起的操作当场在界面上生效、开始过渡，不等工作机往返：身份能由本机预先确定的对象（如本机生成 ID 的窗口）先按本机结果呈现，工作机确认后按同一身份接上，失败再收回并说明原因。读历史、刷新目录、排长内容这类工作排在过渡开始之后或分批完成，不能推迟动作的第一帧，也不能打断进行中的过渡。先行呈现不改变归属，工作机仍是对象集合的权威来源。

窗口、实例和执行进程分别管理生命周期，规则见 [实例与窗口契约](Agent与插件契约.md#33-plugininstance工作区中的业务对象)。客户端连接或窗口的变化不能被当作执行结束。

后台实例的运行与结果不依赖窗口才能被发现和管理；「完成待查看」属于本机阅读状态，不跨设备同步。创建来源用于呈现协作关系，不改变实例的工作区归属。

公共容器承担跨内容类型的一致行为，插件提供自己的业务内容与动作。跨端保持相同的业务语义，并适应设备空间、输入方式和系统辅助功能；公共设计原则见 [界面设计原则](视觉风格.md)。

## 会话与控制

会话操作以工作机声明的能力和状态为准。消息接收、纳入模型请求、执行结束分别确认，重试不能产生重复输入；停止和恢复须保留用户尚未交给模型的内容，不能把连接中断当作操作成功。

当前执行阶段、上一回合结果、恢复阻塞和客户端连接状态分别表达。新建会话和读取历史不启动模型，恢复确认随发送、继续等用户操作带出，不单独成为一步；执行控制与消息交接以 [会话状态机](会话状态机.md) 为主来源。

模型、工具、上下文和授权各有独立含义。代理配置遵守 [角色约束](Agent与插件契约.md#32-角色与代理配置) 和后端声明的生效边界；版本冲突不能静默覆盖用户修改，选择工具或修改提示词不能扩大权限。配置通知见 [线程通知投递](线程通知投递.md)，上下文编辑见 [上下文模板](harness-上下文组装.md)。

## 内容与执行事实

正文、思考、工具参数与工具结果保留各自身份和来源。呈现不能修改用户原文，也不能把参数草稿当作已执行的调用，或从模型文字推断文件已经修改。

结果未知、部分完成和内容截断必须如实表达。耗时、修改量和上下文占比只能使用可靠数据，不能为补齐界面而猜测。内容完整性与流式呈现以 [会话显示协议](会话显示协议.md) 为准。

## 插件与资源边界

插件定义、工作区实例和视图是不同对象。原生内容与自定义视图共用实例和授权边界，网页不能接触宿主凭据或自行改变工作机与实例归属。错误和重连不得触发有副作用操作的自动重放，契约见 [Agent 与插件契约](Agent与插件契约.md) 和 [Bun 插件](Bun插件.md)。

资源引用描述稳定内容及定位，窗口只是呈现入口。历史差异不随当前文件变化；共享内容选择与设备本地阅读状态分开管理，格式与身份见 [资源引用](资源引用.md)。
