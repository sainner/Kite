# 会话流式展示原则

正文、思考、工具参数和执行输出各有独立含义，同一条记录从生成到定稿保持身份。本文说明内容完整性与执行事实的边界；事件、字段和重连契约见 [会话显示协议](会话显示协议.md)。

## 生成与执行分开

正文定稿不表示工具完成，工具完成不表示回合结束，断流不能作为成功依据。上游只提供完整条目时，不能虚构中间的生成或执行过程。

工具参数完整且通过校验后才能执行。参数生成、等待执行、执行中和结果必须可区分；取消未启动的调用与停止已启动的调用采用不同的结果语义。部分写入、失败和结果未知如实保留。

思考属于独立的生成内容，不能从会话运行状态推断正在思考，也不改变工具批次与执行结果的含义。

## 内容完整与阅读连续

增量与最终条目合并后不重复、不遗漏，最终内容应与完整原文一致。未完成的 Markdown 仍须可阅读，呈现变化不能改变原始文字、引用目标或执行事实。

执行输出允许有明确边界的截断，但必须标明；显示的内容不能冒充完整日志。耗时与进度只采用可靠来源。

内容更新保持阅读连续，尊重用户当前的阅读意图。

## 重连与恢复

重连以工作机当前状态为准，旧连接的迟到更新不能覆盖新状态。服务重启只恢复可靠保存的内容，未完成草稿可能消失；未收尾的执行按恢复规则核查，不伪造终态。

## 验证边界

内容合并、参数交接、取消、持久化和重连需要跨层运行验证。界面观感不能证明这些行为正确，运行入口见 [手动验证](../kited/test/manual/README.md)。历史测量保留在 [实验记录](research/2026-09-29-streaming-validation.md)。
