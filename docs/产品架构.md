# Kite 产品架构

本文适用于 App 与工作机，维护产品对象、职责边界和扩展约束。具体接口与开发入口见 [文档索引](README.md)。

## 产品形态

Kite 是 Mac、iPhone 和 iPad 上的个人 agent 工作台，后台服务 kited 运行在工作机。用户选择项目和工作区，在同一处查看会话、文件、差异和插件窗口，让 agent 处理任务，再决定继续、回退、采纳或归档。

产品目标是让 agent 自己推进，把重要决定留给用户，并保留可回看的依据。原生界面负责交互；模型、文件、执行和持久状态由工作机管理。

## 对象与归属

```text
项目（远程仓库，或没有远程时的项目 ID）
└── 检出（所属工作机上 Kite 的裸仓库，按需产生）
    └── 工作区（工作树 + 本地分支）
        ├── 插件实例：agent、文件、待办等
        └── 共享窗口：呈现实例的某个视图
```

这是用户导航的层级：同一项目可以包含不同工作机上的检出，打开工作区时由其检出确定操作目标，无需先选定一台工作机才能浏览项目。工作机是检出、文件与执行的归属，不是项目总览的前置筛选。

各工作机的目录摘要在工作机之间同步，App 从任一台连着的工作机读目录并缓存，直连所属工作机取得实时内容、执行操作。单台机器离线不影响其他机器；目录缓存和客户端连接中断不改变工作机上的任务状态。

工作机是其业务数据的权威来源。资源库、项目登记、项目约束与凭据是所有工作机共有的账号级数据，在工作机之间同步，见 [分布式架构](分布式架构.md#数据的归属与同步)。Kite 不运营服务器：身份与组网交给 Tailscale，见 [身份与设备](身份与设备.md)；没有服务器保存会话正文、文件内容、插件实例配置或模型凭据，也没有服务器转发任务执行。

有远程的项目以远程仓库为身份，多机之间经由远程同步；没有远程的项目各工作机上的检出互为远程，Git 凭据随账号级数据在工作机之间同步。工作区的执行记录与会话正文不进项目远程，由执行它的工作机写，其他工作机以工作区副本跟进，流转时只递执行权，见 [项目与远程仓库](项目与远程仓库.md) 与 [工作区流转](Line与工作区流转.md#工作区流转)。

| 对象 | 负责什么 | 不随什么变化 |
|---|---|---|
| 工作机 | 服务身份、本机目录与执行 | 网络地址变化不应改变已有身份 |
| 项目 | 以远程仓库为身份，没有远程的以项目 ID 为身份；集成方式 | 迁移远程地址不改变项目 ID；不按目录同名推断项目相同 |
| 检出 | 某机器上项目的 clone 及主线，是工作区的源头 | 工作区的执行记录不进项目远程，由执行它的工作机写，其他工作机以副本跟进 |
| 工作区 | 工作目录、隔离改动、快照、集成和共享窗口 | 集成后仍可继续使用；归档一个线程不删除整个工作区 |
| 插件实例 | 身份、定义、标题、配置、业务状态与持久生命周期 | 窗口和执行进程各有自己的生命周期 |
| 会话 | agent 的对话与恢复依据 | 停止执行或关闭进程不删除会话 |
| 窗口 | 某个实例视图的共享身份 | 布局、停靠与焦点按设备分别保存 |

工作区是一个工作树加一个本地分支，从最新的项目主线开出，由用户触发集成：按项目设置直接合入主线，或推分支提交 PR。所有工作都在工作区里做；检出是 Kite 自己的裸仓库，用户自己的文件夹 Kite 不碰，见 [项目与远程仓库](项目与远程仓库.md)。同一工作区可以有多个同级线程；需要互不干扰的修改和回退时另开工作区。工作区与线程的生命周期解耦，创建、快照、采纳和归档规则见 [工作机生命周期](kited.md#工作区与线程的生命周期)。

## Agent 与插件

agent 是一种插件实例，拥有自己的会话。子 agent 表示创建来源，与其他实例同级。执行进程、会话、实例与窗口分别管理生命周期。

内置与自定义插件共用定义、实例、操作、视图和权限边界，执行方式可以不同。原生内容与 MCP Apps 视图共用工作区窗口，Bun 承载自定义工作机逻辑。公共契约不要求不同业务共用对话回合状态机，也不要求内置服务增加进程通信。

界面按钮与模型工具可调用同一业务操作，但分别授权。宿主绑定调用方、工作区和目标实例，声明或提示词不能自行扩权。插件只能通过获准的操作访问工作区和其他实例。

定义、实例回收和共享窗口详见 [Agent 与插件契约](Agent与插件契约.md)，操作参数、收据与授权见 [实例操作](实例操作.md)，包格式、能力桥和执行边界见 [Bun 插件](Bun插件.md)。

## 两层协议与上下文

前端会话协议表达 Kite 的历史、流式内容、状态与控制能力，后端差异通过能力声明表达。完整 agent 后端的适配负责控制与事件转换；自研 harness 的模型适配器只转换模型请求和输出。双方保留自己的原生恢复记录，不从界面文本重建模型上下文。

上下文编排是一份用户可编辑的场景契约，包含段落、条件和变量；标题等轻任务与通知正文也使用它。模板决定内容如何组织；事件何时到达、是否启动任务和允许什么操作，由宿主负责。

规则、MCP 与 skill 的来源分四层：系统、用户、机器、项目，由外到内。系统层是用户层的默认：随 kited 版本提供，用户看得见也改得了，改过的存账号数据，恢复默认就删掉那份，不存在用户改不动的一层。用户层属于 Kite 账号，在工作机之间同步；机器层属于一台工作机；项目层随仓库走。规则逐层接起来：角色提示词就是用户层，没有另一份所有角色共用的个人偏好，项目规则经变量进入模板；skill 与 MCP 按名字去重，里层盖外层，加载时注明来自哪层。规则与 skill 拼好后进入基础上下文；MCP 拼好的是可授权的目录，谁能用仍由项目、角色、实例三层授权决定，模型只看到授了权的。机器层目前三类都没有来源，机器层与项目层的外部 MCP 服务尚未接入，等出现真实需要再填。变量与取法见 [上下文组装](harness-上下文组装.md#公共变量)，授权见 [角色与代理配置](Agent与插件契约.md#32-角色与代理配置)。

普通配置和环境变化在自然请求边界追加，不改写已发送历史，也不独自唤醒线程。当前场景与模板见 [上下文组装](harness-上下文组装.md)，投递与恢复见 [线程通知投递](线程通知投递.md)。

## 跨端与资源

工作区共享窗口集合，设备独立保存布局、焦点和阅读状态，契约见 [工作区窗口](Agent与插件契约.md#34-workspacewindow实例的呈现)。原生公共容器承担各类窗口的一致行为，客户端职责见 [App](App.md)。[资源引用](资源引用.md) 定位内容，窗口只负责呈现；历史 diff 保留稳定身份。

## 尚未开放的架构边界

同一工作区可以容纳多个线程，线程之间默认并行，只在工作区级操作时要求全员空闲，见 [工作区并行](工作区并行.md)。单个执行者内的工具并行不能代表跨线程写入安全；快照、回退、采纳和归档须以工作区为协调边界。

后台实例可以没有窗口，专门的内嵌呈现和结果交接尚未完善。普通通知不自动启动任务，主动唤醒代理只经 [monitor](Monitor.md)。模板可引用的公共变量见 [上下文模板](harness-上下文组装.md#公共变量)。

## 扩展原则

以实际需求提取公共服务，优先复用上游。执行权限由宿主授权和操作系统沙箱共同落实，不能只用一段提示词代替。当前不增加插件市场、热升级、旧协议迁移或另一套全局事件日志；能力限制在对应模块正文说明，需要继续处理的事项在项目记忆维护。
