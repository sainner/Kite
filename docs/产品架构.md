# Kite 产品架构

本文维护产品对象、职责边界和扩展约束。具体字段、当前能力与操作入口见 [文档索引](README.md) 对应的模块正文；历史动机见 [任务书](任务书.md) 与 [项目记忆](../.kite/memory/MEMORY.md)。

## 产品形态

Kite 是 Mac 和 iPhone 上的个人 agent 工作台，后台服务 kited 运行在工作机。用户选择项目和工作区，在同一处查看会话、文件、差异和插件窗口，让 agent 处理任务，再决定继续、回退、采纳或归档。

暂定核心承诺是：让 agent 自己推进，把重要决定留给用户，并保留可回看的依据。原生界面负责交互；模型、文件、执行和持久状态由工作机管理。

## 对象与归属

```text
工作机
└── 检出 ── 关联逻辑项目
    └── 工作区
        ├── 插件实例：agent、文件、待办等
        └── 共享窗口：呈现实例的某个视图
```

| 对象 | 负责什么 | 不随什么变化 |
|---|---|---|
| 工作机 | 服务身份、本机目录与执行 | 网络地址变化不应改变已有身份 |
| 项目 | 逻辑项目身份 | 不按目录同名推断项目相同 |
| 检出 | 某机器上的实际目录及提交归属 | 关联项目不复制或同步 Git 仓库 |
| 工作区 | 工作目录、隔离改动、快照、采纳和共享窗口 | 归档一个线程不删除整个工作区 |
| 插件实例 | 身份、定义、标题、配置、业务状态与持久生命周期 | 窗口和执行进程各有自己的生命周期 |
| 会话 | agent 的对话与恢复依据 | 停止执行或关闭进程不删除会话 |
| 窗口 | 某个实例视图的共享身份 | 布局、停靠与焦点按设备分别保存 |

根检出可直接作为根工作区，独立工作区使用 Kite 管理的工作树。同一工作区可以有多个同级线程；需要独立修改和回退时使用隔离工作区。工作区与线程的生命周期解耦，创建、快照、采纳和归档规则见 [工作机生命周期](kited.md#工作区与线程的生命周期)。

## Agent 与插件

agent 是一种插件实例，拥有自己的会话。子 agent 表示创建来源，在侧栏中仍与其他实例同级。一次任务结束后可释放执行资源，保留会话供后续继续；不另设“待命”生命周期。

内置与自定义插件共用定义、实例、操作、视图和权限边界，执行方式可以不同。内置文件与终端可使用原生界面，自定义视图采用 MCP Apps；工作机逻辑使用 Bun。统一到实例层，不强迫终端、待办使用对话回合状态机，也不让内置服务为了形式统一增加进程通信。

界面按钮与模型工具可调用同一业务操作，但分别授权。宿主绑定调用方、工作区和目标实例，声明或提示词不能自行扩权。插件只能通过获准的操作访问工作区和其他实例。

定义、实例回收和共享窗口详见 [Agent 与插件契约](Agent与插件契约.md)，操作参数、收据与授权见 [实例操作](实例操作.md)，包格式、能力桥和执行边界见 [Bun 插件](Bun插件.md)。

## 两层协议与上下文

前端会话协议表达 Kite 的历史、流式内容、状态与控制能力，后端差异通过能力声明表达。完整 agent 后端的适配负责控制与事件转换；自研 harness 的模型适配器只转换模型请求和输出。双方保留自己的原生恢复记录，不从界面文本重建模型上下文。

上下文编排是一份用户可编辑的场景契约，包含段落、条件和变量；标题等轻任务与通知正文也使用它。模板决定内容如何组织；事件何时到达、是否启动任务和允许什么操作，由宿主负责。

普通配置和环境变化在自然请求边界追加，不改写已发送历史，也不独自唤醒线程。当前场景与模板见 [上下文组装](harness-上下文组装.md)，投递与恢复见 [线程通知投递](线程通知投递.md)。

## 窗口与跨端呈现

同一工作区在各端拥有同一组窗口，添加与关闭同步；Mac 可展开多个窗口，iPhone 一次展开一个。分栏、尺寸、停靠、展开与焦点按设备管理，手机切换不改变 Mac 布局。窗口关闭、停止执行、归档或删除实例是不同操作。

窗口共用原生容器，agent、文件与自定义插件只提供自己的内容和动作。资源引用定位稳定内容，窗口只是打开入口；历史 diff 不能随当前文件变化。具体交互见 [App](App.md)，引用格式见 [资源引用](资源引用.md)。

## 尚未开放的架构边界

同一工作区可以容纳多个线程，但当前同一 cwd 仍有执行互斥。单个执行者内的工具并行不能代表跨线程写入安全；快照、回退、采纳和归档须以工作区为协调边界。

后台实例可以没有窗口，但专门的内嵌呈现和结果交接尚未完善。隐藏不改变权限或生命周期。普通通知不自动启动任务；触发器和工作区公共变量的候选设计保存在 [项目记忆](../.kite/memory/MEMORY.md)，不作为已有接口。

## 扩展原则

以实际需求提取公共服务，优先复用上游。执行权限由宿主授权和操作系统沙箱共同落实，不能只用一段提示词代替。当前不增加插件市场、热升级、旧协议迁移或另一套全局事件日志；能力限制在对应模块正文说明，需要继续处理的事项在项目记忆维护。
