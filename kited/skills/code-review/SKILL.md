# code-review

流程：把审查交给一个只读审查子代理，它回报后你把问题清单交给用户。

## 参数

`/code-review [档位] [--fix] [目标]`

- 档位：`low`、`medium`、`high`、`xhigh`、`max` 之一，可以只写前三个字母。省略时用 `medium`。认不出的档位按 `medium` 审，并告诉用户可选的档位。
- `--fix`：审完按清单改代码。
- 目标：PR 号、分支名或文件路径。省略时审当前分支相对上游的提交，加上工作区里还没提交的改动。
- Claude Code 里的 `ultra`、`--comment`、`--post`、`--max-findings` 这里没有。用户带了就说明不支持，其余参数照常。

## 第 1 步：开审查子代理

用 agent_start 开一个只读审查子代理：

- role：`kite.review`
- title：`审查：<目标，省略时写「当前改动」>`
- prompt：

  > 用 read 读 `${CLAUDE_SKILL_DIR}/review.md`，按其中「<档位>」一档的流程审查，目标是 <目标，省略时写「当前分支相对上游的提交加上没提交的改动」>。最后一条回复只写 review.md 规定的问题清单。

整个审查都在子代理里做，读 diff、逐个角度找问题都在它自己的上下文里。你这边只收最后的清单，不要自己再审一遍。开完告诉用户已经交给子代理、用的是哪一档，然后结束这一回合。

## 第 2 步：转交清单

子代理做完时，宿主把它最后的回复作为一条输入投给你。把清单原样交给用户，开头写一句档位和目标；不改写、不删减，也不重新评判其中的条目。子代理失败或被停下时，告诉用户，然后按下面「没有 agent_start 时」自己审。

带 `--fix` 时接着按清单改。正确性 bug 和复用、简化、效率类的清理一样都改。会改变预期行为的、要改到审查范围之外很远的地方的、你判断是误报的，跳过并记一句原因，不争辩。最后简短总结改了哪些、跳过了哪些。

不带 `--fix` 时不改代码。

## 没有 agent_start 时

工具里没有 agent_start，或者建不了 `kite.review` 的代理时，自己用 read 读 `${CLAUDE_SKILL_DIR}/review.md`，在当前上下文里按这一档的流程审，照它的格式给出清单，再按第 2 步处理 `--fix`。总结里写明这次没有交给子代理，是在当前对话里审的。
