# Kite App

Mac 和 iPhone 共用一个 SwiftUI 工程、一个多平台 target。

一段对话统一称为 `Thread`，界面可称「会话」。会话窗口为 `ThreadPane`；侧边栏条目、分离窗口和窗口组属于工作区，使用 `WorkspaceRow`、`DetachedWorkspace` 和 `WorkspaceContent`。不再以 Session 同时指代线程和工作区。

```
app/
├── Kite.xcodeproj
│   └── xcshareddata/xcschemes/Kite.xcscheme   共享 scheme，命令行和 Xcode 用同一个
└── Kite/                                      源码和资源
```

模型：`RemoteWorkspace.swift` 解码工作机、项目、检出、工作区、插件实例、会话专有字段和统一窗口目标；`AppModel.swift` 用 `WorkArea` 保存工作区布局、用 `WorkThread` 保存每个线程的草稿和对话，目录连接先从 `catalog.snapshot` 取得列表，收到对象概要变更后从 `/workspaces` 刷新。`CatalogRefresh.swift` 根据列表响应的 `X-Kite-Cursor` 跳过已覆盖的通知，并拒绝乱序旧响应及上次连接的结果。每个会话窗口通过实例 ID 取得自己的 WorkThread，可以同时展开多个会话。窗口集合由 kited 管理，本机布局按 machineId / workspaceId 保存在 UserDefaults 的 `KiteWindowLayout.*` 中；重连先按服务端集合清理旧布局，其他设备已关闭的窗口不会复活。

布局：一个工作区拥有一个窗口组（`WindowLayout`，在 `Tiles.swift`）：有哪些窗口、Mac 上怎么排、聚焦哪个。Mac 把它们排成卡片（`TileViews.swift`），按住卡片标题栏移动一个实际标题栏高度后，它缩成跟着指针的停靠形状并进入布局拖动；较短的移动保持原布局。停靠栏里的窗口图标沿用 4pt 起拖距离，落到别的卡片上时用占位预览放下后的排布。拖到内容区的四条外边缘时，沿整个窗口组分栏：左右落点上下铺满，顶部或底部落点左右铺满，其余窗口一起排在另一侧；内部仍按单张卡片分栏。窗口可以放进右侧停靠栏，拖动排序、拖回内容区或点击恢复；允许把所有窗口收进停靠栏。右栏与左栏一样没有独立底色，Mac 右栏和 iPhone 底部窗口栏均提供“添加”弹窗，只创建实例；有视图时自动打开默认窗口，无视图时创建后台实例。弹窗刷新 `/plugin-definitions`；新会话登记时不调用模型。没有窗口的已有实例只显示图标，有视图时点击打开；Mac 将这些图标单独排在右栏底部。最小化的 agent 窗口用圆形，其余窗口用圆角矩形，添加按钮带描边。新建或恢复窗口优先放到右侧全高新列，横向不足则在能容纳的卡片下方分栏（优先聚焦卡片），仍不足则收起一个非聚焦旧窗口并使用它的位置；只有一个旧窗口时收起它。每张卡片保留最小尺寸。完全新建、从已有实例打开和恢复最小化窗口共用展开动画；新卡片通过缩放与淡入出现。远端新增窗口只进入本机停靠栏。Mac 悬停整张窗口卡片时，标题栏右侧显示缩小、展开、关闭按钮：缩小收进右栏；展开让当前窗口铺满内容区，其余窗口按原顺序追加到右栏，已独占时隐藏展开按钮；关闭同步到其他设备；随窗口回收的实例在最后窗口关闭后消失，独立存续的实例保留侧栏图标，可再次打开。agent 保留会话及执行。标题会为按钮让位，按钮区域不接标题栏拖动。主窗口和分离窗口各使用所属工作区的停靠顺序。iPhone 始终只展开聚焦的窗口，其余窗口以相同的停靠形状收在底部 action 区上方，无窗口实例图标放在这一栏的末尾；点击窗口图标就展开它，原窗口收回底部（`PhoneLayout.swift`）。布局和停靠状态保存在本机；缩小、展开和切换焦点不会修改其他设备的布局。

Mac 主窗口左边是侧边栏（工作区列表和底部的 action 区，拖右边的缝调宽度，拖到很窄收成一列图标，⌃⌘S 切换），工作区从侧边栏拖到主窗口外面分离成独立窗口（`DetachedWorkspace.swift`），关掉后回到主窗口。卡片和缝上不拖窗口，拖窗口交给侧边栏这些空白处（`MouseDragArea.swift`）。红绿灯按钮那一条多高、让出多宽，从 AppKit 的安全区读（`WindowChrome.swift`），不写死。尺寸和颜色集中在 `Theme.swift`。

每个窗口都是同一个骨架（`PaneWindow.swift`）：浮在上面的标题栏、内容、浮在下面的控制区，内容从两者后面滚过去，Mac 标题栏后面垫当前卡片自己的系统栏材料（`Material.bar`），模糊从后面滚过的内容，材料使用直角矩形，效果止于标题栏底边，并保留底部分隔线；iPhone 标题栏使用卡片内的横向布局，侧栏入口在左，标题分两行，会话菜单在右；顶部使用系统滚动软边叠加窗口底色渐变，遮罩从窗口顶边的不透明渐变到透明，并向下伸过标题栏底边 20pt，控制区后面垫一层渐变遮罩（窗口底色从控制区顶边的全透明过渡到不透明，伸过 Home 条那一截到窗口底边；不透明度是 1 − h²，h 是离窗口底边的距离占整段高度的比例）。控制区使用 `GlassEffectContainer` 统一合成内部玻璃，外层只负责布局和边距，不绘制整块玻璃面板。会话输入区中的文字输入、effort、状态与操作按钮共用一整块玻璃，并通过 `.regular.interactive()` 启用系统触摸、按压与指针交互反馈；文件窗口的左右操作组各自使用系统玻璃按钮，插件窗口只给重新加载按钮使用玻璃。输入框使用连续圆角矩形，Mac 圆角为 16pt、iPhone 为 28pt，玻璃、交互范围与悬停轮廓共用同一形状，避免交互高光与玻璃边界不一致。`ConcentricRectangle` 配合交互玻璃存在高光退回胶囊的[公开复现](https://developer.apple.com/forums/thread/826485)，输入区采用标准圆角矩形。标题栏与控制区共用 `paneMargin` 窗口边距：Mac 为 8pt，iPhone 为 14pt，左右一致；顶部与底部总留白取 `max(paneMargin, 对应安全区高度)`，容器已让出的安全区只补足差额。Mac 没有安全区时四边均保留 8pt；iPhone 的 Home 条安全区较高时按安全区留白，展开底栏后这段高度仍在窗口内保留。键盘升起时在键盘上方保留 14pt。SwiftUI 的安全区分 container 和 keyboard 两区，但只能按区忽略，读出来是合在一起的；Home 条那一截从 UIKit 的安全区读（UIKit 的安全区不含键盘），多出来的就是键盘；这一比在屏幕那一层做，窗口里读到的安全区在拉开、收起抽屉时跟着动画逐帧变，还会冲过 Home 条那一截。状态信息使用统一 chip，Mac 放在输入框右下角、附件／语音／发送按钮组左侧，文字在左、圆环在右；iPhone 放在底部安全区中央，键盘升起或底部安全区不足时隐藏。窗口标题统一不带图标，Mac 主标题使用系统 `headline` 半粗体，iPhone 使用 `subheadline` 半粗体，次级信息均使用 `caption`。标题与次级信息共用 `PaneHeaderTitle`：Mac 和 iPhone 均上下两行靠左；文字过长截断，路径可横向滚动。Mac 窗口卡片圆角为输入框圆角加窗口边距（16pt + 8pt = 24pt），iPhone 保留 20pt。各个窗口提供标题、次要信息、标题栏菜单、内容和控制区。Mac 上标题栏靠左，次要信息在标题下面，卡片的拖动把手避开可点击的会话标题或目录路径，放在该行上方或下方较高的一侧；iPhone 上靠左，次要信息在标题下面、小一号，左边是拉开侧边栏的按钮（从左边缘往右滑也行），会话标题右侧显示模型和更多菜单。iPhone 上从控制区往上拖拉出 action 栏，打字时不拉，横着拖不算；拉开、收起侧边栏和 action 栏照系统可交互转场的做法分两段（`PhoneLayout.swift`）：拖着时窗口跟手，越过一半轻震一下，推过完全打开还能再出去一截、越推越吃力；松手时甩得够快就去甩的那头，不然看过没过半，用弹簧带着手指的速度走过去，甩得越快回弹越多；点按钮、点窗口收起没有速度，不回弹；走的途中按住就从当时的样子接着拖；打字时点控制区以外的地方收起键盘。终端和独立预览实例仍使用占位内容与空控制区；文件实例已接目录和文本预览。字号是两端共用的一套 token，每个对应一种系统文本样式。

Mac 卡片的滚动区铺到卡片顶边，上下栏用 `safeAreaInset` 留出内容起止位置，标题栏使用边界固定的系统栏模糊材料、底栏使用卡片底色渐变，并隐藏滚动视图自动生成的边缘效果。不能只在 `safeAreaBar` 外隐藏软边：它登记的效果区域仍可能让贴顶卡片共享系统标题栏合成组，露出工作区底色。标题栏仍占 40pt，正文可以从标题栏后面一直滚到卡片顶边，不再为系统标题栏额外下移滚动区；iPhone 沿用 `safeAreaBar`。

会话窗口（`ThreadPane.swift`）：主标题显示该线程的真实会话名称，次级信息显示窗口类别“代理”，尾部带小刷新图标，与工作区名称区分；点击名称或刷新图标立即重新生成，等待期间图标旋转并禁用重复点击，失败保留原题并弹出原因。标题通过工作机目录事件同步；草稿、离线及样本模式不发送生成请求；内容是对话，控制区上方为输入框，下方为一行按钮，effort 左对齐，右侧排列操作按钮。状态 chip 在 Mac 输入框右下角操作按钮组左侧、iPhone 底部安全区，高度 20pt。chip 的圆环颜色表示 idle、running、stopping、finishing 四个主状态；运行中圆环旋转且占比弧长不变，停止中和收尾中以较明显的明暗变化呼吸，空闲保持静止，弧长表示最近一次完成请求的上下文占用，圆环内不放数字；Mac 圆环位于文字右侧，iPhone 位于文字左侧；文字显示状态或上一轮结果，失败和恢复阻塞直接显示原因。缺少用量或有效窗口上限时仅显示圆环底轨，悬停说明用量未知；当前生产只有输入 token，没有窗口上限。

- 控制区：effort 左对齐；操作按钮在右侧，不再显示斜杠命令按钮，effort 暂显示默认 medium，尚不能调档。有字时可发送，回合进行中可打断，暂停时可继续；连接未建立或服务未声明能力时禁用。附件、语音输入和动态 effort 尚未接通；
- 人发的消息（`MessageBubble.swift`）：靠右带气泡，右下角圆角小一点；排队中（agent 还没收到）只描边，收到了填上完整主题色，正文在深浅外观下都用白字；正文原样显示，只把 ``` 围起来的一段排成等宽，斜杠命令名也用等宽字。长消息由整个气泡统一折叠，底部直接提供“展开全文／收起”，裁切区仅在末端保留 20pt 渐隐，按钮不参与裁切或渐隐；图片和文件排在气泡上面。排队中的消息不是记录，单独放在 `Transcript.pending`，收到的那一刻才变成记录。
- agent 的话铺满这一栏，Markdown 用 Foundation 自带的解析、逐块排版（`Markdown.swift`）。思考摘要仅在生成期间显示一行内容，完成或中断后隐藏；完整数据与分组位置保留，不计入工具数量或批次。连续的工具调用折成一行，汇总行不显示图标，展开箭头紧跟在文字后面。点开按同一次模型回复分批列出每一步：同批调用放在一起，相邻调用之间用横向虚线分隔；不同批次之间使用横向实线，缺少批次信息时不猜测分组。工具列表共用描边圆角矩形，各行之间用分割线划分，不再显示竖线或实心点；单个工具行和整个折叠组均按当前边界裁剪，避免退场中的详情在高度收缩时覆盖后续内容；工具标题行在 Mac 上为 32pt、iPhone 上为 36pt，并随系统字号缩放，信息 chip 和分割线样式不改变其高度或间距。每行显示图标、加粗工具名、摘要和右对齐的信息 chip；图标、名字、摘要之间统一为 6pt 间距，read 使用文件图标，iPhone 上的工具图标使用小号符号比例。除失败及未知结果为红色外，各状态的文字和图标基础颜色一致，运行中不另换主题色。read 摘要为相对路径与请求行范围，patch 为路径加 `:diff`，shell 为 `description`。等待中由图标、名字和摘要一起做透明度呼吸，背景无填充；执行中使用 `KitePixels.metal` 的像素扫掠 shader：像素化区域以 SwiftUI `UnitCurve.easeInOut` 从左向右掠过并持续展开，经过的笔画短暂变成珊瑚橙、暖黄、薄荷绿、天空蓝和葡萄紫的彩色方块，随后恢复清晰与原色；每格配色固定，不逐帧换色，每 2 秒一周期，方块边长为 2.5–4pt；各工具行的图标、工具名和摘要作为同一区域连续扫掠，普通文字与文件引用摘要使用相同效果；有工具执行中的折叠组汇总文字也复用此动画，展开组后动画留在各工具行主体；右侧信息 chip、行背景与展开箭头保持原样；生成中只更新流式内容，成功静态、失败及未知结果为红色，状态原文留在详情中。系统开启减少动态效果时关闭扫掠与呼吸，保持完整不透明度。每一步的标题行容器统一接收展开与收起点击，空白区域也可点击；文件引用仍单独跳转，详情区保留选字与引用交互。展开后的兜底详情分成 `input` 和 `result` 两张卡片（`WorkViews.swift`），每张卡片按顶层键排列两列：左侧是键，右侧是紧凑 JSON 序列化后的完整值；嵌套对象和数组不再递归排版，长值在第二列换行。名称、状态及阶段由工具标题行表达，详情不重复显示 `name`、`status` 或 `stage`，输入卡片也隐藏顶层 `description` 字段；原始调用数据不变。生成期间的 `arguments` 原文保留在 `input` 卡片，执行中的流式输出与截断标记放在 `result` 卡片；完成后结果卡片保留 `output`、diff 和历史非文本内容。每个工具在折叠行怎么说、归哪一类仍在 `ToolPresentation.swift`。
- 操作栏（`ActionBar.swift`）：iPhone 上长按一条消息或 agent 的话约 0.4 秒、Mac 上右键弹出（Mac 上左键留给选字，开着文字选择的字会吃掉单击）。一个液态玻璃胶囊，一排图标按钮，出现时从贴着这一行的角整体等比放大；是浮层，不挤开别的内容，和这一行的一边对齐，平常在底下，底下会压到控制区或窗口底边时放到上面；点别处或者滚动时收起。iPhone 单击正文不打开操作栏，单击引用直接跳转。排队中的消息可编辑、取消发送，投递未确认时可用同一 id 重试；收到的消息提供复制。agent 的话提供复制，翻译和分叉禁用。
- 选字：iPhone 上气泡的正文和 agent 的话用 UIKit 的文本视图排（`SelectableText.swift`）：长按不动显示操作栏，接着拖动超过 8pt 就从按下的字开始选字、操作栏收起，松手留着选区和系统的编辑菜单；已有选区时单击只取消选区，再次点击引用才跳转。长按和选字结束不会触发引用点击；agent 的话里连续的段落、标题、引用、列表项在同一个文本视图里，代码块、表格、分隔线照旧用 SwiftUI 排，选字跨不过它们。
- 发送：输入框里的字模糊淡掉，气泡连同附件从下往上浮进来、淡显，和对话往上滑同时开始。空闲、前面也没有排着没收到的时候发的开启新的一轮：对话滑到这条消息停在可见区顶上，最后一轮至少占满一屏，不够就在底下留白，回复往空白里填。回合在跑、或者前面还排着别的时发的是排在后面的：接在最后面，对话滑到最底下把它顶上来，不另留空白，收到时并进那一轮。手动停止后，尚未纳入请求的消息退回输入框，保留已有草稿；停止尚未确认时禁止继续发送，并可重试同一停止操作。
- 滚动（`TranscriptScroll.swift`）：打开或切换到会话时不保留末尾留白，停在最后一条内容的底部，跟着最底下；往上翻就不跟了，翻回最底下又跟。只有本次打开后发送并开启新一轮，才添加末尾留白。内容或可见区变高变矮（展开收起一步、回复变长、键盘、抽屉）时，停在最底下、底下也没露着留白，就按底部对齐：最后几行跟着键盘一起顶上去，展开收起一步时最底下不动；不然按顶部对齐，对话不动。收起后旧坐标超出新内容范围时立即收回新末尾，位置仍合法时保持原位；几何信息统一从同一次回调读取。手指进入 `tracking` 就解除首次贴底或程序滚动的目标，直到拖动与惯性结束都暂停自动对齐；静止后只在正文中部钉住阅读位置，顶部、底部和边界外的位置交给系统完成回弹，不重新写入夹正坐标。留白是人往上翻多少裁掉多少，裁到最后一条内容为止，下一次开启新一轮才重新留。普通尺寸变化的对齐交给 `defaultScrollAnchor`；可见区变矮时留白等键盘的动画走完再缩；留白在排版里和新消息一次算出来（`TranscriptStack`）。工具内部展开/收起时，排版重新读取当前行高，不按宽度和行数沿用旧高度。
- 真实数据：`KitedClient.swift` 解码统一显示协议，`WorkThread` 保留真实线程 id、草稿和投递占位；会话打开时订阅 `/events?thread=<id>`，先接收完整 `thread.history`，再按记录 id 更新文字、工具和状态，断线自动重连。目录连接只接收概要变化。发送和重试沿用消息 id，由后端确认接收；排队消息支持撤回后编辑，已纳入模型请求的不能撤回。打断和继续调用后端；对话回退、分叉、翻译、附件与动态 effort 尚未接通，相应按钮禁用或隐藏。`SampleTranscripts.swift` 仅保留作静态展示样本，正常启动不加载。
- 连接与新建：首次默认连接 `http://127.0.0.1:5483`。连接面板可保存和切换工作机；`MachineConnections.swift` 将机器身份、地址、最近返回的项目身份与当前选择保存在本机 `UserDefaults` 的 `KiteMachineConnections` 中。同一机器更换地址时更新已有连接，App 当前一次连接一台工作机。所有业务请求与 SSE 都携带目标机器 ID；重连发现地址已属于另一台服务时报告错误。先启动 `cd kited && bun src/main.ts`；登记工作机上的目录会建立检出和根工作区，可新建项目，也可选择访问过的工作机上的已知项目。同名不同 ID 的项目分别显示，关联不复制文件或执行记录。选择检出和首条消息可以创建独立工作区。对话控制区不再放线程菜单和新对话入口。没有工作区时显示同一套卡片中的空白草稿；取消新建保留输入。连接状态在侧栏底部显示，新增入口沿用原来的按钮槽位。Mac 与模拟器可直连本机，真机连接工作机的网络入口尚待接入。完整协议及 Claude 只读范围见 [会话显示协议](../docs/会话显示协议.md)。

输入区内部与工具条按钮使用 `PaneButtonStyle`（`PaneButtons.swift`）：图标点击区按平台区分：Mac 为 32×32pt，iPhone 为 44×44pt，文字按钮同高、宽度随文字增长；图标使用正文系统字号，发送和停止使用加粗图标，彩色圆形在点击区内缩 2pt（Mac 直径 28pt，iPhone 直径 40pt），完整圆形点击区可点击。各处共用命中形状、禁用样式、按压、悬停与光标反馈。间距按用途分开：`paneButtonGap` 为 8pt，只用于同组按钮之间；`paneLayoutGap` 为 8pt，用于标题、状态、控件组之间及控件组换行后的行距；`paneGlassSpacing` 为 8pt，只用于玻璃效果的合并距离。工具条按钮到容器四边均留 8pt，一行按钮组在 Mac 上高 48pt、iPhone 上高 60pt；会话输入栏单独使用 `controlInset`，四边内边距统一为 8pt；输入区仍是一整块玻璃。消息浮动操作栏沿用这些布局参数；代码块工具条使用原生无边框按钮和系统 `.small` 档位，保留专用图标，不套用控制区的点击区尺寸，避免撑高代码块。独立操作入口共用 `PaneButtonGroup`：iPhone 侧栏入口与文件底部操作组共用 SwiftUI `Button`／`Menu` 的 `.glass` 样式和系统 `.large` 档位，由 `GlassEffectContainer` 合成玻璃，组内间距为 8pt；独立按钮的图标与文字使用 `PaneButtonLabel`：iPhone 标签保留随系统字号缩放的 18pt 高度，Mac 标签按内容自然尺寸排版。原生 `.large` 继续提供按钮内边距，菜单转场和交互反馈交给系统，不在按钮外添加固定外框。Mac 标题栏的窗口控制组与模型／更多组共用 `PaneHeaderButtonGroup` 和 `PaneHeaderButtonLabel`：每组通过系统 `glassEffectUnion` 合成一块胶囊玻璃，标题栏控件使用 `Metrics.paneHeaderButton` 的 36pt 高度，纯图标入口为 36×36pt，文字入口至少宽 36pt 并随内容增长、左右各留 8pt；尺寸与留白属于按钮标签的完整点击区。标题栏按控件实际高度加上下 14pt 留白布局，拖动层按实际高度与分组宽度避让；浮动操作栏按完整容器高度决定放在消息上方还是下方。

## 操作反馈

`Toast.swift` 统一短提示的展示与生命周期。App 主窗口、Mac 分离窗口和独立面板在根部安装 `toastHost()`；业务视图通过环境中的 `toast` 发出文字与可选图标。同一展示层只保留最新提示，重复触发重新计时，1.5 秒后消失，过期任务不会关闭新提示；提示不拦截点击，并向读屏发送播报。提示位于当前窗口底部，沿用 SwiftUI 安全区与键盘避让，不在不同 Mac 窗口之间广播。代码块、用户消息、agent 消息和工作目录的复制按钮共用这一入口；卡片按压动效仍由代码块自己负责。

## 会话窗口菜单

`ThreadHeaderActions.swift` 在标题栏尾部提供模型和更多两个菜单入口，两端共用业务动作与可用状态，菜单分别使用平台原生实现。iPhone 的 `PhoneThreadHeaderMenus` 使用一个 `UIButton.Configuration.glass` 胶囊按钮，按点击位置选择模型或更多内容；保持同一个菜单呈现者和根菜单，由 `UIDeferredMenuElement` 在展开时提供内容，玻璃与标签共同参与系统菜单转场，并为辅助功能提供两个入口。Mac 的 `MacThreadHeaderMenus` 使用 SwiftUI 原生 `Menu`，通过内联 `Picker` 展示模型勾选项、通过 `Section` 展示分节操作；菜单使用与窗口控制组相同的 `PaneHeaderButtonGroup`，入口使用 `.button` 菜单样式与公共标题栏按钮样式，保留 SwiftUI 标签的完整尺寸；菜单展开时按原生按钮状态显示 20% 不透明度的灰色背景，灰色背景距玻璃容器边缘内缩 4pt，收起时清除，再通过系统交互玻璃与 `glassEffectUnion` 合成一块胶囊玻璃。标题栏控件统一为 36pt 高，图标入口使用 36×36pt 点击区，文字入口按内容增长且两侧各留 `paneToolbarInset` 的 8pt；不再使用 AppKit cell 手工计算坐标，图标本身仍按自然尺寸绘制。Mac 标题栏的窗口控制组与模型／更多组内，按钮点击区直接相接，不叠加额外间隔，文字入口保留自身左右各 8pt 的内边距；iPhone 使用 `paneButtonGap` 的 10pt 作为模型文字与三点图标之间的距离，外侧各保留 15pt，两个点击区在内容间距中点相接。模型菜单显示完整型号并勾选当前项，按钮只显示 tier（astra、sol、terra、luna）。连续打开、收起并切换入口时不能残留旧菜单来源，转场效果由用户实机确认。Mac 的缩小、展开、关闭按钮放在菜单组前面，悬停整张窗口卡片时显示，离开卡片后隐藏；最小化或布局拖动期间隐藏。标题栏由 SwiftUI 布局，Mac 保留 8pt、iPhone 保留 14pt 固定边距；Mac 左侧标题组额外增加 8pt 左边距，距卡片左边缘共 16pt；标题与次级信息在两端均采用左对齐的上下两行布局，窗口圆角保持 20pt。文件窗口的次级信息是相对工作区的分段路径，根目录用工作目录名称展示；点击任一目录段在当前窗口打开目录页，保留实例原来的文件选择，再次打开文件恢复预览。标题栏没有长按菜单。Claude 历史未提供模型信息时显示「模型」，不猜测具体型号。

模型清单唯一来源为 `shared/agent-models.json`，每个 tier 只列当前选定版本；App 将它打包为资源，工作机和 CLI 也从中取得默认型号。当前默认是 sol（gpt-6.1-sol），其余选项为 gpt-6-astra、gpt-5.6-terra、gpt-6-luna。点击菜单项后读取 `/instances/:id/agent-config`，只改模型标识并携带 revision 保存，保留推理强度、工具、上下文与请求预算；失败或版本冲突显示错误，成功后更新按钮，下一次模型请求生效。Claude 当前保持只读历史，不提供切换。样式样本只修改本地内存。

更多菜单接实例设置与授权、复制工作目录、停止／继续执行以及动态样本重播。Mac 拖动层及其右键菜单按实际宽度限制在标题区域，外层不再声明覆盖按钮的整栏命中矩形。

## 插件与实例管理

设置中的「管理插件定义」（`PluginLibrary.swift`）查看当前工作机的内置与自定义插件及生命周期，导入预构建 JSON 包后确认安装。实例创建集中在工作区添加弹窗；未知结果保留同一请求 ID，用户可重试。

从会话标题栏的更多菜单、停靠图标的右键／长按菜单，或 Mac 窗口标题栏的右键菜单进入「实例设置与授权」（`InstanceSettings.swift`）。面板可打开实例声明的视图，查看、停止 Bun 进程，按工作区和目标实例选择业务操作或 MCP 工具授权。无视图实例通过图标菜单管理。

授权草稿保留其他权限，保存携带 revision，冲突后保留草稿；已有工具授权直接显示，无需重新发现即可撤回。离开或重新读取前提示放弃未保存修改。创建和授权均绑定当前工作机，切换连接关闭旧实例面板；工具实际可调用范围由 kited 核验。harness 实例另有「执行授权」页面（`ExecutionGrantSettings.swift`），独立编辑工作区读写、额外绝对路径和网络白名单；模型已可从会话标题栏修改。工具选择、动态推理等级与请求预算尚未提供编辑界面。

设置中的「管理上下文模板」（`ContextTemplateLibrary.swift`）按场景展示当前工作机的创建会话模板、一份会话标题模板，以及配置变更、基础上下文更新、执行授权变化、插件工具授权变化四类通知模板。空会话发送前只选择创建会话模板，也可基于当前模板复制、修改并保存新模板；设置与新会话使用 `ContextTemplateEditor.swift`，段落可双击编辑，变量显示为 chip，条件按页签编辑分支。会话标题模板内分为命名规则和材料两个编辑区域，两区一起保存。模板保留结构化契约，不把未选中的分支拍平。保存带内容 revision；失败保留草稿，切换工作机后不允许保存旧连接的草稿。实例绑定所选内容，编辑创建模板不改已有会话；标题模板在下一次生成时读取，通知模板在之后生成通知时读取，已生成的待投递通知与历史保留原快照。编辑通知模板不会唤醒会话或改变权限。选择模板保留模型、工具、预算与授权，保存期间禁用发送。样本模式提供以上六个场景的可编辑模板，仅保存在内存，不访问工作机。

执行授权页只读查询 `/threads/:id/state`，不启动模型，也不依赖窗口是否展开。运行中先停止，复用会话停止收据与未发送队列退回；结果未知时须用户核对残留执行并显式确认。停止未确认、执行中或恢复待确认时不可保存。冲突保留草稿，重新读取或返回前提示放弃修改；保存成功采用工作机规范化后的授权。通知在下一次自然模型请求追加，保留历史上下文前缀。

## 自定义插件窗口

`PluginPane.swift` 在现有 `PaneWindow` 内承载 MCP Apps 视图，标题栏、缩小、展开、关闭和 iPhone 抽屉沿用原有窗口机制。`PluginWebBridge.swift` 使用非持久 `WKWebView`，可信宿主页与 sandbox iframe 隔离；原生桥只转发当前实例的工具调用。关闭最后一个共享窗口时，工作机按插件的 `lifetime` 回收实例或保留状态与进程；视图卸载、最小化不会触发回收。

当前实例的插件状态变化或目录连接重连后，宿主页发送该视图资源的更新通知，插件重新查询实例状态。其他工作区、其他实例或窗口集合变化不触发这次查询。工具写入复用 kited 操作收据，错误由界面展示，不自动重复写入。控制区提供重新加载按钮。待办样例、资源声明、限制和演示服务见 [Bun 插件宿主](../docs/Bun插件.md)。

`PluginHost.html` 由 `kited/web/plugin-host.ts` 与锁定的 MCP Apps SDK 构建，随 App 打包；修改后运行 `cd kited && node_modules/.bin/bun run build:plugin-web`。`.kite/check` 编译 App 前自动重建。

## 文件窗口

`kite.files` 的单个文件窗口沿用 `PaneWindow` 骨架，包含目录浏览、原文、Markdown 预览与历史 diff。点击文件更新所选目标并在同一窗口显示内容，可按行定位、选字复制和翻页；目录可收起。引用跳转复用已打开的文件窗口。底部目录、显示方式、翻页和刷新均使用公共原生按钮组，与侧栏入口采用同一系统尺寸档位；「原文／预览」的文字宽度随内容增长，当前项用字重和辅助功能选中状态标明。左右操作组的按钮尺寸由系统负责，内部间距统一为 8pt，不额外增大按钮外框；横向放不下时分成两行，保留按钮尺寸和完整命中区域。

`FileBrowser.swift` 保存设备上的目录位置与文本页，`files.select` 将选择和 revision 写入工作机的实例 state。工作区通知带来另一端的新选择时清掉旧文本页，重新读取；迟到的目录和文本响应不能覆盖较新的请求。文件实例随最后一个窗口关闭而回收，重新添加得到新实例和初始选择；最小化及连接重启保留选择。工作区文件与历史 diff 保留。目录与文件内容没有后台监听，刷新按钮读取当前内容。

当前支持最多 2 MiB 的文本文件，目录和正文每页 200 项或行；超限、非文本、删除和路径越界均显示服务端错误。目录列出符号链接但不提供点击跳转。没有文件编辑器；独立 `kite.preview` 占位已撤下。`--sample-data` 的文件窗使用标明用途的本地样本文本，复用同一视图，不访问工作机。

## 约定

外观：齿轮「设置 → 外观」可选跟随系统、浅色或深色，默认跟随系统；Mac 也可从「显示 → 外观」切换。同一 App 的主窗口、分离窗口和设置面板同步，选择保存在本机 `UserDefaults` 的 `KiteAppearance`。`Appearance.swift` 接入系统外观偏好，`Theme.swift` 引用颜色资源中的浅色、深色配色；iPhone 的文本装饰在外观变化时重新解析颜色，保留选区。

- 工程照 Xcode 自带的「多平台 App」模板的设置写成，不用 XcodeGen 这类生成工具。`Kite/` 是同步文件夹：在里面加、删、挪文件，工程自动跟上，不用改 `project.pbxproj`。
- 两端共用代码，差异用 `#if os(macOS)`、`#if os(iOS)` 分开。
- Swift 6 语言模式，数据竞争在编译时报错；模板默认是 5。默认隔离在主线程（`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`），和模板一致。
- 开发语言是简体中文（`zh-Hans`），界面文字直接写中文。
- 最低 macOS 26、iOS 26。只支持 iPhone，要 iPad 时把 `TARGETED_DEVICE_FAMILY` 改成 `1,2`。
- Mac 版开沙盒，允许对外连网（连 kited）、只读用户选中的文件，和模板一致。
- Bundle ID 是 `com.sainner.kite`。

## 编译和运行

文字动画通过 [SwiftUI layerEffect](https://developer.apple.com/documentation/swiftui/view/layereffect(_:maxsampleoffset:isenabled:)) 调用 Metal，`.metal` 文件随同步工程编译到 `default.metallib`。首次使用的 Xcode 如果没有 Metal Toolchain，先运行 `xcodebuild -downloadComponent MetalToolchain` 安装官方组件。

执行动效统一使用已定稿的彩色像素扫掠，样本与正常模式相同；没有动效选择菜单或设置项。开启减少动态效果时保持静态。

`.kite/check` 在 `app/` 有改动时编译两端，出错时列出文件和行号。手动编译：

```bash
xcodebuild -project app/Kite.xcodeproj -scheme Kite -destination 'generic/platform=macOS' -destination 'generic/platform=iOS Simulator' build -quiet
```

运行用 Xcode 打开 `app/Kite.xcodeproj`，选 My Mac 或一台 iPhone 模拟器。

滚动的手动运行时回归用 `bun kited/test/contract/verify-transcript-scroll-swift.ts`：在 Mac 原生宿主中读取带安全区的滚动几何，检查离屏长消息的动画收起和手势阶段的定位交接，不截图，也不计入快测预算。

预览会话样式时，Debug build 带 `--sample-data` 启动（Xcode 的 Run → Arguments 或 `simctl launch` 传入）。装到测试机后需要从桌面反复打开时，编译时传 `KITE_PREVIEW_FLAGS=KITE_SAMPLE_DATA`，这个 build 每次启动都加载样本，不依赖临时启动参数。该编译参数只由 App target 读取，不覆盖 Swift Package 的编译标记；不要全局重设 `SWIFT_ACTIVE_COMPILATION_CONDITIONS`，否则会移除依赖的 `SWIFT_PACKAGE` 标记，导致包内资源加载失败。普通 Debug build 不带参数时正常连接服务；Release build 不加载样本。

`SampleWorkspace.swift` 默认打开「插件 · 侧栏样式」：内容区保留一个会话，上方收起文件、终端、agent 和同一待办实例的两个视图；底部展示无窗口 agent、待办及纯后台插件。待办和后台插件明确标为样式样本，Web 内容仍使用窗口占位；可通过添加入口在内存中创建后台实例。原有 `HarnessSampleTranscripts.swift` 场景保留，「文档整理」在末尾展示 Markdown 样式，涵盖行内代码换行、中英混排、标题、列表、引用、代码块、链接与表格；可重播的「流式会话 · 动态预览」继续保留，正文、思考、工具参数和输出经同一事件合并入口更新；之后保留界面开发、文档整理、日志排查和空白草稿，便于比较不同内容长度和状态下的工作区切换；列表可上下滚动。另有「工具行 · 样式与动画」持续展示命令摘要动效、补丁行数和运行时间，以及「执行动画 · 文件摘要」对比长短文件引用的持续 shader 动画；后面保留四种 chip 状态样本，以及工具批次、工具与消息、工作中与排队、长文与排版、工具与模型报错、停止与退回草稿、结果未知与恢复、长输出与截断、回复生成中、空白会话。沿用实际界面，不连接 kited，也不发送或创建真实会话；添加和关闭在样本内存中使用同一套窗口目标与布局。

样本只使用当前 harness 的 `read`、`patch`、`shell`，记录经过 `RemoteRecord.record` 转换，结果状态与真实历史使用同一映射。覆盖范围见 [会话预览假数据](../docs/会话预览假数据.md)。旧的 `SampleTranscripts.swift` 是 Claude Code 的展示素材，不在这个入口加载。静态样本不验证流式时序、重连或发送重试；动态流式样本用于视觉和交互预览，协议正确性由跨层测试验证，也不展示尚未接通的 shell 工作区 diff 统计、附件、子 agent、MCP、后台任务和自动压缩。上下文占比只在明确标注的 chip 样式样本中使用虚构窗口上限，覆盖 0%、46%、99%、100%；不代表真实模型已提供上限。

## 签名

工程已配置 `DEVELOPMENT_TEAM` 和自动签名，本机可以编译并安装到已连接的 iPhone 测试机。真机预览按设备 ID 编译，再用 `devicectl device install app` 安装和 `devicectl device process launch` 打开。


流式显示：`thread.record` 建立/校正条目，`thread.record.delta` 只传文字、参数或输出增量。`WorkThread` 按约 33ms 合并刷新，`Transcript.replaceRecord` 原位更新对应项；`MarkdownDocument` 缓存当前消息的解析，完成内容不因其他行更新反复解析。工具行区分参数生成、等待、执行和结果，详情在生成期间显示原始参数，在执行期间显示受限尾部输出。协议与实验见 [会话流式展示](../docs/会话流式展示.md)。

Markdown 表格使用系统衬线体，无背景和横向内边距，只保留表头下方分隔线，上下各留 12pt。iPhone 首次显示表格时通过 CoreText 按需取得苹果的宋体常规体与粗体（`TableFont.swift`），下载和缓存由系统管理；等待或失败时沿用系统回退，成功后自动更新中文字体，失败后再次打开表格或回到前台会重试。英文保留系统衬线体，粗体、斜体和表头字重保留；行内代码始终使用自身的等宽字体。

Markdown 正文增加 4pt 行间距。所有 Markdown 入口（正文、标题、列表、引用、表格、文件预览和压缩摘要）的行内代码共用 `InlineCodeStyle`：等宽字体取周围字号的 90%，继承标题与表头字重，保留显式粗体和斜体；引用图标按相邻代码的实际字号缩放。背景按实际文字范围逐行绘制，使用 4pt 圆角、左右各 4pt 内边距；边界字距额外预留背景外的 2pt 间距，背景不包含这段字距。SwiftUI 背景画布左右各扩宽 4pt 并补偿原点，iPhone 正文的文本视图以内外边距抵消的方式保留绘制余量，防止内边距在单元格与段落边缘被裁切，同时保持正文宽度和起点。代码中的文件图标与站点 favicon 一并包含在背景内，图标后仍留 2pt 间距；展示层用零宽连接符禁止图标和名称开头之间断行，长名称后续部分仍可正常换行。Mac 使用 `Text.LayoutKey`，iPhone 使用 TextKit 文字片段，保留原生文字排版、选择和链接，原始消息与引用目标不变。

独立代码块在用户消息与 agent 消息、Mac 与 iPhone 上统一使用 `CodeBlock`，不再由 iPhone 用户消息的 TextKit 片段单独绘制背景和缩进。顶部左侧显示围栏的语言标记，未标记时显示 `text`；右侧显示复制图标，仅 `bash`、`sh`、`shell`、`zsh`、`ksh`、`fish` 这类 Shell 语言标记额外显示执行图标，匹配不区分大小写；图标按钮复用输入区的 `PaneButtonStyle`，按钮间距为 0，点击区在 Mac 为 28×28pt、iPhone 为 44×44pt，图标尺寸取当前环境解析的 `.body` 字号，保持纯图标外观，通过原生按钮动作完成复制并让整块代码卡片朝按钮位置轻微 3D 倾斜后回弹，不额外叠加点击手势，开启减弱动态效果时跳过倾斜，禁用项不响应交互。复制始终取完整代码，不受折叠影响，并通过 App 共用 toast 显示“已复制”，代码块不再持有提示视图或计时状态；终端执行尚未接入，按钮禁用。代码保留横向滚动。agent 代码块保留独立的长内容折叠；用户气泡内代码块由整条消息统一折叠，展开全文后不再要求二次展开代码，并使用随深浅外观调整的不透明蓝色底，避免气泡透入高亮背景；两类代码块统一使用 18pt 圆角；标题栏在按钮上下各留白 4pt，Mac 高度为 36pt、iPhone 为 52pt；左侧边距为（按钮尺寸 − 图标尺寸）÷ 2 + 4pt，右侧保留 8pt。语法高亮通过 SPM 固定接入 HighlighterSwift 3.1.0，使用内置 highlight.js 离线着色；串行 actor 复用引擎，随文本和系统外观更新结果，语言缺失、不支持或解析失败时显示原文。字体、间距和背景沿用 App，仅取高亮颜色。用户普通正文仍不解析 Markdown，iPhone 普通文字保留 UIKit 的长按与拖动选字。

工具信息 chip：patch 只统计参数中明确的增删行数，包含整文件删除或缺少 diff 时不显示整批计数；计数不代表实际成功写入的改动。shell 运行时间使用 `startedAt`、`finishedAt`，执行期间每秒刷新，缺少时间信息时不显示。shell 的工作区 diff 数量需要后端另行提供，目前不从输出猜测。

统一引用由 `ResourceReference.swift` 识别路径、行号、历史 diffId 和网页链接，`ReferenceViews.swift` 显示同色文件图标与站点 favicon（两端高度统一为字号的 85%，随字号缩放），并由宿主处理跳转。`FilePane` 合并目录、原文、Markdown 预览和历史 diff；选择目标共享，定位与显示方式留在设备。设计与边界见 [资源引用](../docs/资源引用.md)。预览首个工作区「引用 · 文件与历史差异」可点击查看同一文件两次修改及当前内容。
