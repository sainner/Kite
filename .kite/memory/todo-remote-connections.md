**状态：** 托管账号、入网和同账号工作机访问按 [托管账号与设备](../../docs/托管账号与设备.md) 实施；原生真机完整验收仍待做。跨机器目录采用托管索引、本地缓存和工作机直连；文件与 Git 的多机同步是另一项候选能力。

**来源：** 用户在 2026-10-06 先验证过旧个人 Headscale 的 iPhone 扫码配对，随后要求由我们托管、账号密码登录、同账号设备授权合并到入网。旧扫码实验不证明新的账号流程已经通过真机验收。

**待处理：**
- 跨机器目录在真实 Mac 与远程机器组合中验收，覆盖开机时读取缓存、单机离线、设备移除和同时打开异机工作区；实现与手动验收范围见 [托管账号与设备](../../docs/托管账号与设备.md)。
- 原生 iPhone 新流程：账号密码登录、新设备扫描已登录设备二维码、浏览与发送、切后台再回前台重连、移除设备后重新登录。
- 节点或账号会话过期后的重新登录；与代理 App 共存。
- iPhone 重连速度（2026-10-08 用 TimingTrace 实测，取回方法见 app/README.md）：后台 25 秒内回前台复用节点并刷新路径，局域网约 0.1 秒、蜂窝约 1.5 秒。重建节点后首次握手偶发丢失、多等 5 秒，根因是 iPhone 关闭前上报的主中继过时，Mac 按上游规则向它回包；同日已把 Headscale 中继表改为只有香港区域 999，改后未再出现。尚未解决：hk-server 公网的 UDP 3478 被云服务商挡住（Pod 与宿主内网端口均正常），网络探测因此 udp=false，节点上线从约 3 秒变慢到 5～6 秒，蜂窝也无法打洞直连；需用户在云控制台放行后复测。
- 项目以远程为身份（[[project-remote-identity]]）的四期已于 2026-10-07 实现，自动测试只用本机账号服务替身。待在线上验收：真实工作机经 hs.sainner.top 托管远程登记、clone 与集成推送，迁移到 GitHub 后托管仓库回收，App 的 GitHub 设备码绑定（需用户先配置 `GITHUB_CLIENT_ID`）与仓库挑选。

**完成条件：** 在明确的设备与网络条件下完成上述真机流程并记录覆盖范围，出现缺陷时转为具体问题；统一总览按上述跨机器浏览与路由要求验收。文件同步另行确认需求；Git 经共享远程同步，自动测试不能代替线上验收。插件跨端操作的验收见 [[todo-plugin-device-validation]]。
