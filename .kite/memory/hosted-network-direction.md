2026-10-06 用户最终明确「改为我们托管一个，然后用账号密码登录」。Kite 由我们托管账号与组网，用户用账号密码登录，普通用户无需自行准备服务器。该要求覆盖同日曾讨论的「Tailscale 官方服务或用户自行部署 Headscale」二选一方案；不要继续把服务选择作为默认首次配置步骤。

用户还要求新设备可以扫描已登录机器上的二维码完成入网。此扫码方向仍适用，不能擅自改为旧设备扫描新设备的码；实现与验证范围以规格文档为准。同一用户的设备授权合并到入网，不再逐台配对工作机。

账号与设备的系统规格已收敛到 [托管账号与设备](../../docs/托管账号与设备.md)。2026-10-06 用户随后明确「开始」，授权实施；并确定 `hk-server`、`hs.sainner.top`，自行调整 DNS。不要再把此前「先讨论设计」视为禁止本轮实现和部署。

**Why:** 用户希望以账号密码或扫描已登录设备二维码完成使用准备，账号与组网由我们托管。
**How to apply:** 以统一的 Kite 登录体验设计首次配置，复用上游账号和组网能力，不把 Headscale 的用户记录直接当成密码登录系统。规格以 docs 为主来源，后续改动同步维护该文档。
