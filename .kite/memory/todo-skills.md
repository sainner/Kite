设计正文以 [产品架构](../../docs/产品架构.md#两层协议与上下文)、[上下文组装](../../docs/harness-上下文组装.md#公共变量) 与 [主循环](../../docs/harness-主循环.md#skill) 为准，文件包契约见 [工作机说明](../../docs/kited.md#账号级数据)。
**来源：** 用户 2026-10-23 决定做 skill，并把规则、skill 的来源统一成四层（MCP 当天改为只来自机器层）；当天改主意加 `skill` 工具（原先排除），随后要求补齐未做项。

- 加 `skill` 工具的理由（用户 2026-10-23）：宿主确切知道加载了什么，压缩重附、界面标记、`/名字` 三件事共用一条记录；清单因此只列名字和说明，正文由工具给。
  工具只给正文和文件夹路径，其他文件用 `read` 按绝对路径读、脚本在 shell 里跑，照 Claude Code 的 Skill 工具（用户同日要求，原先的 `file` 参数去掉）。

**待验收（真机）：**

- 新建代理（已有代理的实例配置里没有 `skill` 工具，要新建或在配置里打开），说「按 Kite 规范体检这个项目」，看它是否先调 `skill` 工具再做、模板是否用 `read` 按绝对路径读到；Claude 后端也试一次。
- 输入框打 `/k`，候选行是否出现、点选后输入框变成 `/kite-onboard `；发出后气泡里命令名是否等宽显示，模型是否按正文做。Mac 首次直接进入窄窗口也要能加载候选；Mac 宽窄窗口与 iPad 外接键盘试上下键选择、Tab 补全，并确认中文组字不被抢键。
- 资源库 Skill 页：新建、改名、加文件、改 SKILL.md、保存、恢复默认、删除，各在另一台工作机同步后是否生效。导入图片或 PDF，保存、同步后导出核对原文件，再试替换和删除。iPhone 上的页面、文件选择器与候选行也看一眼。
- 压缩后重附：手动压缩一段用过 skill 的对话，看替代内容里是否有 `skills.loaded` 的通知。

外部 MCP 不走四层来源，只来自机器层，见 [[todo-context-capabilities]]。
