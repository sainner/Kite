**状态：** 2026-10-25 与用户讨论定稿，正文在 [台面与停靠栏](../../docs/台面与停靠栏.md)。同日工作机（协议 24）与 App 两侧都已实现并合回 main：停靠栏带子（竖排横排同一套、圆格、堆叠渐隐、家族格、布局文件夹、两个添加入口）、台面只剩缩小/展开还原/关闭或归档/拖动、新建页重做成圆头像、项目布局的保存与打开、iPad 从格子长按起拖。Mac 上由子 agent 逐帧截图核过过渡（连续、无回弹、无双份头像）；Mac 性能同日量完（数据见 [[todo-window-motion-remaining]] 2026-10-25 那条）：停靠栏与台面本身没拖慢窗口动画，唯一明确的退步是五个代理在跑时静息主线程约 15%（卡片上看不见的头像照样逐帧画），已修到约 7%；侧栏拖宽、缩小恢复首帧比 10-14 的参照慢，追到的大头不在停靠栏代码里、也没法和 main 交替比（main 的 App 是协议 23，连不上本机 kited）。用户还没验收。

**来源：** 用户认为原来的机制「太臃肿、补丁太多」（缩小的窗口与没窗口的实例两种样子、固定、上一步、家族格、「更多」），要整体替换；用户自己给了停靠栏方案（始终显示所有实例、堆叠渐隐、家族格、布局文件夹、圆形、去掉空画板与固定），我补了「没有共享窗口对象、消失方式按插件分三种、布局是项目的配方」，用户同意。

**待用户验收（Mac 用 `app/scripts/preview-mac.sh` 的 Debug 预览，iPad、iPhone 真机）：**
- 停靠栏整体样子与各过渡；放不下时的堆叠渐隐力度（`fadePower` 0.8、家族格往后 0.75/0.5/0.25 是实现者定的）；添加布局的图标。
- 宽屏放不下时「添加实例」按规则排在末端的堆叠里、几乎看不见，要不要让它例外。iPhone 不受影响：2026-10-28 用户定紧凑布局不列布局组，添加实例换到原来添加布局的位置（最前端），后面一道分割线是我留的。
- 布局打开时「同角色代理先取台面上的，再取最近活动过的」，以及保存布局默认新建、要覆盖才覆盖，是我给的默认。
- 代理开的后台进程结束即回收、用户开的留到关闭，是我给的默认。
- iPad：格子长按出菜单、再动转成拖出，指针按住一挪就拖；只编译过没上真机。iPhone 没有台面、不拖，只看有没有退步；10-28 去掉布局组的那版已装到 iPhone、用户还没看。
- 浅色外观只看过新建页，停靠栏的截图都是深色。
- 2026-10-26 加的两处：拖到卡片中间顶替它（卡片宽高各中间三分之一是顶替区、被顶替的回停靠栏，区大小是我定的）；打开布局先用本机各格上一次的实例；本机最后打开或保存的布局算正在用，这时某格原地换成同种实例（顶替、清空上下文）就记成新的，换别种、换位、改尺寸要覆盖（用户同意的方案），都只在本机。

**未解决：**
- 展开的家族格里面排不下时还是旧叠法（没有按轮廓挖掉压在下面的格子）。
- iPad 的 `PhoneCardView` 和 Mac 修前同一写法：卡片停着时看不见的头像仍每秒 24 帧画，没量也没改。停靠栏末端渐隐到几乎看不见的在跑头像也照样画，代理多时可以一并停住（Debug 预览挤满时进程 CPU 约 16%，九成多是画头像）。
