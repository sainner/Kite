**状态：** 2026-10-25 与用户讨论定稿，正文在 [台面与停靠栏](../../docs/台面与停靠栏.md)，相关契约（产品架构、Agent 与插件契约、kited 接口、实例操作、Bun 插件等）已同日替换。实现中。

**来源：** 用户认为原来的机制「太臃肿、补丁太多」（缩小的窗口与没窗口的实例两种样子、固定、上一步、家族格、「更多」），要整体替换；用户自己给了停靠栏方案（始终显示所有窗口、堆叠渐隐、家族格、布局文件夹、圆形、去掉空画板与固定），我补了「没有共享窗口对象、消失方式按插件分三种、布局是项目的配方」，用户同意。

**实施安排：**
1. kited：去掉 WorkspaceWindow 与窗口接口，实例带当前视图 `state.view`，`lifetime` 的 `window` 改名 `closable`，`process` 进程结束后留到关闭，`DELETE /instances/:id`、`PUT /instances/:id/view`、`POST /workspaces/:id/instances`，`agent.start` 的 `presentation` 换成 `show` 与 `instance.show` 事件，项目布局（账号级 `layout` 条目）接口，协议号 24。旧库里的 `workspace_windows`、`window_requests` 表和 `presentation` 列由启动时的一次性清理去掉，不做读取兼容。
2. App 模型：Pane 就是实例 ID，台面集合与排布按设备存；去掉固定、多步记忆、空画板；新建实例页做底。
3. App 停靠栏与台面界面：圆形格子、堆叠渐隐、家族格、布局组与文件夹、添加入口；过渡动画。
4. 新建实例页重做样子（用户说现在的丑），截图交用户看。
5. 子 agent 截图做视觉与动画验证、用模拟器做性能验证；用户最后在 Debug 预览和真机验收。
