用户确定的侧栏分层原则：

- 侧栏顶部是一级导航：空间、设备（设备列表、各工作机的账号与文件）、资源库（skill、插件、角色、上下文模板、凭据）。未实现的置灰。设置不在导航里，入口在用户栏，在设置里时它变成返回。（2026-10-07 将设备列表从设置移到设备与文件）
- 2026-10-08 用户确认导航名称为“空间”“设备”；设备侧栏按具体工作机展开，“账号”和“文件”是并列子项，复用空间的树状层级。订阅与 API 账号及额度归各设备，设置中保留 Kite 账号。设备栏分工作机和控制端两个列表，不再单设「所有设备」页面；状态以颜色和图标表达，删除入口复用项目行悬停显示的操作按钮。
- 每个一级栏切换整套侧栏列表与内容区，不把不同栏的东西混在同一个侧栏里；工作区以外的栏默认是单页，不用窗口伪装，也不用模态框。2026-10-08 用户明确要求机器账号页采用固定布局的多窗口，作为此规则的例外；必须直接复用会话的窗口容器、模数排布、单一焦点与跨端交互，不能只拼出相似外观的卡片或另做一套移动端底栏。“固定”约束窗口排布，不改变窗口共有行为。具体排布以代码为准。
- 2026-10-09 用户要求资源库的角色像空间里的工作区一样，以树状子项列在「角色」一行下，复用空间侧栏的列表样式；在“内容区直接是角色编辑页”和“仍用编辑弹窗”之间选了前者，切换角色时未保存的修改留作草稿。
- 侧栏不做成面板，除侧边栏按钮外不用玻璃。
- 内容区没有窗口时放占位卡片（宽屏半透明、iPhone 实色），用点阵画板展示状态信息，不承载操作；iPhone 上它就是一个普通窗口，行为与窗口一致。
- 底部导航做成横排标签栏（含嵌系统 UITabBar）的方向试过多轮，用户最终放弃，不再采用。

**Why:** 用户认为原先的空状态在美感和信息层级上都差，侧栏导航应承载一级功能而不是零散操作。
**How to apply:** 改侧栏、空状态或增加全局功能时按此分层；样式细节以代码为准，不写进文档或记忆。视觉约定见 [[visual-style-direction]]。
