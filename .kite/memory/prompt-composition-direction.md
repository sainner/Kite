用户希望直接展示特定时机（例如新建会话）上下文如何组装：双击即可编辑对应段落；条件型内容用页签切换查看不同分支；内部动态内容用 chip 作为变量。

用户进一步澄清这里的核心是「契约」，并认可按「创建会话」「会话中文件变化」等业务场景约束定义与可用变量。这个诉求不代表让组装器接管事件监听、通知投递或 agent 调度。

**Why:** 用户明确纠正了「场景模板库、为会话选择日常工作或代码审查模式」的理解；所期待的是直接看见并编辑上下文的组成。

**How to apply:** 以后设计编排界面时，以实际组装结构和业务场景契约为中心，不把先前建议的工作模式选择流程当成用户需求。组装器仍不负责事件监听、线程启动或调度；2026-09-27 用户进一步讨论了独立的工作区触发器，它可以在组装器之外按工作区状态串行启动不同线程。条件编辑方式、段落重排和配置作用范围仍待确定；不能从页签交互推断运行时由用户手动选择条件。实现现状通过代码和项目文档核验，不在记忆中维护进度。
