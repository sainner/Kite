用户要并行推进时，由主会话直接派子 agent（Agent 工具，各占一个工作树）编排，不逐项请示编排细节；产品取舍照样先问。2026-10-13 用户说「以后直接编排就行」，随后纠正：「我的意思是直接派子 agent，这个任务没有复杂到要派 workflow」。Workflow 只在任务真的需要确定性的大规模扇出、多轮校验时才用。

- 运行中不要给 agent 发 SendMessage 改方向：在 Workflow 里会把它从编排里接走、卡住后面的阶段（2026-10-13 出过一次）；单独的子 agent 被打断也容易丢上下文。要改方向就停掉重派，提示写清楚。
- 逐像素对照要有收敛门槛：差异小到肉眼看不出就列进汇报交用户看，不要反复微调。2026-10-13 输入区原生化的 agent 在玻璃和输入框对照上磨了约一小时，用户看过对照过程「几乎没有差异」，直接要求收尾。
- 一轮做完先独立审查，再合进主线（用户：「先把改动收入主树（或者review）」）；没做完、没手测的分支先不合。

**Why:** 用户要的是持续推进，不想在编排形式、编排细节和过度验证上耗时间；编排越重、插话越多，越容易出岔子。
**How to apply:** 按「子 agent 实现 → 子 agent 或主会话审查 → 编排者测量 → 用户手测 → 合并」走，主会话在两段之间看结果、定下一步。agent 的提示里写明对照的门槛和收尾条件。协作的其他要求见 [[feedback-ui-workflow]]。
