纯样式修改只编译、安装并打开新 build，不运行 `.kite/check`，随后就停，由用户自己预览和试手感。涉及逻辑或数据行为的修改仍按项目检查规则处理。不要自己用模拟器工具点、截图来验证。尺寸、边距和按钮外观等简单调整直接改代码，不启动子 agent，也不搭建模拟器尺寸探针；效果由用户看，避免把小修改做成一轮排查。

样式由用户预览后给出修改意见，agent 按意见实现。没有具体样式意见时先准备可预览的假数据，不自行设计或重排界面。

更新 Mac 预览 build 时先关闭旧的预览实例，再打开新 build，只保留一个预览实例。

**Why:** 用户明确说过「不用你来预览，写好、改好代码之后打开新的 build，我来预览即可」，并进一步说明「我来预览并给出样式修改意见，不需要你负责设计。首先需要一份假数据」。2026-09-29 用户明确要求「样式修改不要运行 check 了」。手势、动画的手感要本人试，自己截图验证慢，还会用错坐标得出错误结论。用户也指出反复打开新实例会留下多个 Mac 应用，预览更新应替换旧实例。2026-10-04 用户因按钮尺寸修改又启动子 agent 和读数探针，明确要求停止这些步骤，改好代码、打开 build，由他本人查看。

**How to apply:** 用户在已连接的 iPhone 实机上预览；改了 app/ 下的界面，应编译实机版并用 `devicectl` 安装、启动，不要把模拟器更新当成已交付 iPhone 预览。样式预览 build 启用假数据，便于从手机桌面再次打开。Mac 先确认并退出旧预览进程，再打开新 build，不能直接用 `open -n` 叠加实例。逻辑上拿不准的地方写在回复里请用户试，不要自己去点。
