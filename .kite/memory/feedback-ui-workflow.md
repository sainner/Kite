用户要求界面工作按已确认的目标推进：

- 美化先给视觉方案，经确认后实现；方案可以调整布局和层次，不顺带整理公共接口或统一其他窗口。新的视觉体系和全局布局需先确认取舍。
- 接真实数据沿用已认可的界面结构；接入本身不授权重新设计外观，也不能用示例内容伪装真实数据。性能优化和结构改造（换文本容器、换排版方式）同样不改外观，字体、间距、颜色、形状逐项保持（2026-10-11 用户：外观调了很久，不要改）。
- 同名控件先结合位置、相邻元素和触发条件确认；仍有歧义再询问。
- 多期工作（包括非界面任务）的整体方案获确认后连续完成各期，不逐期停下征求继续许可；只有新取舍或用户必须亲自操作的事项才中断。修缺陷和性能问题同样修完为止，不在定位、验证、实现之间停下请示（2026-10-11 用户：修不完别停）；子 agent 判断投入产出低、还要用户多跑几轮测量，也不是停下来问要不要接着做的理由（2026-10-13 拖缝丢帧没修好就问要不要继续，用户反问「resize 的优化结束了吗」）；验证尽量自己做，非要用户操作时一次说清。要用户双击跑的测量先想清能一次回答的大问题（例如正常、不重排、定尺寸、拿掉内容分层），候选改法做成开关放进同一次启动，换新版时删掉旧产物防点错（2026-10-13 拖缝前后让用户跑了十几轮，多轮被探针错误作废，用户：「测够了没有」）。在已连接的手机上跑会自己操作界面的探针（自动横滑、弹键盘）前，先告诉用户要占用多久；用户说停就停，未经核对的布局改法不要装到用户手机上（2026-10-11 用户在用手机时看到界面自己动、键盘下的窗口错位而发火）。
- 查交互失灵时，证据一旦指出哪一层可靠（例如 UIKit 每次都收到触摸、失灵在 SwiftUI 识别器），就直接把机制挪到可靠的那层修好，不继续追框架内部原因、不再出对照版本让用户一轮轮试；候选原因解释不了全部现象（在哪操作、多久后出现、怎样恢复）时不做成改法；用户怎么操作的先问清，不自己假设（2026-10-14 控制区横滑失灵，连出玻璃、菜单、禁用按钮几版对照，用户在空白处操作，说「完全是在碰运气修改」「还在测测测」，Codex 按同一份证据把横滑、上拉改成挂在 HostIsland 上的 UIKit 手势，一轮修好）。
- 界面效果由用户在新 build 中验收，不自行截图、裁图代替用户判断；没有具体反馈时不顺带重排。用户报的交互手感问题（滚动抢位置、点不开、动画曲线）改完直接编好交给用户手测，不先搭合成点击、合成滚轮的探针（2026-10-13 两次在探针上被拦下，用户：「我装上自己点点看」「现在好了，我手测过了」）；性能测量的场景仍自己搭。纯样式修改不增设测试或探针，需要测量逻辑或数值时先说明目的。
- 调样式、来回改参数时用 `preview-mac.sh` 编 Debug 预览交给用户看，不打 Release 包重装；Release 只在交付确认或用户要装时才装（2026-10-14 用户：「是不是编 debug 版就可以了，不要编完整的包啊」）。
- 重装 Mac Release 时安装脚本要求先退出 Kite：用户的 `~/Applications/Kite.app` 开着就自己正常退出（`osascript -e 'quit app "Kite"'`）再装，不停下来等用户退（2026-10-14 用户：「以后你自己退就行」）。只退这一个安装版，不碰各检出的预览（DerivedData 里的 Debug 版）。退出可能要二三十秒，等进程没了再跑打好的 `build/Kite-macOS-arm64/安装.command`。安装脚本装完会自己打开 App，之后不要再按名字或 bundle id 打开、激活 Kite（`open -a Kite`、`tell application "Kite"`）：机器上还有 Codex 工作树和 DerivedData 里的 Kite.app，LaunchServices 可能挑中用已吊销开发证书签名的旧构建，系统按恶意软件拦截并挪进废纸篓，弹窗看着像刚装的 App 出了事（2026-10-16）。确需打开时用 `~/Applications/Kite.app` 的完整路径。
- 主线检出的 Kite 供其他会话使用，工作树的预览不能把它退掉（2026-10-12 用户）。`preview-mac.sh` 已按检出各开各的预览；绕开脚本自己起 App 时同样只动本检出的进程。

**Why:** 用户重视已经打磨的界面与真实手感，希望视觉方案和实现范围明确，避免接数据、美化和代码整理相互混淆。
**How to apply:** 构建、预览和安装使用 [App 入口](../../app/README.md#预览和验证)，每个检出只保留自己的一个预览实例。iPhone 窄屏或触控改动需要在已连接真机安装、打开并交用户验收；Mac 构建不能替代。多份 Xcode 并存时先核对有效工具链，并按路径打开用户选定版本。Release 按 [安装说明](../../docs/macOS安装与打包.md) 整体替换，避免合并覆盖破坏资源与签名。事件诊断见 [[ui-hit-testing-debugging]]。
