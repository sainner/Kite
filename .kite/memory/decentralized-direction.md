2026-10-15 用户决定：Kite 不再运营自己的服务器，账号服务、Headscale、托管目录、资源库与凭据服务、托管 Git 都要下线；可以依赖 Tailscale、苹果这类第三方公共服务。以后要发给别人用，后台推送暂定走 CloudKit 订阅，不在用户设备上放推送密钥。数据只在用户自己的设备之间同步，每个工作区同一时刻只有一台设备执行和写入。设计见 [分布式架构](../../docs/分布式架构.md)，待用户评审。实施顺序（2026-10-15 与用户定）：① 账号级数据与工作机目录在工作机之间同步、发现改用组网节点；② 工作区副本跟进、没有远程的项目设备间互为远程（含 Line），流转只交执行权；③ 换 Tailscale 官方身份并加登录引导，下线账号服务与 Headscale；④ 有预告的自动换机现在就做，CloudKit 与推送上架时做。①至④中不依赖付费账号的部分已实施（2026-10-15，未提交；数据不重要，没做迁移；旧服务器当天下线），剩下的见 [[todo-decentralized-rollout]]。

起因是 Line 要在机器睡眠或失联时换到别的机器继续。讨论依次经过：睡前 30 秒内交接、数据全放 Kite 云端，最后用户定为纯分布式、服务器下线。

商业模式（同日讨论，未进设计）：没有服务器也能收费，iPhone、iPad 走 App Store 内购，StoreKit 2 凭证带苹果签名，可以经 tailnet 递给 Mac 由 kited 离线验证；Mac 版要跑任意开发工具，过不了 Mac App Store 沙箱，只能在商店外发行。以后可选的付费服务是云端常驻设备，作为用户网里的普通一员（Line 的家、大陆中继），不改架构。内购用户说先不急，第一版设计不含。

**Why:** 不想运维服务器；数据留在用户自己的设备上；设备之间持续同步之后，交接只剩递执行权，Line 换机就不用再赶时间。
付费 Apple Developer Program 等准备上架时再加入（用户 2026-10-15）：在那之前没有后台推送，kite-net 仍是临时签名；见证方做成可替换的：有远程的项目用项目远程的 Git ref，没有远程的（如 Line）用 CloudKit；上架前无远程项目没有见证方，只做有预告的换机、意外失联不自动接手（用户 2026-10-15 定，不建 GitHub 专设仓库过渡）；上架后有远程的项目是否也统一到 CloudKit 待定。后备已采纳、上架后与 CloudKit 一起上线（用户 2026-10-15）：有远程推私有远程的 ref，无远程存 CloudKit，项目自己打开。自建服务器能当见证方但不采用，推送必须付费账号、自建也绕不过。

**How to apply:** 不再引入 Kite 自营的服务器。涉及身份、组网、目录、资源库、凭据、没有远程的项目、工作区副本与流转的改动，先对照设计文档。执行权是记在见证方（Git ref 或 CloudKit）的租约：续不上就自己停下，过期后别的设备抢占，因此意外失联也能自动接手（用户 2026-10-15 认可）。自动换机：Line 总是；普通工作区默认不换，项目在设置里打开并声明需要的环境后，只搬正在工作的工作区；见证方不可用时才退回用户手动强制接管。现行文档与代码已按这个方向改写，没实施的部分以 [[todo-decentralized-rollout]] 为准。
