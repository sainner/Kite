2026-10-09 用户在新代理草稿换成真实代理仍不连贯时指出：应该是同一个组件的不同状态，不要分成两个组件再替换。当时草稿和真实会话是两个 `WorkThread`，窗口里换对象，补过渡也总有一下替换；改成草稿对象在工作机建好实例后原地变成那个代理，第一条消息就是它待发送区里的普通消息。

**Why:** 换组件会重建视图状态（滚动、动画、点阵签名），无论怎么补过渡都看得出替换。
**How to apply:** 用户看来是同一个东西的前后阶段（草稿→实体、占位→内容），先让模型对象和视图身份贯穿全程，状态变化由同一对象承担；需要服务端配合时让客户端预先生成 ID（窗口、消息）。不要先做两套再靠转场掩盖。
