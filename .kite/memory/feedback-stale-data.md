本机 kited 的旧数据跟不上新格式而出错时，处理办法是删掉那份旧数据，不改读取代码去兼容它。2026-10-17 删除 zhinan-nas 时，一个线程的会话记录写于执行授权加 `unsandboxed` 之前，读回时补了默认值，请求配置摘要对不上，删除卡在停线程这一步。用户说「删掉旧数据就好了」，并允许删除。

设计取舍时同理：2026-10-23 接外部 MCP，我把「改 tool_search 的参数会让已有 harness 会话报定义已变化」「服务清单只写在模板里，改过的角色和已有代理看不到」列为待定代价，用户问「我们产品现在是什么阶段」——没有改过提示词的角色，已有代理是旧数据，这些都不算代价。

**Why:** 项目在研、不考虑兼容（见 AGENTS.md），旧数据不重要。
**How to apply:** 出故障时先查清是哪份数据、确认没有在跑的进程，再告诉用户要删什么，经允许后删，不要顺手放宽校验或加迁移。比较方案时，「已有会话、角色、代理、本机数据会对不上」不进代价，也不为它保留别扭的写法；AGENTS.md 写明要跨版本兼容的（`/machine`、`/update`、账号级数据同步）除外。
