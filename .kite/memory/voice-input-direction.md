Kite 的语音输入自己做，不和 Keyo 输入法定协议，也不引入 KeyoKit；识别是资源库「辅助生成」的一类，在工作机上调用，凭据是账号里单开的「语音识别」一类，不由托管服务转发。现行机制见 [语音识别](../../docs/kited.md#语音识别)。以后 Keyo 改用 Kite 账号登录；Mac 上在 Kite 里按 Keyo 的右 Option 先与 Kite 自己的语音并存，两者怎么统一以后在 Keyo 侧处理。

识别路线 2026-10-12 用户确认，依据见 [实验记录](../../docs/research/2026-10-12-语音识别选型.md)。默认不做 LLM 美化；需要书面化时以后另做手动「整理」。未选的候选：Apple SpeechAnalyzer 实测字错率近三成；豆包流式识别 2.0 只对企业实名认证用户开放，且要豆包语音控制台的 key（火山方舟的 key 不通），个人账号暂不考虑。

术语词典是后续功能，暂不做。灵感来自 Pigeon：在消息里划词翻译时可以把词收进术语词典，Kite 语音输入用它提高识别和整理的准确性。

点阵表现（2026-10-11 用户定）：语音输入时，只在说话的 agent 窗口底部一带铺这个 agent 的签名图案，随响度 v 起伏；放音乐时每个 agent 窗口同样出各自的签名，App 背景露出来的地方在底部出频谱柱；其他窗口不出，免得分散注意力。放音乐那部分还没做。

**Why:** Keyo 只有 Mac 版，iOS 键盘扩展不能用麦克风；点阵动画要在 Kite 进程里拿到电平；对话上下文本来就在 Kite。用户觉得 Keyo 现在「转写加 LLM 美化」不好用。
**How to apply:** 做 Kite 语音相关功能时按此分工；改识别机制先看 docs/kited.md 的语音识别一节。术语词典、手动整理或放音乐的点阵开工时更新本条。
