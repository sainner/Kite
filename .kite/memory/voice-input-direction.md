Kite 的语音输入自己做，不和 Keyo 输入法定协议，也不引入 KeyoKit；识别是资源库「辅助生成」的一类，在工作机上调用，凭据是账号里单开的「语音识别」一类，不由托管服务转发。现行机制见 [语音识别](../../docs/kited.md#语音识别)。以后 Keyo 改用 Kite 账号登录。Kite 自己的语音输入快捷键也是单按右 Option（2026-10-29 用户定，明知和 Keyo 同键），Keyo 开着时两边都会响应，怎么统一以后在 Keyo 侧处理。

识别路线 2026-10-12 用户确认，依据见 [实验记录](../../docs/research/2026-10-12-语音识别选型.md)。未选的候选：Apple SpeechAnalyzer 实测字错率近三成；豆包流式识别 2.0 只对企业实名认证用户开放，且要豆包语音控制台的 key（火山方舟的 key 不通），个人账号暂不考虑。

整理（2026-10-29 用户定）：原先默认不用 LLM、书面化留给以后的手动整理；用户嫌口述太口语，改成定稿后自动整理，只做减法（删语气词、口头禅、重复和改口，补标点分段，不换用词、不加内容），定稿先出、整理版换上，Mac 输入框在编辑中时能 ⌘Z 回定稿。整理用 DeepSeek（`deepseek-flash`、`low`），用户定的；同日比过识别时就润色的 `qwen-audio-3.1-asr-flash-message`，带对话就不润色、不带又认不准标识符，没采用，见 [语音润色](../../docs/research/2026-10-29-语音润色.md)。合成录音上整理要多等约 2.5 秒。已实现、未装到工作机：真人录音、App 里的实际速度、Mac 撤销、iPhone 都没试；iPhone 开录时收起键盘，没有撤销回定稿的办法。

术语词典是后续功能，暂不做。灵感来自 Pigeon：在消息里划词翻译时可以把词收进术语词典，Kite 语音输入用它提高识别和整理的准确性。

输入框里的样式（2026-10-29 用户定）：语音写进去的那段字在这次语音输入结束前另换样式。还在录时整段灰；说完后整理流式推来，整理出的字从前往后逐字替换定稿，交界处是工具行同款的像素扫掠（PixelSweep），扫过的地方变成整理后的正文，没扫到的还是灰的定稿；整理没成退回定稿。同日工具行的扫掠也改成换字的过渡：新字等下一遍扫掠才换上，扫过去才变，步数和箭头也随扫掠换。点阵底部那一带改成开录时从底边升起、停下时沉回去。Mac 已实现、工具行用户看过；输入框的逐字替换要重装工作机服务才看得到，还没看。待做：iOS 的输入框扫掠和工具行着色器（KitePixels.metal）的换字过渡；Mac 窄窗口的输入框是 SwiftUI TextField，没有这些样式；iPad 外接键盘没接右 Option。

扫掠按固定速度走，不跟着流式到达的节奏（2026-10-29 自测）：DeepSeek 整理等约 3 秒才出第一个字，然后 70～90 字在 0.3 秒内全到，跟着到达走会一下跨几十个字、看着乱（用户：「乱七八糟」）。现在一段约 1.5 秒匀速扫完，不超过收到的字；等整理的那几秒灰字按等待呼吸起伏（我提议的，用户看过预览后让提交）。自测办法：Debug 带参数让 App 用 AVSpeechSynthesizer 念 spikes/voice-polish 的口语稿当麦克风（沙盒读不了主目录的录音文件），外面 `screencapture -l 窗口号` 连拍、按时间戳对日志，裁出输入框拼图看。

点阵表现（2026-10-11 用户定）：语音输入时，只在说话的 agent 窗口底部一带铺这个 agent 的签名图案，随响度 v 起伏；放音乐时每个 agent 窗口同样出各自的签名，App 背景露出来的地方在底部出频谱柱；其他窗口不出，免得分散注意力。放音乐那部分还没做。

**Why:** Keyo 只有 Mac 版，iOS 键盘扩展不能用麦克风；点阵动画要在 Kite 进程里拿到电平；对话上下文本来就在 Kite。用户觉得 Keyo 现在「转写加 LLM 美化」不好用，所以整理不改写，规则在资源库「语音整理」模板里可调。
**How to apply:** 做 Kite 语音相关功能时按此分工；改识别机制先看 docs/kited.md 的语音识别一节。整理太狠或太轻先改模板；整理验收后删掉本条的待验收说明。术语词典或放音乐的点阵开工时更新本条。
