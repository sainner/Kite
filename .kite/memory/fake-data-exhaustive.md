做 Kite App 的界面时，假数据要尽量覆盖当前后端实际可能产生的工具、成功、出错、打断、没跑完及边角情况。用户于 2026-09-28 明确要求复核全面性，并确认预期是自研 harness 的假数据；不能继续将旧 Claude Code 样本作为当前能力的默认展示。

尚未支持的能力如有样式预览需要，应明确分开标注，不混入当前后端的正常样本。静态样本的覆盖不能当作流式更新、发送、重连等交互已验证。

**Why:** 界面要让用户看到各种真实可能出现的情况，避免接数据后才暴露缺漏，也避免旧样本让人误以为新后端已支持那些能力。

**How to apply:** 先读当前后端的工具定义和显示协议，再列覆盖范围，参数、结果和状态照实际实现写。后端方向变化时重新核对，不只换工具名称；明确哪些仅是静态展示、哪些尚未支持。
