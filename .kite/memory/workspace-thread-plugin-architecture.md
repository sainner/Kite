2026-09-27 当前产品架构方向：侧边栏条目代表工作区，而不是单个会话。工作区对应一个 cwd、工作树和分支，下面可以有多个同级工作线程和插件窗口；线程与工作区解耦，删除线程不自动删除工作区。

工作区允许多个线程存在，但同一时间只有一个线程运行。工作区持有执行槽和串行触发队列。线程类型是可复用的 agent profile，包含上下文组装策略、工具能力和运行约定；subagent 可以复用同一模型，作为内部调用关系或被提升为工作区中的同级线程，不建立主线程/协作线程的产品层级。

工作区状态以只读、可快照的公共上下文变量提供给上下文契约和触发器，例如 `workspace.cwd`、`workspace.diff.*`、`workspace.check.status`。上下文组装器只展开契约，宿主负责收集状态，触发器负责按结构化条件排队线程。

终端和文件系统在界面上作为预制插件，但属于拥有核心权限的系统插件：它们与工作区文件、Git 快照、PTY 和进程生命周期共用底层服务。普通插件通过受限能力接口接入，不能默认获得任意路径、shell、环境变量或认证信息。

**Why:** 用户希望一个工作区承载多个同级工作窗口，并让审查、测试等线程按工作区状态串行触发；终端和文件系统需要超出公开插件契约的工作树、Git、进程和安全语义。

**How to apply:** 设计 App 数据模型时优先使用 `Project → Checkout → Workspace → Thread / Plugin Window`；同一工作区的模型和工具修改保持串行；扩展上下文时沿用 `contextScenes` 和 `ContextBinding`，不要另造环境变量系统；先做系统插件，再定义普通插件公开边界。
