引入新的视觉体系、全局布局规则这类牵涉面广、尚有取舍待定的改动时，先给出方案和待决问题，等用户确认后再动代码。小的样式修改仍按 [[user-previews-ui]] 直接改。

**Why:** 2026-10-06 着手点阵视觉语言时，用户中途要求“先给我方案审阅，不要直接实现”，确认取舍后才让继续。
整体方案获确认后，分期只是实施顺序，不是审阅节点：2026-10-07 项目以远程为身份的四期计划，用户在第 2 期中途说“四期直接执行完，为什么要分期”。

**How to apply:** 方案写明改哪些文件、关键几何与交互规则、本轮不做的部分和需要用户拍板的问题，并给出推荐项；用户回复确认后再实现。确认后的多期计划一路做完再统一汇报，只在需要用户亲手操作（生产部署、密钥）或出现新的取舍时停下。
