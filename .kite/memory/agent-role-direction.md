2026-10-09 用户在讨论创建会话模板与工具归属时确定：

- 一个代理 = 角色 + 临时的实例配置（初始窗口里可调的参数）。角色收纳提示词、工具、默认模型与思考强度、每回合预算，以及点阵签名；原「代理」「只读审查」「Claude」三个 agent 定义合并为一个「代理」插件，前两者变成角色，Claude 变成模型菜单里的一个厂商（后端规则见 [[model-vendor-backend]]）。
- 代理插件的窗口叫「代理窗口」，不再把窗口称作「会话」。
- 工具等集合类配置用白名单或黑名单表达，有效集 = 全集 ∩ 各层白名单 − 各层黑名单之并，禁止优先、与层序无关。层次是角色、项目约束（[[project-constraints-direction]]）和实例选择。角色默认以全集为起点，安全用途的角色用白名单。
- 角色可把工具标为「必需」；必需项被约束去掉时，该角色在这个代理窗口里不可选，并说明是哪层禁了什么。没标必需的角色总能选。
- 数值上限取最小；默认模型、思考强度是偏好，只要求落在允许范围内；提示词叠加不求交。角色在创建代理时拷贝，之后修改不影响已有代理。

同日用户确认界面里指代理实例的「会话」一并改掉：新会话→新代理、会话配置→代理配置、归档会话→归档代理、更多会话操作→更多操作、重新生成会话标题→重新生成标题，提示文案里的「会话」改「代理」；首页「开始会话」实为建工作区，改「新建工作区」。「组网会话」和 docs 里指对话记录的「会话」不改。

**Why:** 原先提示词在模板、工具上限在定义、实际值在实例配置，用户选了「只读审查」模板仍可能带着 shell，概念绕。
**How to apply:** 实现角色、草稿与代理配置时按以上分层和算法；用户可见名称用「代理」「代理窗口」「角色」。分期见 [[todo-agent-roles]]。新会话开场白尚未决定，讨论起点见 [[template-emblem-direction]]。
