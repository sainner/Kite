2026-10-06 用户要求 Mac 区分「在这台 Mac 上运行任务」（安装 kited）和「仅远程控制」，两者都入网。仅远程控制不意味着在初始配置中绑定某一台工作机，同账号设备授权合并到入网。

同日用户进一步纠正：原定侧栏是「项目 → 检出 → 工作区」，检出包括异机检出；不能把当前单机连接限制当作进入 App 后必须先选工作机的产品决定。用户随后确认托管目录索引、本地缓存与工作机直连方案；规格见 [产品架构](../../docs/产品架构.md#对象与归属)。

用户指出独立 macOS kited 包主要面向节省空间或未来无界面服务器，不能把服务职责独立推导为 Mac 必须拆成两套安装流程。系统规格与当前实现范围见 [托管账号与设备](../../docs/托管账号与设备.md) 和 [macOS 安装与打包](../../docs/macOS安装与打包.md)。

**Why:** 用户希望 App 是管理多台工作机的入口；把本机用途选择和连接某一台机器混在一起，会错误限制整个使用流程。
**How to apply:** 改首次配置、安装包和工作机列表时按此方向设计，并区分目标与当前能力。规格由对应 docs 维护；视觉约定继续见 [[visual-style-direction]]。
