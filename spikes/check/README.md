## 影响耗时的几件事（2026-09-23，本机，Bun 1.3.14）

- **小测试并行时互相抢 CPU**：同一个测试单独跑 0.46 秒，全量里被拖到 1.03 秒。单个上限按全量里的耗时判，所以要留足余量。
- **两次检查同时跑会一起超出预算**：两次全量同时跑，快照的小测试分别用了 1.09 和 1.14 秒，超了 1 秒上限。所以 check 工具一台机器一次只跑一个检查。
- **macOS 上新可执行文件第一次执行有额外开销**：内容从没执行过的新文件约多 260 毫秒；内容执行过、但是新文件约 50 毫秒；同一个文件再执行约 10 毫秒；用 `/bin/sh 文件` 执行没有这笔开销。测试里写出来的检查脚本要用固定内容，变化的部分放进文件读出来。
- **App 编译**：Mac 和 iOS 两端一条 xcodebuild 一起编。系统框架的预编译模块（约 236 MB）放在 Xcode 默认的 DerivedData 根目录，各工程、各工作树共用；只有第一次要生成，两端一起约 16 秒。之后新工作树第一次编译约 5 秒，没改动约 1.7 秒，改一个文件约 1.9 秒。每个工作树在 DerivedData 里另有一个缓存目录，关掉索引约 9 MB，不关约 70 MB；会话归档后它不会被删。用 `-derivedDataPath` 把缓存放进工作树的话，预编译模块每个工作树各一份，344 MB、16 秒，所以不这么做。
- **最慢的几个**（加排队之后那次）：小测试里快照「capture」0.67 秒、合回「主线有新提交」0.55 秒；中测试里「一条完整的会话」约 1.7 秒、「采纳冲突」1.62 秒、「kited 被 SIGKILL 后续接」1.04 秒。

## 机器忙时的中测试（2026-09-24，本机，开着 iPhone 模拟器和 Mac 版 Kite）

- **最重的两个中测试超了 2 秒上限**：「一条完整的会话」1.9 到 2.2 秒，「采纳冲突」2.1 到 2.2 秒；关掉模拟器就回到 1.6 到 1.7 秒。两个测试里没有睡眠，等待都是等事件，唯一的轮询（等会话记录写好，10 毫秒一次）第一次就拿到。按事件时间线拆开（模拟器开着，单位秒）：

  | | 一条完整的会话 | 采纳冲突 |
  |---|---|---|
  | 起两次 Claude Code（第二次是续接） | 0.59 | 0.54 |
  | Claude Code 的 Bash 工具（见下一条） | 0.35（两个并行调用） | 0.54（两次调用） |
  | kited 的 git：登记、工作树、快照、采纳、归档 | 0.49 | 0.66 |
  | 测试自己建仓库、断言用的 git | 0.27 | 0.18 |
  | 跑 .kite/check 本身 | 0.06 | 无 |
  | 其余（请求往返、Claude Code 内部） | 0.22 | 0.20 |
  | 合计 | 1.97 | 2.12 |

  最重的两个中测试都起两次 Claude Code，各起六七十个子进程。模拟器开着时内存紧张（交换区用了约 1.9 GB），起一个 git 从约 10 毫秒变成约 14 毫秒，整体慢两三成。隔一阵再跑，第一次起 Claude Code 还要把 217 MB 的可执行文件重新读进内存，多 0.5 到 1.5 秒，全量里落在排第一个的中测试上。模拟器刚启动的一两分钟负载在 200 以上，什么上限都会超，等它稳定再跑。
- **Claude Code 的 Bash 工具在 git 仓库里每次多约 0.2 秒**：2.1.280 的 Bash 工具会把命令改了哪些文件算成 diff，放在 SDK 消息的 `tool_use_result.bashEditDiff` 里给界面显示，模型收到的工具结果里没有（设置 `bashEditDiffEnabled`，auto 和 bypassPermissions 模式下默认开，Kite 会话用的是 bypassPermissions）。每次调用在命令前后各用私有索引打一次快照，再 diff-tree，串行约 13 条 git；同一仓库里并行的调用也被它排成先后。同样一条 echo，不在 git 仓库里 45 毫秒，在 git 仓库里 255 毫秒，关掉后 39 毫秒；两个测试各快 0.35 到 0.45 秒。
- **处理**：Kite 会话关掉 Bash 的 edit diff（`src/runner.ts` 的设置里 `bashEditDiffEnabled: false`），改动由 Kite 自己的快照记录，真实会话和测试一起变快。「采纳冲突」第一回合原来让 agent 用 Bash 改文件，只是为了在会话一侧留下改动，改成测试直接写进会话工作树，省一次 Bash 调用和一枚快照，改前改后交替各跑 5 次，每次都快 0.3 秒以上。中测试单个上限从 2 秒放宽到 3 秒，理由写在 `.claude/agents/test-writer.md`。处理之后开着模拟器，「一条完整的会话」1.6 到 1.8 秒，「采纳冲突」1.55 到 1.6 秒。
- **内存紧张时还有随机卡顿，和测试无关**：本机 16 GB，同时开着模拟器、Chrome、Figma 和几个 Claude Code，交换区用了约 2 GB。这时哪个测试都可能偶尔慢一两秒：快照的小测试平时 0.5 秒，偶尔 1.6 到 2.0 秒；SSE 事件推送的小测试平时 0.5 秒，有一次 3.3 秒。重跑一次就过。上限不为这种情况放宽，要稳定通过就关掉用不着的 App。
