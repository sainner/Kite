# 单画布点阵：布局动画中卡片位置从哪来

2026-10-06，本机 macOS 26，Swift 6 / SwiftUI。

## 问题

点阵改成窗口里唯一一张底层画布、卡片底面也由它来画时，分栏、开关窗口、侧栏宽度这类布局动画进行中，画布上的卡片能不能和 SwiftUI 实际摆出的卡片对齐。

## 方法

`main.swift` 是一个独立的 Mac 小程序，摆法与 Kite 相同（侧栏在左，内容区里卡片用 frame + position 按排布摆放）。同一张底层画布用两种来源画卡片：

- **A**：卡片用 `onGeometryChange` 报的窗口坐标，即现在 `DotStage.register` 的做法。
- **B**：由模型直接算出窗口坐标，作为画布视图的 `animatableData` 传入，跟同一个动画事务插值。

参照是放在卡片里的 NSView 探针：在同一帧提交之后读它在窗口里的位置。自动跑五段动画：分栏和开关第三张卡片、侧栏变宽（各 2 秒线性），分栏和关闭卡片（`.snappy`）。

```sh
swiftc -parse-as-library -O main.swift -o dot-canvas
./dot-canvas --auto <日志路径>   # 自动跑完退出，逐帧写 CSV
./dot-canvas                     # 手动按钮，肉眼看绿底（B）、红框（A）是否贴着蓝框（实际卡片）
```

## 结果

| 动画 | A 与实际的最大偏差 | B 与实际的最大偏差 |
|---|---|---|
| 分栏，线性 | 316 pt | 0.00 pt |
| 侧栏变宽，线性 | 126 pt | 0.00 pt |
| 开关卡片时其他卡片让位，线性 | 294 pt | 0.00 pt |
| 分栏，`.snappy` | 244 pt | 0.68 pt |
| 关闭卡片时其他卡片让位，`.snappy` | 294 pt | 0.53 pt |

- **A 不能用。** `onGeometryChange` 在动画一开始就报终点位置，画布上的卡片先跳到终点，实际卡片随后才到。
- **B 逐帧对齐。** 只要画布与卡片读的是同一份模型、在同一个动画事务里变化，画布插值出的位置就与实际卡片一致。侧栏变宽时整个内容区平移也一样。
- **在同一帧提交之前读探针会差一帧。** 探针的 NSView 位置要到这一帧提交时才更新；在画布绘制时读，它停在上一帧的位置。这是读取时机造成的，不是画布领先。
- **插入、移除过渡的缩放没有核对。** `.transition(.scale)` 只是绘制时的变换，不改探针的位置，因此这一项量不到。画布按同一过渡（0.92 倍、透明度）自己模拟，是否贴合要靠肉眼看。

## 结论

单画布可行，前提是画布上的卡片位置直接从排布模型算，不从 `onGeometryChange` 回读。在 Kite 里，这意味着要把卡片排布的计算提到窗口根部，让画布和卡片共用同一份结果。插入、移除过渡要由画布按同一过渡参数自己画。

同日后续：用户决定窗口内部不显示点阵，只在背景上。卡片恢复为不透明的面，盖住背景画布，画布不再需要画卡片底面，这套做法没有采用。如果以后要让点阵或波出现在卡片上，可以从这里接着做。
